# Bitcoin puzzle registry for gpu/btcpuzzle.
#
# FORMAT   <n>  <pubkey-hex | ->  [<known-private-key-hex>]
#          '#' starts a comment.
#
# Puzzle #n has its private key somewhere in [2^(n-1), 2^n).  That interval
# is the whole reason these are tractable: Pollard kangaroo solves an
# interval discrete log in about 2*sqrt(W) group operations, so puzzle #n
# costs roughly 2^(n/2) rather than the 2^128 a full-group search would.
#
# A puzzle is only attackable this way if its PUBLIC KEY is known.  That is
# true exactly for the puzzles whose outputs have been spent from, since a
# spend reveals the key.  Where only the address is known, the public key is
# behind HASH160 and the search reverts to brute force over the whole
# interval -- 2^n rather than 2^(n/2) -- which is out of reach for every
# unsolved puzzle.  This tool therefore does interval ECDLP only; it has no
# address scanner, and adding one would not help.
#
# The public keys are public record but are NOT shipped here: this file was
# written without a trustworthy offline source for them, and a wrong key
# would fail silently by searching for something that does not exist.  Add
# them yourself, one per line.  Every entry is validated on load -- the key
# must decompress to a curve point, and any private key you supply must lie
# in [2^(n-1), 2^n) AND generate the stated public key -- so a bad paste is
# reported rather than trusted.
#
# Solve a target directly without touching this file:
#     ./bench solve --bits <n> --pubkey <hex>
#
# Example of what a filled-in line looks like (this one is SYNTHETIC: the
# key was generated here, it is not the Bitcoin puzzle's key):
#     40 03a2efa402fd5268400c77c20e574ba86409ededee7c4020e4b9f0edbee53de0d4 8000000000
#
