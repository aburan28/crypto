  Failure mode is NOT rounding drift -- it is the final
  math.sqrt(nrm2(u)) on an int above 2^1024 (OverflowError).  Below
  that the float path is bit-exact against exact integer arithmetic
  (max rel err 0.000e+00 everywhere it returns).  With lambda_1^2 ~
  det ~ n^2/eff, the wall sits at bits(n) ~ 1024/2 - log2(1/eff)/2,
  i.e. ~510 bits at eff=0.05 -- exactly where the table breaks.

  Consequences: every nu_hat number already in the log (20, 24 and
  256 bits) is unaffected, and P-384 is safely inside the range.
  P-521 is NOT: the shipped routine cannot compute nu_hat there.
  The exact-integer version in this file has no such limit.

T23-C  which convergent wins, and the reduced closed form
==============================================================================
  Write rho = S_K1/S_K2 (~ K2/K1 ~ 1/eff).  Dividing the objective
  by det = n*S_K1*S_K2 kills both scales but their ratio:

      nu_hat(j)^2  =  rho * r_j^2 / n  +  q_j^2 / (rho * n)

  so nu_hat = min_j sqrt(rho*r_j^2/n + q_j^2/(rho*n)), a function of
  the CF data (q_j, r_j) of lam/n and the single scale rho.
  For a fixed j this is minimised at rho = q_j/r_j, value 2*q_j*r_j/n,
  so the index to bet on is the one whose own optimal scale q_j/r_j
  is nearest the operating rho.  (The 2026-07-29 guess q_j ~
  sqrt(rho*n) is the same statement with r_j ~ n/q_{j+1} substituted;
  that balances sqrt(q_j*q_{j+1}), so it sits one index high.)

  reduced form vs exact Gauss, max |diff| over 100 curves x 4 eff : 2.220e-16

    0.50       0.685119       0.685119   70  141        128        126

  The winning convergent is the SAME (j*=70) at every eff above;
  only the weighting rho changes.  For that convergent
    q = 2^127.., r = 2^125..,  rho* = q/r = 4.7039  (i.e. eff* = 1/rho* = 0.2126)
    nu_hat_min over all rho = 2*q*r/n = 0.338039
  So secp256k1's nu_hat cannot be pushed below that by any choice of
  nonce-bound split -- the CF of lambda/n caps how skew L2 can get.

  Caveats unchanged from 2026-07-29: this is a 20/24-bit -> 256-bit
  extrapolation of an empirical regularity, and the whole thread is
  conditional on a NON-STANDARD nonce generator k = k1 + lam*k2 with
  k1 bounded.  It is NOT an attack on secp256k1.
