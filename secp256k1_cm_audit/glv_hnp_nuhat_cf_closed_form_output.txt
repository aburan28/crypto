T8  the eff=1 exact zero in T7 is a genuine isometry, not a bug
==========================================================================
  For a primitive cube root of unity, lam^2+lam+1=0 mod n gives lam^3=1,
  hence lam' = n-1-lam = lam^2 = lam^{-1} mod n.  Writing
      L_lam = { (a*n - b*lam)*S_K1, b*S_K2 ) },
  the coordinate swap (x,y) -> (y,x) carries L_lam to L_{lam^{-1}} = L_{lam'}.
  That swap is an isometry exactly when S_K1 = S_K2, giving
      nu_hat(lam) = nu_hat(lam')   and   b*(lam) = eps*(lam'),  eps*(lam) = b*(lam').

  NOTE: the codebase's eff=1 setting is K1 = isqrt(n), K2 = isqrt(n)+1, which
  gives S_K1 != S_K2 -- only S_K1/S_K2 = 1 + O(n^-1/2).  So the T7 eff=1.00 row
  is a NEAR-isometry (agreement to O(n^-1/2), i.e. below print precision), not
  an exact one.  Arm A forces S_K1 = S_K2 to test the exact statement; Arm B
  measures the codebase parameterisation.
