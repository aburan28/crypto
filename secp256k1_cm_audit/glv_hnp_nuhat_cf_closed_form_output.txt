T2  Precision audit of the 2026-07-29 gauss_reduce_2d  [PRE-REGISTERED
    HYPOTHESIS FALSIFIED -- the routine was correct]
========================================================================
  Hypothesis going in: `q = round((u.v) / |v|^2)` looked like an f64
  rounding hazard, since at 256 bits |v|^2 ~ 2^500 -- far past the
  53-bit mantissa -- so the 2026-07-29 secp256k1 numbers might be wrong.

  This is FALSE.  CPython's int.__truediv__ is correctly rounded for
  arbitrary-precision operands: it does NOT convert each operand to
  double first.  The quotient here is small, so `q` is exact.
  Column 3 = the original routine; column 4 = the same line ported
  naively to fixed-width doubles (float(a)/float(b)), which is what a

  T23 theorem: CONFIRMED
  nu_hat is computable by one Euclidean-algorithm pass over lam/n;
  no lattice reduction is required.  It is small exactly when lam/n
