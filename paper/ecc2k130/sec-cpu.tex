\section{CPU clients}
\label{sec:cpu}

The CPU client is the bitsliced backend at the host's word width. It
matters for three reasons. It is how every GPU report gets verified,
it runs the ECC2K-95 end-to-end control, and the campaign's spot fleet
included CPU workers whose points cannot be told apart from the
GPUs'.

Table~\ref{tab:cpu} collects the measurements.\art{ecc2k130/README.md, ``Throughput''}
Two observations from it apply more widely. First, the AVX-512 build
spends half of each multiply moving data rather than computing
($4{,}069$ logic instructions against $4{,}287$ \texttt{vmovdqa32}),
because the Karatsuba leaf keeps 254 values live with only 32
registers. A scheduling pass over the same DAG recovered moves only
in the conversion ($4{,}287$ to $3{,}903$), missed its declared target,
and left the leaf size and the compiler on record as measured dead
ends.\art{ecc2k130/HOST-SCHEDULE.md} Second, on aarch64 the gain splits
cleanly. On the M4~Pro the NEON word with \texttt{BSL} alone is worth
$1.76\times$ and \texttt{EOR3} a further $1.24\times$, and a core
without \texttt{FEAT\_SHA3} (Graviton2) still gets $1.81\times$ from
the wider word and \texttt{BSL}. On this code the compiler matters more
than either: gcc emits $9{,}372$ instructions for the multiply leaf,
$59\%$ of them loads and stores of spilled temporaries, where clang
emits $1{,}902$ plus five outlined calls. We only enable the SHA3 path
when the CPU reports the feature. An ungated probe on a Graviton2
picks a \texttt{+sha3} spelling under both compilers, and the
resulting binary dies with \texttt{SIGILL} on its $8{,}907$
\texttt{eor3} instructions.\art{ecc2k130/README.md, ``Word width''}

In the fleet, a CPU worker at $2.3$~billion iterations/s (the self-reported median of
the twelve CPU slots on 2026-09-17) was worth about a sixth of an
RTX~PRO~6000. On Modal, a 32-thread (16-core) sidecar running beside a
GPU adds about $25\%$ to the container's cost for $2.7\%$ more
iterations, so it is off by default.\art{ecc2k130/benchmarks/dp-interval/raw/worker-counters-2026-09-17.tsv}\art{ecc2k130/README.md, ``Walking on the container's CPUs too''}
