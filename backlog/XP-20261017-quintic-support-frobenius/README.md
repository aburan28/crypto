# Native complete-support Frobenius comparison

The question is whether the exact cached quotient operator moves the complete
support path after setup and extraction. See [the derivation](../../research/quintic_cached_frobenius_20261017_v1/CONTRACT.md)
and [protocol](PROTOCOL.md). This card is blocked on native implementation,
input/source freezes, an independent checker and a reachable executor.
It is not ready or scheduled. The protocol's90second worker limit is a cap,
not a measured runtime estimate. Source and input hashes are deliberately not
invented. The dense symbolic operation model alone does not predict8x.

Outcome decisions: mismatch requires a new implementation/version; a regression
rejects uniform dispatch; no full-cost improvement redirects the work upstream.
Success would establish only this bounded component/pipeline comparison. The
novel all-roots8x objective and matched external baselines remain unresolved.
The existing original release gate is not weakened.
