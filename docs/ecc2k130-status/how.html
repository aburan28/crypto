Certicom ECC2K-130 · the algorithm, not the fleet

How the walk works

The live dashboard is a count of work. This page is the method: the same Pollard rho the GPUs run, on a curve small enough that a browser recovers k in a moment. The production kernels are bitsliced CUDA; the readable copy is ecc2k130/examples/rho_toy.py.

What the campaign is computing

A Koblitz curve over GF(2^131) and two points P, Q on it. The secret is the integer k with Q = [k]P. Certicom published the instance in 1997. Nobody has published k. The expected cost of a collision, from Bailey et al., is 2^60.9 group operations.

Independent walks start from random seeds and iterate

R ← R + τj(R)

with j = 3 + ((HW(x)/2) mod 8). Hamming weight is taken in a normal basis so it is constant on Frobenius orbits; the walk therefore runs on classes, not points, which is why this curve is easier than a prime-field curve of the same size. A point is distinguished when that weight is at most 32. Two walks that hit the same orbit give a linear equation for k. Until that happens, the only honest progress number is how many iterations the walkers have actually counted.

Run it here, on GF(223)

Same iteration, same distinguishing test, planted k. The subgroup is 21 bits, so a collision is a fraction of a second rather than a decade. This is not the challenge; it is the algorithm finishing. 

Press the button. The script is rho-toy.js, a line-for-line port of rho_toy.py.

The four steps in the Python file

  1. Walk: step(P) adds the Frobenius image τ^j(P).
  2. Distinguish: stop when HW(x) ≤ 8 (32 on the challenge).
  3. Collide: store the canonical orbit; a second seed on that orbit is the meeting.
  4. Solve: rewalk both seeds, build a, b from the branch counts, recover k, check [k]P = Q.

Run it locally with python3 ecc2k130/examples/rho_toy.py. The GPU client is the same loop with a packed field and millions of walks in flight; it is not a different attack.
