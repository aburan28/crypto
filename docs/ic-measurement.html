Index Calculus Measurement Standard

Two index-calculus figures are comparable only when they measured the same problem, in the same unit, over the same window, against the same reference, on the same class of host, under conditions that could not have moved the result. ICMS writes each of those down for every run and refuses a comparison when one differs. The audit behind it found 31 ways the existing figures were not apples to apples, 15 of them severe. The demonstrations below run on this repository's cloud container, a virtual machine that can be pinned and is sometimes quiet (L2) but is never isolated (L3). Operation counts there are exact except in rows marked host-dependent, where a solver was priced from host wall time. Wall time is admitted only when every run of both arms earned its declared level, and is otherwise shown as descriptive only.

One YAML file per configuration

A spec names everything that decides what was measured: the instance and workload, the factor-base family and its parameters, the symmetries folded out, large-prime and partition variants, the decomposition method, its encoding and splitting, the solver and every option that changes its search, the relation stop rule, the linear algebra, the descent, the reference, the unit, the window and the isolation required. Labels are not identity; everything else is hashed into the spec id. A new factor-base family or variant is a registry entry, not a schema change. Isolation levels

A run earns the highest level whose checks, and all lower levels' checks, passed. Unknown never passes. A spec may tighten a threshold, never loosen one. Wall time is admitted only at or above the spec's level, default L2. Operation counts need only L0, because they do not depend on contention.

levelrequires
L0 recordedthe run executed under a saved host capsule
L1 pinnedchild CPU mask read back equal to the reservation; CPU 0 excluded; other threads evicted; CPU time over wall at most the declared threads
L2 quietchild run-queue delay ≤ 0.5 %; zero hypervisor steal on the pinned CPUs; no foreign runnable task on them in any 50 ms sample; no memory stall; ≤ 50 preemptions/s; quiet preflight
L3 isolatedpinned CPUs in isolcpus or nohz_full; performance governor, turbo off; SMT off or siblings reserved; bare metal

Reproduce

From the repository root, on the host whose capsule you want recorded. Building is heavy work: run it through tools/isolated_bench.py busy so it cannot overlap a timed run.

python3 tools/isolated_bench.py busy -- cargo build --release --bin ic
python3 tools/icms capsule
python3 tools/icms validate docs/ic/measurement/specs/*.yaml
python3 tools/icms run A.yaml B.yaml A.yaml --cpus auto --out docs/ic/measurement/sessions/<new>
python3 tools/icms compare docs/ic/measurement/sessions/<new> --a 0 --b 1 --declare <field> --out …/comparisons/<name>.json
python3 tools/icms audit-sessions docs/ic/measurement/sessions
python3 scripts/build_ic_measurement.py

The audit re-derives every committed session from its raw files: hashes, ids, the isolation level of every run from its own observations, and every frozen comparison. CI runs it on every change.
