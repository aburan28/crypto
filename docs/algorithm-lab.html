01 / Factor bases

A small vocabulary of curve points

Coordinates mod 17

Here a factor base is a chosen set of elliptic-curve points. We try to write a target as a sum of two of them. It is not a prime factorization of the target’s coordinates.

E: y² = x³ + 2x + 2 (mod 17)  ·  G = (5, 1)  ·  ord(G) = 19

Pairs are unordered and may repeat a point. A larger base offers more pairs but also adds unknown logarithms to the matrix below.

How the example chooses and checks points

We take points with y ≤ 8, ordered by x, then keep the first B. This chooses one representative from each sign pair on this curve; this toy search uses only the selected points, without adding their negatives automatically. Real repository factor bases use subspace and orbit constructions.

Each candidate sum is computed with the elliptic-curve group law. The point at infinity is part of the group, but has no affine dot. The counters above count candidate pairs and distinct nonidentity targets covered, not runtime or cryptanalytic speedup.

Worked example at B = 4: F₁ = (0, 6), F₂ = (3, 1), and F₁ + F₂ = (13, 10) = [11]G.

02 / Linear algebra

Point relations become a matrix

Logarithms mod 19

If Fᵢ = [ℓᵢ]G, then Fᵢ + Fⱼ = [a]G gives ℓᵢ + ℓⱼ ≡ a (mod 19). The factor base above controls the columns here. Row operations use the subgroup order 19, while point coordinates use 17.

Inspect the original point relations
Augmented matrix [A | a], reduced over F₁₉

Current operation

The demo gathers known probes [a]G by explicit enumeration and selects independent relations for teaching. Gauss–Jordan elimination receives only the coefficient matrix and right-hand side. Each recovered logarithm is checked by multiplying G.

What the repository runs at larger sizes

This dense walkthrough makes every row operation visible. The repository also implements relation filtering and sparse block Wiedemann: duplicate and singleton handling, a smaller matrix core, sparse matrix-times-block products, reconstruction, and verification against the original relations. The small matrix here is not a benchmark of that implementation.

For B = 4, the recovered logarithms are (7, 4, 1, 2). The first relation gives 7 + 4 ≡ 11 (mod 19), and [11]G = (13, 10).

03 / SAT solvers

Decide, propagate, and backtrack

Boolean arithmetic · F₂

The binary-field route turns polynomial equations into Boolean constraints. Products become AND gates; sums become XOR parity rows. This four-variable example lets you follow those constraints through a small DPLL solver.

SAT finds candidate point decompositions before the relation matrix is solved. This Boolean example illustrates that solving machinery separately from the mod-17 curve above. The repository uses CDCL and native parity reasoning; this demo uses chronological backtracking and single-row XOR propagation.

Constraints at this step

Each CNF clause is an OR of literals; all clauses and parity rows must hold. ¬x means “not x”; ⊕ means XOR.

Solver step

Truth table: independently check all 16 assignments

Every row is checked against the original AND and parity constraints, regardless of the selected encoding. A satisfying row verifies SAT; no satisfying rows verifies UNSAT for this bounded example.
