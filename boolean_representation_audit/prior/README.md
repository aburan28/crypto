# Exact Boolean closure: candidate adaptation and negative performance result

2026-09-28. Standalone synthetic algebra audit; at most 10 variables.

The prototype correctly extends the recovered sparse storage component to exact Boolean ideal closure. It preserves zero-coordinate solutions and never discards high-degree terms. It passed all correctness controls, but was slower and used more Python memory than an elementary exhaustive reference on every declared measurement case. This is a correctness artifact, not evidence of a faster algebra solver, a new complexity bound, or a cryptanalytic improvement.

## What changed

The earlier component indexes squarefree monomials and reduces sparse GF(2) rows. Its optional degree cap can discard terms. The wrapper instead uses its full degree n and schedules exact rows by degree. It starts with input generators, reduces queued rows, and forms variable multiples of each newly independent row. An unchanged product is already represented and is not queued again. All other nonzero products remain eligible; none are discarded to maintain a degree bound.

Every accepted row records its source: an input generator or a variable multiple of a previously accepted row. A verifier with different column indexing and dense integer bitsets checks those records independently of the sparse reducer. Budget exhaustion is explicitly incomplete; partial results certify containment only.

This is an adaptation of the storage component into a small exact audit. Boolean arithmetic, sparse representations, degreewise completion and basis verification have substantial prior art. Mathematical novelty has not been established. The prototype does not transfer characteristic-zero toric theorems to Boolean rings.

## Exactness argument

Work in R = F2[x1,...,xn]/(xi^2+xi). Every polynomial is a sum of squarefree monomials; multiply their masks by bitwise union and cancel repeated terms modulo two.

Let I be the ideal generated by the inputs and V the span of certified rows. The provenance check proves V is contained in I: each accepted row differs from its declared source by a combination of earlier accepted rows. Checking that every input lies in V and that every variable multiple of every basis row lies in V proves that V is an ideal containing the inputs. Thus I is contained in V, and V = I. The argument does not exclude assignments containing zero.

The independent truth-table check uses that R is the algebra of all functions from {0,1}^n to F2. Therefore the dimension of I is 2^n minus the number of common zeros. The tests compare full solution sets as well as dimensions; rank alone is not used as the completion certificate.

For example, xy = 0 retains (x,y) = (0,0), (1,0), and (0,1). For x+1 = 0 in three variables, closure retains terms through degree three, including xyz; stopping at degree one would not certify this full ideal.

## Controls and measurements

Nine unittest methods passed, including 60 seeded random systems, zero-coordinate examples, duplicate cancellation, high-degree retention, malformed provenance, missing closure, omitted generators, empty/contradictory inputs and four resource limits. Both algorithms produced independently verified identical ideals on all eight measured systems.

Both algorithms use the identical recovered sparse representation and reducer. The exhaustive reference enumerates every monomial multiple of each input, so it is deliberately elementary. It is not PolyBoRi, F4/F5, or another optimized solver. Timings include construction, conversion, scheduling, elimination and certificate recording, but exclude verification. Each is the median of three untraced runs. Python allocation peaks come from one separate traced run and include certificates; they are not process RSS. At these tiny runtimes, timing ratios are descriptive only, not stable hardware claims.

## Interpretation and limits

The useful result is the independent completeness verifier and a reproducible negative control. Full ideal closure may require 2^n independent rows. That exponential ceiling makes this implementation unsuitable as a scalable sparse solver; the 10-variable limit is deliberate. The experiment measures no target curve, no blocked workload, and no end-to-end cryptographic task.

A broader sparse-algebra question remains whether repeated polynomial supports can be represented and reduced compactly throughout a computation. That is a hypothesis, not a result of this study; representation sharing and zero-suppressed decision diagrams already have prior art. No additional performance tuning was done after inspecting the declared suite.

The protocol was written before implementation and measurements. Recorded deviation: the two planted measurement systems use seeds 131+n, rather than the protocol's literal seed 131; all generated equations are included and no seed was changed after observing results. Exact inputs, seeds, individual runtimes, Python/platform details and counters are in results.json. SHA256SUMS records the delivered source after the experiment; it is not an independently timestamped preregistration. No process RSS or external state-of-the-art comparison was measured. This artifact is not an admission-ready benchmark for the repository's cryptanalytic claims.

## Reproduce

Python 3.10 or newer; standard library only. Extract this archive, enter its boolean_sparse_adaptation directory, then run:

```sh
sha256sum -c SHA256SUMS
python3 -m unittest -v test_boolean_closure
python3 measure.py
```

Run the hash check before rerunning measurements if checking the delivered evidence: rerunning measure.py intentionally replaces the runtime results. baseline/ contains the unchanged recovered source, original tests/report/results, and original hash manifest; that manifest was verified before use. example_certificate.json contains a complete small certificate.

## Primary sources reviewed

- PolyBoRi features: https://polybori.sourceforge.net/features.html — Boolean quotient arithmetic, ZDD polynomial representations and sharing/caching of common substructures.
- Mourrain and Trebuchet, Borderbasix: https://www-sop.inria.fr/teams/galaad/software/bbx/borderbasis.en.html — established degreewise prolongation, sparse linear reduction and completion checks. The prototype is not an implementation of their full algorithm.
- Bender, Faugere and Tsigaridas (2019): https://arxiv.org/abs/1902.00208 — sparse semigroup-algebra methods; the earlier applicability review identified characteristic-zero and torus assumptions. Their complexity bounds are not claimed here.
