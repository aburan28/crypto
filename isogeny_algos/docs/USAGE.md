# Using isogeny_algos

`isogeny_algos` is a standalone Rust crate (its own workspace, no dependencies) with a command
line, `isogeny-algos`, for the operations other tools in this repository need most: certified
point counts, rational isogenies with explicit kernels and maps, and modular polynomials, for
prime-field curves `y² = x³ + ax + b` with `p` up to 640 bits. Every result carries the checks
that were run on it; nothing is printed without a status.

## Build

```sh
cargo build --manifest-path isogeny_algos/Cargo.toml --locked --release
B=isogeny_algos/target/release/isogeny-algos
```

Binaries: `isogeny-algos` (this guide), `bench` and `micro` (benchmarks, see the README),
`report` (Markdown tables from a benchmark file), `gen_mont_adx` (prints the assembly embedded
in `fpm.rs`).

## Commands

Each run prints **one JSON object** on stdout.

| command | does |
|:--|:--|
| `count` | `#E(F_p)`, the trace, the twist's order, a certificate for each, ICV1 identities of the curve and its twist |
| `count --order N` | certifies a known order instead of counting (milliseconds at 256 bits) |
| `isogenies --ell L` | every F_p-rational ℓ-isogeny (ℓ prime, ℓ = 2 included): kernel polynomial, codomain, x-map, checks; `--order N` adds ICV1 slugs |
| `velu --ell L --kernel c0,c1,…,1` | the isogeny with that monic kernel polynomial (coefficients low to high) |
| `velu --ell L --kernel-x X` | the isogeny whose kernel is generated by a point with x-coordinate X (odd ℓ) |
| `velu --ell L --kernel-x X --method M` | the codomain by one formula: `kohel`, `velu` (P must be F_p-rational), `xonly` (x-only Vélu) or `sqrtvelu` (√élu) |
| `isogenies --ell L --method M` | the rational ℓ-isogenies with the kernel found by one BMSS variant: `linear_algebra`, `stark1972`, `atkin1992`, `atkin_modcomp`, `elkies1992`, `elkies1998`, `fast_elkies`, `fast_elkies_prime` (odd ℓ, j ∉ {0, 1728}, p > 2ℓ + 1) |
| `chain --ell L --n N` | the ℓⁿ-isogeny with kernel ⟨P⟩ as n ℓ-isogenies; P is `--kernel X,Y`, or found from #E (`--order N`, else counted); `--strategy naive\|balanced\|optimal` |
| `dual --ell L` | each rational ℓ-isogeny φ and its dual φ̂ (from Φ_ℓ alone), with φ̂ ∘ φ = [ℓ] checked |
| `csidh --exps E1,…` | the CSIDH class-group action on y² = x³ + Ax² + x over p = 4∏ℓᵢ − 1: `--primes L1,…` or `--preset csidh512`; `--a A` (default 0) |
| `path --p P --j1 J1 --j2 J2` | a path of ℓ-isogenies (`--ells`, default 2,3,5) between ordinary j-invariants by `--method galbraith` (BFS), `ghs` or `gs` (Galbraith–Stolbunov); `--max-steps` |
| `klpt --p P --norm N` | a random left O₀-ideal of norm N in B_{p,∞} (p ≡ 3 mod 4) and its KLPT-equivalent ideal of ℓ-power norm (`--ell`, default 2) |
| `richelot --p P --roots R1,…,R6` | the 15 Richelot (2,2)-isogenies out of J(y² = c∏(x − Rᵢ)) (`--lc c`, default 1; p < 2⁶²): a Jacobian codomain or a product E₁ × E₂ |
| `modpoly --ell L --p P [--j J]` | Φ_ℓ mod p, or Φ_ℓ(X, J) and its roots in F_p |
| `modpoly --ell L --integer` | Φ_ℓ over ℤ |
| `modpoly --method cm --ell L --modulus M` | Φ_ℓ modulo any positive integer, including composites and 1 |
| `modpoly --method cm --ell L --integer` | Signed integer coefficients by CM volcano walks and explicit CRT |
| `modpoly --method cm --ell L --p P [--j J]` | CM method with the usual prime-field output or evaluation/root extraction |
| `version` | `{"schema", "tool": {"name", "version"}}`, to pin the version a pipeline ran |

Curves are given as `--p P --a A --b B` (decimal; `a`, `b` may be negative) or by name with
`--curve p192 | p224 | p256 | secp256k1`. `--seed S` (default 1) fixes the random choices; the
results do not depend on it, only the sample points shown do.

### The record

```json
{"schema":"isogeny-algos/v1","command":"count",
 "tool":{"name":"isogeny-algos","version":"0.1.0"},
 "curve":{"field":"fp-<p>","form":"y^2=x^3+a*x+b","p":"…","a":"…","b":"…","j":"…","preset":"p256"},
 "result":{…},
 "checks":[{"name":"order.hasse_interval","status":"PASS","detail":"…"},…],
 "status":"PASS","elapsed_ms":23}
```

- Integers that can exceed 2⁵³ are **decimal strings**.
- `checks` lists every check with a status from the curve-audit vocabulary: `PASS`, `FAIL`,
  `INDETERMINATE` (not decided either way) and `NOT_RUN`. `status` is `FAIL` if any check
  failed, `INDETERMINATE` if any is not `PASS`, otherwise `PASS`.
- **Exit code:** 0 when every check passed; 3 when one is indeterminate and none failed; 1 when
  one failed; 2 on a usage error (then the record carries `"status":"USAGE"` and an `error`).

`count` result fields: `order`, `trace`, `twist_order`, `method` (`bsgs` below 2⁴⁰, `cm` for
j = 0 or 1728, `sea` with its Elkies congruences `[ℓᵏ, t mod ℓᵏ]` and Atkin data
`[ℓ, r, #candidates]`, or `given`), `certificate` and `twist.certificate` (below; their
`certified_by` is `point_orders`, `twist_order` or null), `icv1` and `twist_icv1` (`icv1`, `slug`,
`model_json`).

`isogenies` result: `isogenies[]`, each with `degree`, `codomain` {`a`, `b`, `j`, `icv1` when
`--order` is given}, `kernel` (monic, low to high), `x_map` {`num`, `den`} (den = kernel²) and
`verified`.

Result fields of the other commands:

- `velu --method`: `method`, `degree`, `codomain` {`a`, `b`, `j`}.
- `chain`: `ell`, `n`, `degree`, `strategy`, `kernel_point` [x, y], `codomain`, `j_path` (the
  j-invariants after each step), `operations` {`l_mults`, `evals`, `builds`}.
- `dual`: `pairs[]`, each {`isogeny` (as in `isogenies`), `dual` {`kernel`, `x_map`}}.
- `csidh`: `p`, `primes`, `exponents`, `a_in`, `a_out`.
- `path`: `method`, `length`, `j_path`, `degrees`, `work` (nodes expanded or walk steps).
  Closed sub-walks are cut out, so no vertex repeats.
- `klpt`: `norm_in`, `ideal_in` and `ideal_out` (Z-bases, each element [c0, c1, c2, c3, d] for
  (c0 + c1 i + c2 j + c3 k)/d with i² = −1, j² = −p), `ell`, `e` (N(J) = ℓᵉ), `xi` (J = I ξ),
  `attempts`.
- `richelot`: `isogenies[]`, each {`matching` (the root pairs of G1, G2, G3), `kind`
  (`jacobian`, `product` or `product_not_rational`), `codomain` {`sextic`} or {`cubic1`,
  `cubic2`}}, coefficients low to high.

## What the checks mean

- **Certified order** (`order_unique_in_hasse_interval: PASS`). Sample points P are checked
  to satisfy `[N]P = O`, and the order of each point is pinned down along the prime factors of
  N found by trial division, Pollard–Brent and Miller–Rabin. If the least common multiple D of
  these divisors exceeds 4√p, N is the only multiple of D in the Hasse interval, so it is the
  group order. This is a proof modulo the probable-prime tests on the factors of N. When N
  does not factor far enough the check is `INDETERMINATE`. A certified order for either the
  curve or its twist certifies the other, because `#E + #Eᵗ = 2p + 2`.
- **Isogeny checks.** `image_on_codomain` and `homomorphism` evaluate the map on 8 random pairs
  of points. `kernel_degree` checks that the kernel polynomial has degree (ℓ−1)/2 (1 for
  ℓ = 2). `modular_polynomial` checks that Φ_ℓ(j(E), j(E′)) = 0 when Φ_ℓ was used. These are
  strong checks but not a proof that the map is an isogeny.
- **Kernel formulas** (`velu --method`): the random-point checks above on the map the method
  built, and `codomain_matches_kohel`: the codomain equals Kohel's, computed from a kernel
  polynomial built separately from the x-multiples of P.
- **Chains**: `kernel_order` ([ℓⁿ]P = O, [ℓⁿ⁻¹]P ≠ O), the random-point checks on the
  composite, `kernel_maps_to_zero` (P pushed through the chain) and `matches_naive_strategy`
  (the naive strategy recomputes every kernel point, an independent route to the codomain).
- **Duals**: the random-point checks on φ̂, `codomain_is_domain`, and `dual_composition`:
  x(φ̂(φ(P))) = x([ℓ]P) on 8 random points.
- **CSIDH**: `matches_one_at_a_time` (the tree-strategy action against one isogeny at a time),
  and `input_supersingular` / `output_supersingular`: random points have order dividing p + 1,
  and one has order above 4√p, which no ordinary curve allows (CSIDH's validation). A curve
  that fails the input check is refused.
- **Paths**: `endpoints`, `modular_polynomial_edges` (Φ_ℓ(jᵢ, jᵢ₊₁) = 0 on every edge) and
  `explicit_isogenies`: every edge built as an explicit isogeny of its degree from a curve with
  j-invariant j1 (Elkies + BMSS; Kohel on a division-polynomial factor where Elkies' codomain is
  undefined), arriving at j2.
- **KLPT**: `norm` (N(J) = ℓᵉ recomputed from the basis), `integral` (J ⊆ O₀), `left_order`
  (O_L(J) = O₀), `equivalent` (J = I ξ), `primitive` (J ⊄ ℓO₀).
- **Richelot**: `l_polynomial` (for p < 512: the L-polynomial of the codomain, or L(E₁)L(E₂),
  equals that of J(C), by point counts) and, for a Jacobian codomain at any p,
  `image_on_codomain`: random points of C mapped through the Richelot correspondence lie on the
  codomain. A product codomain over p ≥ 512 is `INDETERMINATE`.
- **`modpoly`.** The mod-p output comes from Hecke operators and Newton's identities. The
  crate's tests check it against the linear-algebra Φ_ℓ and the CRT integer Φ_ℓ. `--integer`
  also checks the integer result against Φ_ℓ computed directly modulo 2⁶¹ − 1, a prime outside
  the CRT set.
- **`modpoly --method cm`.** Implements the CM surface/floor construction in
  Bröker–Lauter–Sutherland Algorithm 2.1 and explicit CRT (§6.2). It selects a
  fundamental discriminant, generates both class groups using paired prime ideals,
  certifies a Hilbert-polynomial seed's trace and torsion, walks the surface and
  floor using Frobenius eigenkernels, groups descendants by the class-group
  projection, and interpolates. CRT retains one residue matrix at a time and
  uses integer fixed-point rounding with a proven coefficient bound. The target
  modulus can share factors with the CRT primes. `--p` still requires a prime;
  `--j` requires `--p`. Choose exactly one of `--integer`, `--p`, or `--modulus`.
  `--method hecke` is the unchanged default.

### CM implementation limits and API

This is a bounded reference implementation, not the paper's optimized large-degree
implementation. Supported degrees are odd primes from 3 through 31. Automatic
selection searches odd fundamental `|D| <= 20000`, with ℓ split and `h(D) >= ℓ+2`.
It uses `v=1` for `D=5 mod 8`, otherwise `v=2`. CRT primes must be below `2^40`,
the floor discriminant satisfies `|ℓ²D| <= 16000000`, at most 4096 ideal classes
are enumerated, and auxiliary generator primes are at most 43. A custom
discriminant or exhausted sampling/search budget can return an error; it never
silently switches to q-expansions. Asymptotic parameter selection, optimized
polycyclic presentations, and Enge evaluation remain unimplemented.

The native numerical Hilbert polynomial supplies seed candidates. For each CRT
prime the code verifies the seed's trace (exact counting below `2^22`, otherwise
an exact point-order/Hasse certificate) and full ℓ-torsion, plus full 2-torsion
when `v=2`. These establish the maximal endomorphism order for this restricted
family. Class-orbit distinctness, Hilbert roots, neighbor counts, symmetry,
leading coefficients and all interpolation points are checked. None of these
checks depends on a q-expansion oracle at runtime.

Public convenience functions are `api::modular_polynomial_cm`,
`api::modular_polynomial_integer_cm`, and `api::modular_polynomial_cm_at`.
For reusable setup or a specific discriminant, use:

```rust
use isogeny_algos::{field::Rng, find::sutherland::cm::CmPlan, int::Int};
fn main() -> Result<(), String> {
    let plan = CmPlan::with_discriminant(5, -151)?;
    let mut rng = Rng::new(1);
    let at_talk_prime = plan.phi_mod_p(4451, 52, &mut rng)?;
    let mod_1000 = plan.phi_mod_m(&Int::from(1000u64), &mut rng)?;
    assert_eq!(at_talk_prime.len(), mod_1000.len());
    Ok(())
}
```

Matrices use `c[i][j]` for the coefficient of `X^i Y^j`; the CLI retains the
existing sparse symmetric output. Validation evidence and the exact scope of
the comparison are in [the implementation report](../../research/cm_volcano_crt_20261016/REPORT.md).

## Curve names: ICV1 and EC1

`count` emits the curve's **ICV1** identity: the string, the slug and the hashed model JSON. It
is computed exactly as in [`docs/curves/ICV1.md`](../../docs/curves/ICV1.md) (`AGENTS.md` §11),
and the tests pin it to the vectors of the crypto crate's `curve_id::prime`. The P-256 and
secp256k1 slugs it produces are the ones listed in `docs/curves/registry.json`.

- `end` and `level` are `unk` and `path` is `r`: neither the endomorphism ring nor a volcano
  position is certified here.
- A curve that is not yet in the registry must be registered before it is cited
  (`AGENTS.md` §11).
- The **EC1 curve UID** names an exact record (generator, subgroup, cofactor), which this crate
  does not have. Build it with the repository's `tools/curve_identity.py` or the walker's record
  code, and keep isogenous curves' identities separate (`docs/curve-identities.md`).

## From Rust

```toml
[dependencies]
isogeny_algos = { path = "../isogeny_algos" }   # no transitive dependencies
```

```rust
use isogeny_algos::api::{self, PrimeCurve};
let c = PrimeCurve::preset("p256").unwrap();
let n = /* known order */;
let pc = api::check_order(&c, &n, 1);
assert!(pc.certificate.certified);
let isos = api::isogenies(&c, 3, 1)?;     // Vec<IsogenyRecord> with kernels, maps, checks
```

`api` is the supported entry point: `PrimeCurve`, `count_points`, `check_order`,
`certify_order`, `isogenies`, `isogeny_from_kernel`, `kernel_from_x`, `modular_polynomial*`,
`isogeny_from_x` (`VeluMethod`), `isogenies_by` (`BmssMethod`), `ell_power_chain`
(`ChainStrategy`), `duals`, `csidh_action` / `csidh512_primes`, `isogeny_path` (`PathMethod`),
`klpt_random`, `richelot_isogenies`, and `with_field` for generic code over the field chosen by
the size of p. Every result carries its `checks`. The algorithm modules
underneath (`kernel::*`, `find::*`, `path::*`, `quat::*`, `theta*`, …) are documented in
[`docs/SURVEY.md`](SURVEY.md). They are research code: their signatures may change between
commits, so pin a commit.

## Cost (one run each on the 4-vCPU development VM)

| task | time |
|:--|:--|
| `count --curve p256 --order …` (certify a known order, and the twist) | 23 ms |
| `count --curve secp256k1` (CM count, certification) | 21–27 ms |
| `count`, 24-bit curve (BSGS) | < 0.1 s |
| `count`, 127-bit curve (SEA, Φ_ℓ computed on the way, both orders certified) | 2.9 s |
| `count`, 256-bit curve (SEA, ℓ ≤ 167; twist certified by point orders, curve through the twist; record `results/cli-count-256bit.json`) | 7 min 41 s |
| `isogenies --ell 7`, 61-bit curve | < 0.1 s |

Each SEA run computes Φ_ℓ mod p for every prime ℓ it uses and keeps nothing between runs (for
scale: all ℓ ≤ 89 at 127 bits take 9 s, `results/p12-speed.jsonl`). For a standard curve with a
published order, use `--order`.

## Where it fits

- **Curve audits** (the `audit-curve` skill in crypto-autoresearcher) need a certified `#E`, the
  trace, the twist order and explicit isogenies with independent checks. `count` and
  `isogenies` give these, with statuses in the same vocabulary as the audit's records.
- **`isogeny_walk`** (crypto's walker, [`docs/isogeny-walk/README.md`](../../docs/isogeny-walk/README.md))
  lists as limits: no 2-isogenies, ℓ ≲ 61 in practice because Φ_ℓ mod p is rebuilt at every
  start, and order proofs only for prime-order roots. `isogenies --ell 2`, the faster Φ_ℓ, and
  `count` cover those operations. They are not wired into the walker; that is a separate change.
- **Point counting elsewhere** (`ecc_safety.rs` brute force at 24 bits by default): `count`
  covers cryptographic sizes.

## Limits

- Prime fields with p > 3 only. GF(2ⁿ), GF(3ⁿ) and extension-field curves are in the library
  (`binary`, `gf3n`, `fpr`) but not in the command line; nor are theta (2,2)-isogenies, radical
  isogenies, Deuring correspondence, Delfs–Galbraith and endomorphism rings.
- `chain` needs ℓⁿ < 2⁶³; `richelot` p < 2⁶²; `klpt` p ≡ 3 mod 4.
- p ≤ 512 bits. SEA needs j ∉ {0, 1728}; those curves are counted by CM.
- `isogenies` for j = 0 or 1728, or for p ≤ ℓ + 1, uses division polynomials and is limited to
  ℓ ≤ 31.
- Nothing is constant-time; this is a research and audit tool, not a production library.
