X1 unit: Q_word is 64-bit word XORs per target (extraction + search).
Q_enum is C(|F|, m-1) word-ops at one word-op per pair (m=3) or point (m=2);
that undercounts enumeration, so Q/Q_enum is conservative against an advance.

The `agree` column is the correctness gate, and it has two strengths.
  `exhaustive, ==` : crossbred's root set equals exhaustive search's, exactly.
  `F4 capped, ⊆`   : past v = 24 exhaustive search does not fit, and F4+splitting
                     runs under its default max_solutions cap, so its list is a
                     prefix of the root set.  The check is then two one-sided
                     ones: every crossbred root verifies against the original
                     equations, and every root F4 found is one crossbred found.
A row that does not say `yes` is not a result.

What this prices is the decomposition oracle only.  Relation collection stays
Θ(2^n) with any oracle polynomial in the factor base — see
RESEARCH_SEMAEV_DECOMPOSITION.md, `What this does not buy`.
