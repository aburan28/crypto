# n37 one-target online control: verified near parity, no controlled win

The frozen public point is `Q = [82317944755, 6781999994]` on the Koblitz
`a=0` curve over `GF(2^37)`, generated by native hash-to-curve seed `370413`.
Its subgroup order is `230603167`. Neither program received the recovered
scalar as input. Strong signed-Frobenius rho and compact-orbit IC each
recovered `208760117`, and the independent native general-law replay verified
`[208760117]G = Q` in all six post-fix pairs. The IC base had **518 actual
points and seven folded columns**. Every IC run reached rank 7 in seven
verified relations, with zero failed rank attempts and zero target failures.

The separately calculated median of the six paired **IC/rho** ratios is
`0.9276907676250028` (shown as `0.927691` on the progress chart). With an
even number of pairs, that is not exactly the reciprocal of the displayed
median rho/IC ratio.

The paired ratio spans **0.6433–1.1420** on this unisolated Apple M4 Pro
(14 cores, 48 GB RAM; Darwin 25.6.0). It changes direction between pairs.
These sub-millisecond wall times are **exploratory**: there is no exclusive
CPU partition, fixed-frequency/IRQ/noise receipt, or host-level isolation
record. The controlled speedup field is therefore **unknown**. The local
median is a description of this sample, not an IC win or an ECC2K-130
prediction. This experiment measures the one-target **online** interval only;
the reusable preparation and complete cold-start total remain separate and
have no fully exclusive charge certificate here.

The IC clock starts at `target_query_begin` after base construction, root
index, rank collection, and log solving, then stops at `recovery_check_end`.
Its exclusive phases are query, PDP, relation check, descent, and scalar
replay. The phase sum equals `online_ms` in every retained row. For r2 these
costs are `0`, `0.197626`, `0.010708`, `0.000125`, and `0.012083` ms;
the zero query entry is below timer resolution, not a missing phase. Rho's
online value is `walk_ms + validation_ms`; public-point generation and rho
jump setup are excluded. The same `Q` and same frozen resource acceptance
limit were used in both arms. Peak RSS was at most 2,539,520 bytes for IC
and 2,179,072 bytes for rho, below the preregistered 16 GiB acceptance gate.
The gate was measured with native `getrusage`; macOS rejected `ulimit -v`,
so the limit was checked after each run rather than enforced by the kernel.

The independent replay uses `binary_ecc::curve` rather than the producer's
packed group arithmetic. For every pair it rebuilt the seven-column modular
matrix, checked each rank relation and rank transition, verified all 518
base-point logs with general-law scalar multiplication, summed the target
witness, and replayed both recovered scalars. Two negative controls were
rejected: changing `recovered_scalar` by one produced `target relation or
recovered scalar failed replay`; changing the first rank-row coefficient
produced `rank row 0 differs` (both exit code 1). The targeted native rho
test `strong_backend_recovers_fixture_scalars` passed. `rustfmt --check` on
the three touched examples and `git diff --check` passed; repository-wide
`cargo fmt --all -- --check` reports pre-existing formatting differences in
unrelated files, so this PR does not rewrite them.

The `pilot/` directory preserves the first pair before RSS accounting was
fixed. It solved the point, but IC reported `peak_rss_bytes: null`; its
0.138500 ms IC and 0.140792 ms rho intervals are **excluded** from the table
and all acceptance counts. The failed `ulimit -v` preflight is likewise not
silently counted as a measured run.

## Reproduction and provenance

The preregistered [protocol](PROTOCOL.md) was committed before measurement.
All accepted raw outputs are in this directory (`r2` at top level, `r3`–`r7`
under `pairs/`), including the base, full rank transcript, target input,
both arms, and replay receipts. `replay_v1.jsonl` preserves the earlier
verifier output; `replay.jsonl` comes from the stricter final verifier. The
fixed-order [runner](run_repeats.sh) reproduces `r3`–`r7` from a release
example binary directory, refusing to overwrite an existing run. The raw
files are covered by `SHA256SUMS`; source, dependency lockfile, and exact
binary hashes are in `BUILD_SHA256SUMS`. Both `replay_v1.jsonl` and
`replay_v2.jsonl` preserve earlier verifier receipts; `replay.jsonl` is from
the final verifier. The build used `cargo build --offline --release` with
Rust 1.93.1 on `aarch64-apple-darwin`. IC and rho producer files and
binaries were frozen at `d6f2ef298`; later commits froze the repeat schedule
and strengthened independent replay. The exact IC/rho source
hashes are `50fbf161…` and `9c6ff4f7…`; exact accepted binary hashes are
`e5aaadb3…` and `1f766088…`. The target-point input hash is `3e71f654…`.

This resolves the n37 one-target **correctness and phase-accounting control**.
It does not settle n41/n53 or the ECC2K-130 transfer question. The next
decision for the active goal is a matched, isolated one-target measurement
on a larger rung with the same five-phase and independent-replay contract,
followed by cold fully charged runs and explicit n131 transfer bounds.
