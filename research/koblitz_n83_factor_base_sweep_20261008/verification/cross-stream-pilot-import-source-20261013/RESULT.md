# Pinned cross-stream pilot import gate: source availability only

The mixed-orbit worker now has a read-only `verify-cross-pilot` mode for two
objects from the exact 54-row pilot manifest. An object is selected by its
compressed BLAKE3, and the importer requires the byte-identical embedded
manifest, the row's exact S3 path and compressed length, both compressed and
plain hashes, every curve/source-point/phase/sign record, and the reconstructed
signed-Frobenius orbit map. It admits the 27 primary `a=0` rows across three
public-x policies, three seeds, and K=64/256/600; it rejects the other curve
arm. The two selected rows must differ in policy or seed.

After both archives replay, the worker calls
`build_exact_residual_difference_factor_base` and reports complete shared,
small-only, and pool-only signed-orbit counts. The residual constructor rejects
partial overlap, corrupt labels, an empty residual, and overlapping x-domains.
This mode does not call SAT, build a large-prime graph, or download an object.
It provides an exact import gate for non-nested existing factor bases; it does
not make the earlier v3 nested-pair design exhaustive over cross-stream pairs.

The [manifest-only census](census.json) is generated by [census.py](census.py)
from pilot manifest SHA-256
`5bd862987844f709e03beeab9fd265e3d2024011bcadcb82f5af9c72018df6a6`.
It records **648 ordered, source-addressable primary-arm cross-stream pairs**:
216 each with smaller, equal, and larger small-base K relative to the pool;
162 each differing only in policy or only in seed; 324 differing in both. The
receipt lists all 27 pinned object identities and S3 URIs. These counts are
Cartesian addresses, not successful imports: two different streams can still
have an empty pool-minus-small domain, and no actual pair's orbit overlap was
measured in this source step.

Validation: the release mixed-orbit example passed five tests, including a
new control that selects exactly 27 primary rows and rejects all 27 other-arm
rows, changed manifest bytes, an invalid object hash, and wrong compressed
bytes. The small-field residual-difference control and full release library
suite passed at the unchanged library source in the prior publication step.
The K600 supervisor's historical import check now hashes the worker blob at
frozen build commit `f3d27f68b68cda907e0668042ac7fa13ae6b579d`, rather
than today's worker file. Its five focused tests pass, including rejection of
a changed frozen-source digest and a changed import disposition while allowing
subsequent source edits. New build/run receipts still bind the current clean
source through the supervisor's separate `source_hashes` check.
The census reproduces byte-for-byte with:

```sh
python3 research/koblitz_n83_factor_base_sweep_20261008/verification/cross-stream-pilot-import-source-20261013/census.py --check
cargo test --release --example koblitz_n83_mixed_orbit_worker -q -- --test-threads=1
```

No retained N83 archive import, SAT search, relation, rank, linear algebra,
individual log, or matched-rho measurement was launched here. No S3 object
was read or written, and the conservative local experimental ledger remains
17,400 seconds. A real cross-stream pair requires a separately accounted
archive download/import and independent output audit before any relation
search. Neither this gate nor the census identifies a minimum-runtime base.
