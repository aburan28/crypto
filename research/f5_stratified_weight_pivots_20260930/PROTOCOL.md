# Stratified current-weight F5 pivots: frozen structural and paired screen

## Hypothesis, prior failures and reference

The [unbounded current-weight candidate](../gf2_minweight_pivots_20260929/RESULT.md) roughly halved returned n24 degree-4 terms but slowed the complete call while maintaining all row weights after table updates. The [first-8/16 bounded candidate](../f5_bounded_weight_pivots_20260930/RESULT.md) avoided that maintenance but reduced terms by only 1.6–3.6%; its eligible choices came from the front of the strip. This experiment tests whether **spreading a fixed number of candidates across the entire remaining strip** recovers the lighter pivot rows without paying for per-update weight maintenance. It is a distinct opt-in research route. The returned echelon basis may change, so rank and canonical row space must match exactly; no caller-contract promotion follows without the user's decision on row-space-equivalent output.

The reference is merged main `28620d9fa2f095efb8d9048f19014900045906b1`: `gf2_elim.rs` SHA-256 `6fd3f10ef8e681490784c624e703eeb8fa887c5817ec9bdf34844e3f943c7f5c`, `matrix_f5_f2.rs` `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da`, benchmark `f4_f2_bench.rs` `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336`, isolation wrapper `ff59e53fd5566078ad493c8be0d06168699c4fd194bc881d99df19fa20e007ef`. New timing uses same-binary paired calls, never an absolute time from another host.

## Candidate and workload

`KIC_GF2_PIVOT_STRATA=0` keeps the reference. `=16` or `=32` applies only to echelon elimination with at least 4,096 packed rows and 4,096 columns. After the existing search finds the next pivot column, divide the unpivoted strip into `min(K, remaining_rows)` consecutive, nearly equal bands. In each band, inspect strip entries in row order and use the first row with that pivot bit; if none exists, skip the band. Count the **current packed suffix** popcount for each selected row and choose the lightest, breaking ties by row order. There is no global row-weight array and no row-weight recounting during table application. Charge every scan and popcount to reduction and the complete call. Record an actual route indicator. The original rule remains the default and serves smaller matrices and RREF.

The local screen uses one Rayon thread, the seven F5 cases in `examples/f4_f2_bench.rs`, seed XORs `0` and `badc0de1`, and primary `f5_n24_m24_d4`. Fix selective echelon, fused row counting, direct packed build and scalar unpack, branchless AVX2 strip where present, AVX2 row XOR, four Gray-code tables and table reuse; disable deferred-above, word batching, AVX-512 unpack and experimental table construction. Use separate processes for `K=0`, `16`, and `32` so env caches cannot cross arms. Correctness requires unchanged rank, canonical row-space fingerprint, criterion work, built/pruned row and column counts for every case. Raw rows, term count and reduction word operations may differ only where the stratified route is selected. Unit tests compare small random, sparse, dense and partial-word echelon rank and canonical RREF for both K values. Preserve all processes, failures, timeouts and OOMs.

## Frozen selection and speed gates

Build and test through `tools/isolated_bench.py busy`. First run one **untimed-for-decision** reference and one candidate process per K and seed, preserving full JSON output, source/binary hashes, host and route. Select K=16 if both seeds emit at most 75% of reference primary terms; otherwise select K=32 if both do; otherwise reject without paired timing. Selection uses only deterministic term counts and correctness, never observed wall time. A failed route or exactness check rejects. The 75% threshold asks for a substantial fraction of the unbounded method's term reduction and is only a structural progression gate.

If selected, run a local Apple ARM64 paired screen for that K: per seed, one warmup per arm, five reference/reference A/A pairs and five alternating reference/candidate pairs. Preserve every process output, host/load, source and binary hashes, exclusive phases, complete-call time, counts and fingerprints. Use `tools/isolated_bench.py reserve` when this host can reserve a core. With qualified isolation, advance to x86 only if both primary complete-call paired medians are at least 1.05 and no smaller case falls below 0.95. Without qualified isolation, mark local ratios exploratory: reject only if both primary medians are below 0.90 or correctness fails; otherwise advance to x86 for a qualified decision, without claiming a local speed gain. The at-most-75% term gate applies throughout. A local rejection archives the exact patch, harness and raw receipt and removes the runtime option.

A passing local candidate then requires Linux x86-64 AVX2/BMI2 same-binary one- and two-thread pairs on seeds `0`, `badc0de1`, `5eed2026`, `f5c02a28`, five A/A and five alternating A/B pairs each, first-clean isolation, zero eligible user threads and zero contended samples. Incremental advancement needs the frozen one-thread full-call median at least 1.10, exact 3,125-resample bootstrap lower bound above 1.05, no seed or smaller case below its A/A minimum, and no two-thread regression. The user's further 2× target requires the frozen full-call median **and** its lower bound above 2.0 with all guards. A passing performance result remains opt-in until the changed echelon basis is accepted as a caller contract. These are Boolean matrix-F5 solver-stage diagnostics, not IC one-target DLP or rho speedups.
