# WDSat child-status triage result

Protocol: [WDSAT_CHILD_STATUS_PROTOCOL_20260925.md](WDSAT_CHILD_STATUS_PROTOCOL_20260925.md). Scope: the Rust Semaev `wdsat_oracle.rs` adapter only. This is a correctness repair, not a new solver campaign or ECDLP speed result.

## Result

A child with a nonzero exit is now an error at the process boundary and an exhausted/unknown decomposition at the oracle boundary, even if it printed `UNSAT`. A successful child with empty stdout, stderr-only `UNSAT`, or an unrecognized line is also exhausted/unknown. The adapter marks a model-free run refuted only for a successful child with exactly `UNSAT` or `UNSAT on XORGAUSS init` on stdout, the two markers in upstream WDSat [`61c6ff3f49445af2729274819edb27b85a89efc1`](https://github.com/mtrimoska/WDSat/blob/61c6ff3f49445af2729274819edb27b85a89efc1/src/wdsat.c#L462-L561). A returned model still has to pass ANF, original-equation and group-law checks.

The mock-child regression drove zero/nonzero/empty, nonzero-plus-misleading-UNSAT, stderr-only-UNSAT, explicit UNSAT, valid model and invalid model through the real child launch and/or `wdsat_decompose`. For the valid n=7 model, the test exhaustively found a root of the planted tiny system that lifted to factor-base points, sent its bits through a shell child, then independently re-added recovered points to the exact target. The invalid model remained `spurious` plus `exhausted`, never `refuted`.
