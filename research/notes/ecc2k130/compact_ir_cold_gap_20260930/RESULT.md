# Matched cold CPU closes the four missing compact-orbit cells

The [preregistered protocol](PROTOCOL.md) was committed in [PR #1053](https://github.com/aburan28/crypto/pull/1053) before inspection of the [complete instruction result](../compact_ir_ledger_20260930/RESULT.md). [Hosted run 36694337420](https://github.com/aburan28/crypto/actions/runs/36694337420) checked out merged main `fe75eea69dc66660c3920342d83f17e3f4eb1151`, materialized the pinned twenty-file source freeze, and built the current W64 compact producer and signed-Frobenius normal-basis rho v3. Each n/L cell ran on its own Linux x86-64 runner, with the same public Q, one pinned CPU and byte-identical compact/rho binaries across this four-cell panel. All setup, index construction, full rank, linear solve, target recovery, group checks and audit output are inside each fresh process.

All **105 child processes** completed, with **70 compact full-rank traces** and **15,450 recovered target logarithms**. The hosted verifier and a separate macOS replay independently checked every rank relation and scalar against verifier-only labels. The two receipts agree for all four cells. Every A/A median lies in the preregistered [0.9, 1.1] window, every A/A 95% interval contains one, and every isolation monitor reports zero contended samples. No arm, block, Q list or cell was selected out after measurement.

Each CPU ratio is the median across the fixed blocks of `sqrt(CPU_off_a × CPU_off_b) / CPU_rho`; the interval is the preregistered two-sided 95% log-ratio t interval. CPU is `wait4` child user plus system time, not runner wall time. The Ir column is the separate same-Q [Callgrind ledger](../compact_ir_ledger_20260930/RESULT.md), whose builds and runners differ from this native panel. It is a qualitative all-phase work comparison, not a conversion from guest instructions to cycles or group additions. The runner polls `wait4` at roughly 0.2-second intervals, which coarsens short-arm elapsed wall measurements, especially rho. Raw wall values remain archived but **no wall ratio is eligible as a speed claim** from this panel.

The n37 batch cell is the sharpest accounting discrepancy: complete IC uses 0.5165 times rho's guest instructions but 1.7064 times its eligible native CPU. The n41/n53 batch cells previously measured on the same frozen source/Q in the [blocked-prefilter repeat](../compact_s3_prefilter_20260930/RESULT.md) likewise have eligible filtered IC/rho cold CPU ratios 1.3282 and 1.4727 (off ratios 1.5711 and 1.6442), despite off Ir ratios 0.6221 and 0.7773. Together these cover all six current-source n37/41/53, L=1/1,024 cells in the instruction matrix. The earlier n37/n41/n53 single-target CPU numbers came from a different rho/source snapshot; this panel replaces them for the current source. The data do not isolate a cache, branch, compiler or field-arithmetic cause for the Ir/CPU difference.

**Decision.** None of the six tested current-source W64 compact cells has an eligible end-to-end cold CPU crossover against the strong matched rho. At fixed reference and unchanged other costs, even the best single/batch outcomes would need a total CPU reduction of `1 - 1/R`: 41.4% at n37/L1,024, 24.7% for the n41 blocked batch, or 32.1% for the n53 blocked batch. These are workload-specific break-even distances, not estimates of how much any proposed PDP or factor-base change will save. The K+L compact attempt floor is already met, so a next experiment should target the cost per useful relation and base/index construction while preserving rank and useful-base size. The separately certified degree-263 transport changes the endomorphism order but has no measured native m≥3 PDP benefit yet; the next gate is the independently reviewed, label-gated [m10 capacity PR #937](https://github.com/aburan28/crypto/pull/937), followed by frozen natural-target native-descendant/source/transported/pullback comparison at equal useful-base size if that gate passes. A disjoint-Q cold confirmation, n83 wide-field transfer and GF(2^131) cost assumptions remain unmeasured. This same-Q panel does not establish a method crossover or an ECC2K-130 challenge result.
