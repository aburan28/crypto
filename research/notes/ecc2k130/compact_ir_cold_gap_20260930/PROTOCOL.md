# Matched cold native CPU gap panel for the compact instruction ledger

Status: preregistered before any run of this panel or inspection of the dispatched Callgrind result. The merged instruction-ledger source and all four Q lists are fixed; this is not a new target-distribution holdout, a descendant-native PDP experiment, or an ECC2K-130 challenge attack.

## Question and boundary

The [six-cell whole-process instruction protocol](../compact_ir_ledger_20260930/PROTOCOL.md) runs the latest frozen W64 compact S3 producer and 32-walk normal-basis signed-Frobenius rho v3 on identical public Q. The earlier cold point panel used an older rho/source snapshot for n37/L1, n37/L1024, n41/L1 and n53/L1. The [blocked-prefilter repeat](../compact_s3_prefilter_20260930/RESULT.md) already provides eligible latest-source matched cold CPU at n41/n53 L1024, with filtered IC/rho ratios 1.3282 and 1.4727. This panel fills the four missing current-source cells without adaptively choosing a size after seeing instruction counts.

The exact twenty-file source is the blocked-prefilter `FROZEN.json`, materialized from committed snapshots and compiled with its pinned lockfile. `CONFIG.json` pins the instruction-ledger config hash, four cell IDs, Q/label hashes, K, source freeze and arm count. Each arm is a fresh full process from startup through base/index construction, full rank, linear algebra, all target recoveries, group checks and audit output. No label enters the producer. Every compact rank trace and scalar and every rho scalar must pass the independent Python group-law verifier. Use `RAYON_NUM_THREADS=1`, W64 S3, rank seed 7, window 64, prefilter off, rho DP4, normal-basis canonicalization and signed Frobenius. No candidate, K, Q, arm order or source may be changed after the first timing result.

## Paired execution and accounting

Run three arms per block: `off_a`, `rho`, `off_b`, rotating that fixed order by offsets 0,1,2. There are 20 blocks at n37/L1 because the process is very short, and five blocks at each other cell. Pin every child and the reserve monitor to one selected Linux CPU. The reference and both off controls use exactly the same Q and binary in each cell. Each child has a 900-second process timeout and 5-GiB address-space limit; the cell job has a 90-minute cap. Record wait4 user+system CPU, wall time, max RSS, exit/timeout, exact command and environment, all raw traces, source/binary/input hashes, host CPU model/flags, and the reserved-core monitor. One block never reuses a process; a failed arm remains in the ledger.

For block $b$, use $\sqrt{T_{\mathrm{offA},b}T_{\mathrm{offB},b}}/T_{\rho,b}$ as the complete CPU ratio and $T_{\mathrm{offB},b}/T_{\mathrm{offA},b}$ as the drift control. Report the median and a two-sided 95% log-ratio t interval across all preselected blocks, along with every process's CPU, wall and RSS. The A/A interval must include one and its median must lie in [0.9,1.1]. The isolation monitor must show zero contended samples. Stop the cell after its first unsuccessful child and preserve every completed arm plus the failure. If an arm fails, times out, exceeds the cap, fails replay, or an eligibility gate fails, report that entire cell's timing as censored/ineligible; do not discard a block, pick a favorable subset or rerun in this protocol. The repeated Q measures execution noise, not target-distribution uncertainty.

Compare these four within-cell CPU ratios to the same-Q instruction ratios only after independent replay. Carry forward the two eligible n41/n53 batch CPU rows separately, with their different hosts and Q identified. A same-Q CPU or Ir lead is an engineering diagnostic. A method crossover remains unset unless both units win and a separately frozen disjoint-Q cold confirmation passes with every setup cost and scalar checked. No cross-degree runtime exponent, generic-group S, n83 result or n131 transfer follows from this panel.
