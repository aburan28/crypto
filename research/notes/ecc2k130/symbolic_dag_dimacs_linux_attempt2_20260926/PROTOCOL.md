## Frozen inputs and source

`PREPARE.json` pins the #804 first-run identity and the SHA-256 of the unchanged `INPUT.json`, `bounded.py`, `export.py`, `produce.py`, `verify.py`, vendored DRAT-trim source/license, parent #802 freeze/raw rows, and archived CaDiCaL SAT transcript. `check_parent.py` verifies these bytes and the first failed receipt before any Linux preparation. It also pins the official [CaDiCaL 3.0.1 release](https://github.com/arminbiere/cadical/releases/tag/rel-3.0.1) tag `rel-3.0.1` at commit `c60730422e758ef1cebe7aeddf2dda31c996bf04`, Git tree `9630ba7aaccee77f6fec916e5babd6d1ccedd404`, and a tracked-path/mode/blob SHA-256 `d6b6be954a455b1ea8bd0d75d00f52b3fef5ff7d41ecb65e53a80a9fc47f51c2` over 468 files. `source_manifest.py` checks all three identities and `VERSION=3.0.1`; tag movement or any byte mismatch stops preparation. The content digest starts with `cadical-source-manifest-v2\0`, then for each `git ls-files -s -z` entry adds its four-byte big-endian path length, path bytes, six-byte Git mode, and SHA-256 of the Git blob bytes. This treats symlinks as their tracked link text and is independent of checkout behavior. The upstream [build instructions](https://github.com/arminbiere/cadical/blob/rel-3.0.1/BUILD.md) specify `./configure && make`; this preparation fixes `./configure`, then `make -j2 cadical`, with `CC=/usr/bin/gcc`, `CXX=/usr/bin/g++`, `AR=/usr/bin/ar`, `LC_ALL=C`, `TZ=UTC`, and `SOURCE_DATE_EPOCH=1784475655`.

The target is an `ubuntu-24.04` GitHub Actions x86-64 runner with Python 3.12. The preparation receipt must record its exact image version, OS release, kernel, Python executable/version, GCC/G++/binutils/make/glibc outputs, build commands/logs, source digest, and both binary SHA-256 values. Two independent source checkouts/builds under the same captured toolchain must yield identical executable hashes; otherwise preparation fails and no result is promoted. The preparation workflow must upload the binary, receipt, and logs even on failure. After a successful preparation, the exact selected binary and receipt must be committed as Git blobs with their SHA-256 values in a distinct attempt-2 freeze before any measured dispatch; an expiring Actions artifact alone is insufficient. `PREPARE.json` deliberately leaves the Linux binary and build-receipt hashes null and `measured_attempt2_admitted=false`; these are release blockers, not values to fill from a measured result.

## Harmless Linux gate before any producer

After peer review of this design, add a preparation-only workflow to this stacked PR. It must check out the exact reviewed head, run `harmless_cap_probe.py` before the build, then run `prepare_cadical.py`; it must never invoke #804's `run.py` or `produce.py`. The probe launches `/usr/bin/true` and a disposable Python child under hard `RLIMIT_AS=(cap,cap)` at each unchanged phase cap: 512 MiB, 1 GiB, and 2 GiB. The child must report those exact limits and reject an anonymous mapping larger than its cap. Preserve its JSON receipt even on failure. Failure to set or demonstrate a hard cap, wrong architecture, source/hash/version drift, a build failure, or unequal binary hashes stops the process before any measured child. Sampled RSS alone is not an equivalent replacement for this hard-limit gate.

## Separate attempt-2 release and decision

A later, independently reviewed release commit must create a **separate v2 runner/archive namespace** without changing #804's raw first attempt. It must pin the exact Linux binary Git blob/SHA, preparation receipt and toolchain, both source-build hashes, PR checkout head, main/parent ancestry and bytes, source/input/cap hashes, proof checker, and a new unique archive path. The Linux binary is a new measured tool, so its provenance and host class must be explicit even though solver version remains 3.0.1. The semantic `INPUT.json`, exporter, producer, verifier, DRAT source, and phase caps must remain byte-identical to #804; any change to them is a new experiment, not this host correction. Provenance plumbing may change only with a reviewed diff and new freeze. The v2 archive replay must independently verify the new release gate and the first failure's pinned bytes.

The fixed caps remain: toy wall 60 s/RSS-address space 512 MiB/CNF 1 MiB; n13 panel wall 1800 s/RSS-address space 2 GiB/query CNF 8 MiB; solver wall 30 s and n13 query RSS-address space 1 GiB; n131 export wall 90 s/RSS-address space 512 MiB/CNF 64 MiB/node cap 500,000; proof 128 MiB; checker compilation and checking wall 60 s each. The single cold v2 run may begin only after the Linux preparation receipt and executable are frozen, exact-head hash-only CI passes, and independent review clears the complete release. It runs toy, then n13, then n131 once, stopping on the first failure and preserving every raw byte. SAT requires a complete model and independent group-law lift; UNSAT requires a nonempty text DRAT proof independently checked on the exact CNF. Timeout, missing proof, launch error, cap failure, or incomplete archive is not a pass. The full gate passes only if all three phases pass their existing verifier and caps.

Record Linux source/build/preparation cost and the three phase CPU, wall, RSS, proof, and archive costs separately. This gate measures a single-edge circuit and export feasibility, not a recovered ECDLP; it cannot establish a factor-base, relation-rank, or rho crossover. No `S`, speedup, or n131 attack feasibility number is inferred from preparation or a partial gate.
