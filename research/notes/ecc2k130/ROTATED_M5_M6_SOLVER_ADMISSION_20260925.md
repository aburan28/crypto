# Admission gate for rotated five- and six-summand PDP solvers

Status: source/evidence audit on main f00acba3d07f9eefb2b41581cdf33a01aa46ae76 (2026-09-25). This note contains no rotated S6/S7 solver outcomes and no ECDLP speed claim. The next experiment must freeze its own corpus and caps before running.

## Decision

Build **one canonical square-free GF(2) polynomial corpus** and independently verify its point semantics before timing a portfolio. The existing S4 corpus formats and solver interface are reusable patterns, but none of the current in-process BooleanSystem engines can ingest an n = 131 system with roughly 125–126 summand bits. A multiword polynomial representation or a direct streaming exporter is an admission prerequisite, not an optimization. Compare the direct S6/S7 system and a recursive S3/S4 chain as different *encodings of the same point-decomposition question* only after exceptional branches and target translates have been accounted for.

Initial admission uses the original Koblitz source and its cheap Frobenius τ and associated λ compression. The degree-263 descending leaf has a different endomorphism order and lacks that cheap geometric action in the measured implementation; transport, dual and leaf action already have material costs ([decision ledger](NEXT_EXPERIMENT_DECISIONS_20260925.md), [degree-263 receipts](RESEARCH_NEXT_EXPERIMENTS_20260924.md)). Add a leaf arm only later, as an equal-useful-size, same-target comparator after source support and solver gates pass; do not charge transport to neither side or infer leaf yield from a source solve.

The earliest meaningful portfolio measurement is a **small-rung solver-stage diagnostic**. It cannot establish a full index-calculus crossover: factor-base construction, failed queries, relation rank, linear algebra, point-log recovery, and matched batched rho remain outside that timing.

## Equivalence and size gates before a solver runs

1. Freeze curve/field polynomial and basis transforms, factor-base predicate, all point-only targets, arity, variable order, and an ordered list of square-free monomials per equation in a versioned manifest. Save SHA-256 of the canonical equations and of each derived encoding, exact producer/source commits, binary hashes, and conversion commands. Derive direct S6/S7 and recursive-chain files from the same mathematical PDP specification; do not silently compare different solution sets.
2. The direct S6/S7 representation uses only summand-coordinate bits before any optional auxiliary encoding. For illustrative dimensions ell = 25 at m = 5 and ell = 21 at m = 6, these are m·ell = **125** and **126** bits at n = 131. An S3 chain has m·ell + (m−2)n variables: **518** and **650**, respectively, before field-equation, denominator/exception or solver auxiliaries. Even the direct form exceeds the repository's 64-bit monomial mask. If a rotated factor base uses a non-linear membership test rather than an F2 subspace, record its defining equations/auxiliaries too. These are layout counts, not a feasible solver or memory estimate.
3. Introduce a pinned multiword Boolean monomial representation or a canonical streaming ANF/extended-DIMACS exporter that does not round-trip through u64 F2BoolPoly. Cross-check evaluations against an independent field/group implementation on every frozen planted witness and randomized assignments. Count exporter time, bytes, peak RSS, variable and equation counts, degree and monomial histogram before any solver ranking.
4. Treat a direct resultant's zero as an *algebraic candidate*, not automatically a rational point relation. Lift each abscissa to both rational signs where they exist, check base membership and all exclusions, and recompute the signed sum against the exact target. If derivation clears a denominator, cover its zero locus by an explicit exceptional branch or prove it cannot occur; check chain/elimination branches the same way. Encode any allowed cofactor-torsion relation as an explicit target translate Q+T (including the permitted E[4] cases), and label exact-Q versus translated-Q outcomes. The [S4 source](../../../src/cryptanalysis/binary_semaev.rs) explicitly warns that vanishing can admit lifts only over a quadratic extension; the [cofactor audit](RESEARCH_ECC2K130_RELATION_SWEEPS.md) shows why E[4] accounting changes usable relations.
5. On a small rung, compare the direct and chain encodings against a complete independent group-law PDP oracle for **every** frozen target. Every reported solver model must satisfy the canonical equations *and* group-law witness check. A SAT answer without a valid lift is a spurious algebraic root; an absent model with a budget/cap is unknown, not UNSAT. Use only certified negatives as UNSAT labels.

## Bounded next experiment (new PR, no measurement in this audit)

After the rotated producer and independent point oracle are frozen, pick the smallest eligible curve for each of m=5 and m=6 where the oracle can exhaust the chosen factor base. Freeze **four planted and four oracle-certified negative point targets per arity**, with no target selection after seeing solver output. If an arity's chosen rung has fewer than four certified negatives because its projected support is nearly saturated (as may occur for n=13, m=6), use the next predeclared eligible small curve; if none fits the oracle/caps, mark that negative arm censored and make no refutation ranking for it. Freeze this fallback sequence in the producer protocol before any solver outcome. This is an admission pilot (16 systems total), not a speed fit. Freeze one direct S6/S7 corpus and, only if exact equivalence passes, one recursive-chain encoding of those same targets. Give every admitted arm 15 seconds and 2 GiB per target, one thread, one cold process, identical host and target order; rotate solver order across two repetitions. Store all attempts, including capacity refusals, nonzero exits, wrong models and timeouts. The 15-second/2-GiB values are pilot caps to keep the first result bounded, not a claim they are adequate for any solver.

For each arm report preflight eligibility, complete/first-solution semantics, verified SAT, certified UNSAT, unknown, false or unliftable models, setup/export/solver/verification CPU and wall, peak child RSS, native counters with precise scope, and raw proof/model files when supported. Compare the SAT-positive time-to-first-valid-witness and the negative full-refutation workload separately; report paired per-target ratios only where both arms finish the same task. The first gate is **zero semantic discrepancies and at least one complete admitted arm per encoding/arity**. If that fails, repair encoding or capacity before expanding. If it passes, preregister a larger held-out panel with target count and caps chosen from the pilot; any later full-DLP claim needs all attack phases and matched same-Q batched rho under AGENTS.md. A later "easier PDP" predictor is a separate held-out experiment: only instance-derived features that vary within the subgroup, with feature-computation cost and skipped-target bias charged, can be considered. Trace, cofactor class and Frobenius-orbit size do not by themselves classify the nonzero H targets in the existing rotated n=13 preflight.
