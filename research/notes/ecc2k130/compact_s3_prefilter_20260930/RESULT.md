# Blocked S3 root prefilter: complete-process engineering gain, rho still ahead

The preregistered 512-bit blocked Bloom filter inserts every canonical root key and uses three deterministic positions in one 64-byte block. A negative skips only the exact root-table lookup; a possible positive still takes the original path. The same W64 compact-orbit binary runs with `KIC_S3_PREFILTER=off` or `blocked`. Its base, full-rank policy, S3 candidate order, full-point lift, first witness, scalar recovery, and group verification are unchanged. This tests one implementation lever at n41/K255 and n53/K440, each with 1,024 new point-only public targets. It is not a native m≥3 PDP, isogeny, or ECC2K-130 attack result.

The [protocol](PROTOCOL.md) was committed before code or evaluation points. Candidate source and decisions were locked before seed 623051 generated the two disjoint held-out target files; [FROZEN.json](FROZEN.json) pins point and verifier-only label SHA-256, curve, subgroup, generator, source hashes, K, and five block orders. The points were independently checked as `[d]G=Q` and disjoint from 6,147 previously published points at each size. [CI_MATERIALIZATION_AMENDMENT.md](CI_MATERIALIZATION_AMENDMENT.md) records three premeasurement workflow failures and fixes; none produced timing data. No candidate, input, or decision-rule change occurred after target freeze. The Linux action checked out the exact PR head rather than a moving synthetic merge.

Each cold child charges basis self-test, index/filter construction, rank, linear algebra, all target recovery, and group checks under a 900-second / 5-GiB limit. `off_a`, `filter`, `off_b`, and 32-walk normal-basis signed-Frobenius `rho_normal` share the same public Q in each of five position-rotated blocks. The off-B/off-A 95% paired log-ratio interval must include one and its median must lie in [0.9,1.1], and the reserved-core monitor must record no contention, before a timing preference is eligible. Each block reuses the same Q, so intervals measure host/run variation rather than target-distribution uncertainty. Absolute seconds across n41 and n53 hosts are not directly comparable.

The prespecified filter/off intervals are wholly below one at both sizes: 14.7% and 10.8% less complete cold CPU relative to the paired off geometric mean. These are **engineering wins at the two frozen K/Q cells**. The filter/rho intervals are wholly above one; the filtered processes still need a further 24.7% and 32.1% of their measured CPU removed to reach parity on these hosts. There is no timing crossover and no disjoint-Q confirmation trigger. The first run's ineligible ratios remain in the preceding table; the repeat is the single prespecified fresh-host timing adjudication, not an adaptive selection of a new target corpus.

The query-count mechanism is unchanged in the repeat because code and Q are identical. The n41 filter rejects 3,154,054 of 3,187,358 rank-plus-target root keys before the exact table, leaving 32,025 false positives and K+L=1,279 true hits. At n53 it rejects 27,985,237 of 28,244,062 keys, leaving 257,361 false positives and K+L=1,464 true hits. The n53 rank and target phases still execute 14,169,152 S3 calls and 42,507,456 counted batch multiplications. On the eligible repeat, median n53 index construction rises from 2.341 s (off A) to 2.420 s (filter), while rank falls from 2.625 to 2.288 s and targets from 5.281 to 4.398 s. Eliminating almost all empty table visits improves the implementation; the large residual S3/candidate workload is the next cost component to profile rather than an inferred free speedup.

After these runs, main changed the curve constructor and isolation helper. The [postmeasurement integration note](CI_MATERIALIZATION_AMENDMENT.md) records the unrelated two-expression Rust 1.98 lint fix and the workflow's fail-closed materialization of the exact twenty frozen source files from committed snapshots. The measured candidate, Q, old source-lock hashes, and both reported timing samples remain unchanged; the new integration run checks replay portability and is not selected as another performance sample.

**Decision.** Keep the blocked filter as an optional, correctness-preserving W64 engineering improvement. Do not promote a method-level speedup or ECC2K-130 attack claim: a calibrated common all-phase operation unit `S=total_operations/sqrt(r)` remains unset, matched rho wins both complete CPU cells, and the K+L full-rank/recovery attempt floor is unchanged. There is no n83 confidence result, GF(2^131) transfer, or degree-263 descendant-native factor-base/PDP result.

The separate [degree-263 all-line transport decision](../dual_all_lines_20260930/DECISION.md) reports source endomorphism-order discriminant −7 and first descending-leaf conductor 263/discriminant −484183, with the rational endomorphism algebra unchanged. It proves rational forward/dual correctness, not favorable native PDP yield. The next high-arity gate is the independently reviewed, label-gated [m10 capacity PR #937](https://github.com/aburan28/crypto/pull/937). If that capacity gate passes, freeze a natural-target solver/yield study and then compare equal-useful-size original, native descendant, transported, and pullback PDP bases on held-out targets with rank and fully charged costs. More tuning of a filter that already skips about 99% of keys should not replace those algorithmic gates.
