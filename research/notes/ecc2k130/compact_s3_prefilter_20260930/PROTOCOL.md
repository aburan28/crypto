# Frozen question: can a no-false-negative root prefilter cut complete compact-orbit cost?

Status: design registered before candidate implementation or new evaluation-point generation. This follows the [batched S3 result](../compact_s3_batch_20260929/RESULT.md), whose lowest measured full-process W64 cells still cost 1.535× normal-basis rho at n41/K255 and 1.582× at n53/K440. In those cells, rank plus targets made 3.22 million and 27.63 million root-table lookups; most missed. The filter is an engineering hypothesis about the current binary S3 index, not a native m≥3 PDP or degree-263 descendant claim.

The falsifiable hypothesis is that a blocked Bloom filter over *every* inserted canonical root key will save more random root-table misses than it costs in construction, hash work, memory, and false positives, without changing any first full-point witness. The candidate uses 512-bit blocks, three positions per key from a fixed deterministic 64-bit mixing function, and a power-of-two number of blocks sized for at least 12 bits per expected root-table entry. A filter-negative key skips the root-table lookup; every possible positive still visits the original table. No deletions or approximate-success decisions are permitted. The default-off and on modes must use the same compiled source and W64 S3 batch window. The existing root table, factor base, state quotient, ordered candidate generation, full-point lift, rank policy, linear solve, scalar recovery and group checks stay unchanged.

Before new Q are generated, test that the filter contains every inserted key and has no false negatives over exhaustive n5 S3 roots plus deterministic absent-key controls; compare the off/on complete rank trace, base logs, target witnesses and recovered scalars on the already published n41/n53 development Q. Count expected entries, allocated filter bytes, keys checked, definite negatives, actual table probes, false positives, true positives, and all existing S3/inversion counts by phase. The filter does not affect the K rank-attempt plus L target-recovery counting floor; the matched boundary is 32-walk normal-basis signed-Frobenius rho on identical public Q. Complete cold CPU is the host-specific decision metric. A calibrated, common all-phase operation unit `S=total_operations/sqrt(r)` is still absent and must remain unset; even a timing win cannot establish an algorithmic ECDLP speedup.

After candidate source, runner, verifier and decision rules are committed, generate disjoint point-only 1,024-Q evaluation sets at n41 and n53 using seed **623051**, with scalar labels in separate verifier-only files. Check `[d]G=Q` independently, distinctness within each set, and disjointness from prior point-only, strong-rho, K-sweep, swap-quotient and S3-batch sets. Freeze source and input SHA-256, curve, subgroup, generator, corpus, K and seed before evaluation. Use n41 K255 and n53 K440, the previously observed W64 minima; there is no evaluation-target K tuning. The evaluation arms are `off_a`, `filter`, `off_b`, and `rho_normal`, five fresh cold blocks with cyclic order rotations (the first four blocks are position-balanced). Each child is capped at 900 seconds and 5 GiB, with one thread and the same public Q file; the Linux harness reserves and pins one CPU. Archive commands, binary/source/input hashes, host and contention record, exits, timeouts, stderr, full stdout, base/rank/target traces, CPU user+system, wall and RSS for failures as well as successes. An independent verifier replays every base/rank/target logarithm and rho recovery; a producer success flag alone is insufficient.

The one-table report gives each arm's complete cold CPU, wall, RSS, verified logs, filter bytes/counts, and paired CPU ratios to the geometric mean of the two off controls and to rho. Compute a two-sided 95% t interval on five blockwise log ratios; the off-A/off-B interval must include 1 and its median lie in [0.90,1.10] for a timing preference. A complete-process engineering improvement at a size requires the filter/off interval entirely below 1 with all 5×1,024 outputs independently correct. A timing crossover requires the filter/rho interval entirely below 1 at both sizes, followed by confirmation on a second disjoint Q corpus; a method-level claim additionally requires a complete calibrated operation unit and the m83 confidence gate. If the filter fails correctness, stop and fix it before any timing interpretation; if both cells have filter/off intervals touching or above 1, reject this filter policy. If it helps but remains above rho, retain it only as an engineering candidate and report the remaining measured gap. Missing/censored runs are retained, never silently dropped. No n83, GF(2^131), native-PDP, or descended-factor-base transfer follows from these two cells.
