# Frozen protocol: n19 four-base joint rank and point-only archive oracle

Status: preregistered before any joint-rank, recovered-scalar, or holdout-support outcome. This follows the exact five-base support census in [PR #775](https://github.com/aburan28/crypto/pull/775), which selected the fixed-order four-base candidate `[3,338435,303097,464276]`. The comparison arm is beta `3` alone. Both use the same `E: y²+xy=x³+1` over `GF(2^19)` with polynomial `x^19+x^5+x²+x+1`, subgroup order `q=130873`, generator `H=(385982,301867)`, six rotated two-dimensional summand spaces, and the same target stream. No base may be replaced after outcome.

## Question and frozen split

Does the selected portfolio supply a full-rank *joint* set of formal factor-base logs, and does the resulting archive-witness oracle recover more new, natural point-only holdouts than beta `3` alone? Generate a single order of every nonzero `k in [1,q)` sorted by `(SHA256("ECC2K130-ROTATED-JOINT-RANK-20260925-v1/k"),k)`. The first 256 scalars are training Q, the next 64 are held-out Q. Do **not** condition this order on support. Commit the full selected ordering, a point-only file containing only opaque case IDs and Q coordinates, and a separate sealed-label file. No held-out Q may be a training Q. The constructor uses group arithmetic only and must not read support, row, rank, or log outcomes. Freeze all code, literal inputs, archive and source hashes, and a draft PR before measuring.

For each beta and selected training Q, use the first complete projected-histogram witness for `[4]Q` from the independently verified #767/#769 archives, if present. A missing witness is a counted training miss, never a fabricated row. The first-witness rule is fixed by each archive's recorded order and `witness_indices`; do not select a favorable torsion coset or decomposition. Train beta `3` on its rows alone and the four-base arm on the union of its four sets of rows, using the **same** 256 Qs. Every held-out Q is excluded from every training row in every arm. Scan and charge all four archived histograms, including misses; the prior complete `7^6` tuple censuses are prerequisites outside this stage receipt.

## Signed columns and exact rank

For a source factor point `P_i` in slot `i`, let `B_i=τ^(−i)P_i`, `R_i=[4]B_i`, and let `C_i=min(R_i,−R_i)` by integer coordinate tuple. If `R_i=O`, the term is zero; otherwise `s_i=+1` when `C_i=R_i` and `−1` otherwise. With the n19 Frobenius eigenvalue `λ=41811 mod q`, the term coefficient is `s_i λ^i mod q`. Aggregate coefficients of equal `C_i` modulo q, including *across betas* in one global column dictionary. The archived first witness has `ΣP_i=Q+T` for a 4-torsion point T and must satisfy `Σ coeff(C) C = [4]Q`. The row RHS is `4k mod q` for training `Q=[k]H`. The column universe is all nonzero canonical signed `[4]F0` points from all four frozen bases, not merely columns observed in the selected rows. Report each base's three possible nonzero signed columns, global unique count, cross-base overlaps, per-arm rank, nullity, first full-rank training row, zero rows, dependent rows, training misses and inconsistent rows. Rows are processed in fixed `(SHA training position, beta order)` for the joint arm and SHA position for beta `3`; eliminate modulo prime q using leftmost pivots. Keep every dependent and zero row in accounting. A deficient rank yields no unique log vector and forbids point recovery for that arm. With full rank, solve and check every training equation and every column point by independent group law.

For holdouts, build a cold **archive oracle** keyed by `[4]Q` coordinate, returning the first available beta in frozen order and that base's first saved witness converted to signed row coefficients. Make separate beta-3 and joint responses, including misses. The point-only recovery child receives only the point-only targets, solved column logs, and stripped oracle responses: no k, witness indices, source target index, or sealed label. It evaluates `k̂=4^(−1)Σ coeff(C) log_H(C) mod q`, then checks `[k̂]H=Q` by group law before the sealed labels are opened. Record all 64 target outcomes for both arms, including oracle misses, rank-deficient skips, failed point checks, and label mismatches. Source/argument isolation is audited; it is not OS filesystem confinement.

## Independent replay, bounds, decision

The independent verifier rederives the SHA split and all Q points with #767's bit-serial/Fermat field and group law. It reconstructs source factor points, canonical signed columns and every selected first-witness row from the pinned archives; checks each witness sum, torsion removal, and row group identity; independently computes exact modular rank/solution; verifies all training equations and column point logs; rebuilds both oracle responses from source rows; and checks every recovered scalar against its Q before comparing sealed k. Full prior archive re-enumeration is not repeated, because #767/#769 already independently replayed all `7^6` tuples per base. No output from the producer is trusted by the verifier merely because its JSON parses.

Run input construction under 60 s / 512 MiB; producer, oracle and point-only recovery children each under 120 s / 512 MiB; independent replay under 300 s / 512 MiB. Record child UTC start/end, wall/CPU, high-water RSS, stdout/stderr, exit/censor status, archive bytes scanned, field/curve and modular operation counters, frozen hashes, result hashes and a compact raw archive. Preserve failures and cap violations; a failed replay leaves the decision unknown. CI checks the frozen protocol/input/source hashes before outcome, then requires and replays the archived result.

The bounded **semantic follow-up gate** passes only if the joint arm has full formal column rank, every row and recovered point passes independent checks, and the joint arm verifies at least 12 more of the 64 natural holdouts than beta `3`. Otherwise it fails or is censored, without changing seeds or bases. Passing admits an eventual *charged implicit-PDP solver* experiment; it does not establish solver runtime, negative-PDP proof cost, relation acquisition, a whole-DLP speedup, n131 support, or an ECC2K-130 challenge logarithm. No end-to-end IC/rho `S` or speed ratio is computed from this archive-oracle stage.
