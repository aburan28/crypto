# Frozen whole-process instruction ledger for compact-orbit logarithms

Status: preregistered design; no Callgrind result has been inspected or selected. This is an accounting experiment on already published point-only Q, not a new target-distribution holdout, native PDP, isogeny, or ECC2K-130 challenge attack.

## Question and boundary

Measure the complete work of the current W64 compact-orbit S3 producer and the 32-walk normal-basis signed-Frobenius batched rho reference on identical public Q. The producer already has correct full-rank logarithms and a cold CPU panel, but its S3/field counters and rho charges cannot be added in one unit. Follow the repository's `scripts/ic_e2e_instructions.py` precedent: run each **entire process** under Valgrind Callgrind on one Linux x86-64 host, with `RAYON_NUM_THREADS=1`, and count guest instructions `Ir` from the Callgrind `summary`/`totals` record. This includes process startup, field and group arithmetic, basis self-test, factor-base/index setup, rank search, linear algebra, all target recoveries and checks, allocations, hashing, and emitted audit traces. Callgrind wall time is not a cost metric.

For each arm, report `S_Ir = Ir / (L sqrt(r))`, complete `Ir`, and `Ir_IC / Ir_rho` on the **same n, L, Q**. `Ir` is a common all-phase work unit; it is not a field multiplication or group addition. A generic-group floor ratio and a group-addition-equivalent S remain unset until an independently frozen conversion is measured. Do not compare raw `S_Ir` across field degrees as if an instruction had degree-independent group-operation cost. Cold native CPU/wall/RSS from the earlier matched panel remain secondary diagnostics, not Callgrind timings.

The counting floor for this full-rank route is K independent base-log equations plus L target decompositions; count actual attempts and report `(rank_attempts + L)/(K + L)`. This is an attempt floor, not an instruction lower bound. The matched reference is the strongest measured normal-basis rho v3 on exactly the same Q. A fully charged method crossover would need both an instruction ratio below one and a separately eligible cold native CPU ratio below one on a disjoint confirmation corpus, every log correct, no omitted setup, and explicit n=131 transfer assumptions. This panel alone cannot establish that result.

## Frozen cells and execution

`CONFIG.json` fixes all six n/L cells before any Callgrind count: n37, n41, n53 at L=1 and L=1024. Single-target K is 7/85/220 from the earlier disjoint tuning panel; batch K is 42/255/440 from its batch selection. n37 and every L=1 cell run `off` versus rho; n41 and n53 L=1024 run `off`, `blocked`, and rho so the instruction ledger covers the prefilter decision. Use `KIC_S3_BATCH_WINDOW=64` and rank seed 7 for every compact arm; `KIC_RHO_DP_BITS=4`, 32 walks, normal-basis canonicalization, signed Frobenius, each cell's frozen corpus/seed and its public-point JSONL for rho. The code, curve, subgroup, inputs, K, and mode may not be tuned after counts are seen.

Build the **exact twenty-file source** pinned by the merged blocked-prefilter `FROZEN.json` from its fail-closed committed snapshots, using the pinned `Cargo.lock`; verify the materializer receipt and all source hashes before compiling. The n37/n41/n53 L=1 and n37 L=1024 public Q and verifier-only labels come from the older point-panel freeze. The n41/n53 L=1024 Q and labels come from the blocked-prefilter freeze. `CONFIG.json` pins both freeze hashes and each actual points/label SHA-256. The producer only receives points; labels are withheld for independent replay.

Run one cold Callgrind process per arm; n37/L1 repeats **both** its `off` and rho arms once as a deterministic-count control, with an allowed relative Ir difference of at most 0.1% for each arm. Process timeout is 45 minutes per arm and the per-cell job limit is 120 minutes; cap RSS at 8 GiB. The order within a cell is compact `off`, compact `blocked` when present, then rho, followed by the two n37/L1 controls. All arms receive the same Q. No result is selected from a repeat and no incomplete arm can be extrapolated. If a child exits nonzero, times out, exceeds the cap, or Valgrind cannot decode the binary, preserve the failure and leave that cell's ratio null. A deterministic-control failure leaves all instruction ratios provisional.

Capture exact commands, environment, binary and input hashes, host and Valgrind version, exit codes, Callgrind file SHA-256 and `Ir`, full stdout/stderr, rank/base/target traces, and native subgroup/rank/target counts. Independently replay each compact full-rank trace and every recovered point log against the verifier-only labels; independently check every rho scalar as `[d]G=Q`. Compare the `off` and `blocked` arms' base, rank, first witnesses and recovered scalars on every shared Q. A producer success flag or an `Ir` total alone is not a correctness receipt.

## Decision and stop rules

Give one table with all arm rows, n/L/K, L correct of L, complete `Ir`, `S_Ir`, same-Q `Ir_IC/Ir_rho`, native cold CPU context, RSS, and attempt-floor ratio. Report each phase's available native counters separately without adding incompatible units. Classify an instruction reduction with unchanged attempt floor as accounting/engineering; classify no method advance unless the full separate crossover gates above pass. Retain all failures and raw traces in a content-addressed archive or committed deterministic compressed parts with an extraction command and SHA-256 manifest; do not use a local path or expiring CI artifact as the sole evidence. Update `docs/index-calculus-scoreboard.html` and `docs/ic/BOUNDARY_TARGETS.md` with the result or censored status in the outcome PR.

Do not run the next m10 capacity experiment from this work: PR #937 still requires independent non-author approval and its exact dispatch label. An Ir result on these small binary fields says nothing by itself about descendant-native m≥3 PDP yield or GF(2^131).
