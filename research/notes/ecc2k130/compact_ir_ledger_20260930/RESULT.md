# Complete instruction work: batched compact IC uses fewer Ir but still loses eligible cold CPU

The [preregistered protocol](PROTOCOL.md) was committed before the first Callgrind count. [Hosted run 36685674084](https://github.com/aburan28/crypto/actions/runs/36685674084) checked out merged main `ee2364968ae42a59db30e7cd10069dc73de1c29e`, materialized the exact twenty-file blocked-prefilter source freeze, and built its pinned release compact and rho v3 binaries. The six cells use the frozen public-point Q lists and K values in [`CONFIG.json`](CONFIG.json), with verifier-only scalar labels withheld from both programs. Each arm is a fresh entire process under Valgrind 3.22.0 Callgrind, one Rayon thread, with process startup, index construction, full rank, linear algebra, target recovery, checks and audit output charged in guest instructions `Ir`. The six matrix cells ran on separate Linux x86-64 runners; all arms **within a cell** shared one runner, Q list and both byte-identical binaries across the matrix. No cross-cell hardware normalization or degree-scaling fit is made.

All 16 children exited successfully. The hosted verifier and a separate macOS replay each checked nine compact full-rank traces and **8,200 point logarithms** (5,124 compact, 3,076 rho, including the n37/L1 controls), replaying every relation and recovered scalar against the independently checked labels. Both replays returned the same receipts. Every compact rank took exactly K attempts, so `(rank_attempts + L)/(K + L) = 1.000`; that is an attempt-count floor, not an instruction lower bound. The repeated n37/L1 off and rho Ir totals differed by 0.00357% and 0.0000724%, both below the frozen 0.1% deterministic-count gate.

The native CPU column is context, **not a conversion from Ir to seconds**. Its two n41/n53 batch pairs are eligible same-source, same-Q W64/blocked/rho v3 cold data from the [blocked-prefilter repeat](../compact_s3_prefilter_20260930/RESULT.md): blocked/rho 1.3282 (95% paired interval 1.2980–1.3556) and 1.4727 (1.4231–1.5292), with both A/A and isolation gates passing. The four single/n37 figures come from the [older point panel](../compact_orbit_point_panel_20260929/RESULT.md), whose corrected but weaker rho v2/source snapshot differs from this run. They are historical context only; [PR #1053](https://github.com/aburan28/crypto/pull/1053) preregistered a four-cell current-source cold panel before any Callgrind result was inspected and will adjudicate those missing CPU cells. Callgrind RSS includes instrumentation and is not native peak RSS or a memory-capacity projection.

The batch instruction result and native timing point in different directions. At n41/n53 L=1,024 the off arms consume 0.6221/0.7773 times rho's guest instructions, yet eligible complete cold CPU is 1.5711/1.6442 times rho. The blocked filter **adds** 2.10%/1.49% guest instructions relative to off while the separate eligible native repeat **saves** 14.7%/10.8% complete CPU. Ir is a useful common all-phase accounting unit, but one guest instruction is not one cycle, field multiplication, or group addition. The current data do not isolate which cache, branch or microarchitectural effect produces that gap; no such cause is claimed. The filter does not change witnesses, rank attempts, or scalars.

The [analysis JSON](ANALYSIS.json) recomputes the 14 primary arm rows from independently hashed raw `run.json` data; it leaves the method crossover null. The [durable evidence manifest](evidence/run_36685674084/MANIFEST.json) has SHA-256 for all six deterministic tarballs, every archived member, hosted and second-host receipts, and the replay host manifest. Two independent packings produced all 20 files byte-identically; the manifest SHA-256 is `ac124a37a3cfb2805944d437234d07e190c11b3e91bedcf89190b421f8099ae3`. **Decision.** The current W64 compact batch route has no end-to-end crossover at n41/n53 against the strongest measured matched rho: both eligible cold CPU ratios remain above one even where complete Ir ratios are below one. The four cells this note left pending were later measured once by the frozen current-source panel in [the cold-gap result](../compact_ir_cold_gap_20260930/RESULT.md): n37/L1 3.7362, n37/L1024 1.7064, n41/L1 17.0499 and n53/L1 27.4483 complete CPU over the same-Q rho, all with A/A and isolation gates passing and every interval above one. That later panel adjudicates those CPU cells. It does not create a method crossover, and the instruction counts in this note are unchanged. The K+L attempt floor is unchanged. There is no calibrated group-addition-equivalent S, disjoint-Q confirmation, n83 wider-backend result, GF(2^131) transfer assumption set, or descendant-native m≥3 PDP yield. The separate [degree-263 all-line certificate](../dual_all_lines_20260930/DECISION.md) proves transport and the descending order change but not an easier PDP. The high-arity native comparison still depends on the independently reviewed, label-gated [m10 capacity PR #937](https://github.com/aburan28/crypto/pull/937); it is not dispatched from this result.
