# Frozen design: charge and batch S3 inversions in the compact-orbit DLP

Status: preregistered design before implementation, new evaluation Q generation, or held-out timing. Parent: merged [swap/Frobenius quotient PR #947](../compact_swap_quotient_20260929/RESULT.md), whose evaluated source and fixtures are immutable. Its best observed n41/n53 L=1,024 quotient arms remain 2.119/2.562 times matched normal-basis batched rho in cold CPU; both corresponding 95% paired intervals lie above one. This experiment asks whether removing *serial field inversions in both construction and extraction* changes that complete-process ratio. It is not a descendant-native PDP test.

The boundary is the 32-walk signed-Frobenius normal-basis rho in `koblitz_rho_batch_ks_v3`, solving the same new public Q on the same host, plus the unavoidable K rank attempts and L target recoveries. The #947 rank attempts already equal K, so batching cannot improve the K+L attempt-count floor. Count the complete cold process from executable startup through base construction, normal-basis self-test, index, rank, linear solve, all targets and group checks. The headline is paired user+system CPU seconds against both a same-binary scalar-inversion control and rho. CPU is a host-specific engineering diagnostic: common calibrated `S=all operations/sqrt(r)`, its generic-group-floor ratio and an algorithmic attack-speed claim remain unset until a separate operation ledger exists.

## Frozen candidate and semantic obligation

Copy the #947 swap-quotient producer into a separately named experimental example. Keep the curve, signed-orbit factor base, state involution, root table, rank policy, public-point query origin, target ordering, full-point lift, scalar solution and output contract unchanged. A runtime window chooses scalar `W=1` or Montgomery batch inversion `W=16,64`; the same compiled binary serves all three. The baseline source SHA-256 at main `3a4e9859eea2505348efd85ce729304989291711` is `b008bfbdbc008ac8919af1160da6c3cd2cf414250beb7f01ec7bb58de4eed608`. The rho source SHA-256 is `98b6e8a27d821ebfc7ae716410184dffe89aadf27dfe36bcac8ce834c39cf04c`.

For nonzero regular S3 denominators `d_i=a_i p_i^2`, a window computes prefix products, one Itoh–Tsujii inverse of the product, then each `d_i^{-1}` in reverse. The polynomial-basis field multiplication and the existing normal-basis inversion routine must be identical to the scalar arm; do not silently switch to `Gf2::inv`. Exceptional `a=0` or `p^2=0` inputs must take the original fallback and never enter the nonzero product. Root results must be returned in the original candidate order. During target extraction, compute a full fixed-width window, then consume candidates in the *same* order and stop at the first accepted full-point lift. All prefetched but unconsumed work is charged to that target; no successful relation may be moved earlier by batching. The last partial window also pays its actual work.

The candidate must count by index, rank and target phase: solver candidates prepared; regular and exceptional calls; trace-negative returns; root pairs; scalar or batch inversion calls; nonzero denominators; Montgomery prefix/reverse multiplications; consumed and discarded prefetched candidates; root-table lookups/probes; full-point lift attempts. Counts are diagnostics alongside total CPU/wall/RSS, never replacements for them. Instrument `W=1` with the same counters. Preserve zero/equal-x/fallback tests; add an exhaustive GF(2^5) test comparing scalar and both batch windows for every x pair, plus a target-order test with an early accepted candidate and a final partial window. On #947's published Q, which are development-only here, require same base hash, states, canonical root keys, rank transitions, every recovered scalar and group check. Timing on those Q is exploratory and cannot enter the held-out claim.

## New evaluation freeze, arms and caps

After the candidate, runner, independent verifier, source hashes and acceptance rule are committed, generate two fresh point-only L=1,024 corpora with seed **622935**, labelled `compact-s3-batch-n41-L1024-eval-20260929-v1` and `compact-s3-batch-n53-L1024-eval-20260929-v1`. Keep scalar labels in separate verifier-only files. Independently check `[d]G=Q`, 1,024 distinct points per n and zero overlap with the prior point, strong-rho, K-sweep and swap-quotient panels. Freeze exact source/input SHA-256 before hosted evaluation.

At n41 test K=192 and K=255; at n53 test K=440 and K=550. These are prior observed controls and minima, selected before the new Q. Per K run `scalar_a`, `batch16`, `batch64`, `scalar_b`, plus one rho arm: **nine arms**. The two scalar names call the same binary with `W=1` and provide an A/A noise control. Execute nine cyclic Latin blocks so every arm occupies each position once, as a fresh process with the same new public Q file. Each compact process must reach rank K and recover all 1,024 scalars; rho must recover the same Q. Cap every child at 900 wall seconds and 5 GiB address space; each hosted matrix cell at 90 minutes. Archive every command, source/binary/host hash, exit, timeout, stderr/stdout, base/rank/target trace, CPU, wall and RSS, including failures. The independent verifier must replay all base logs, rank transitions, four-sum witnesses and recovered scalars, and rho outputs, without accepting a producer's status field as proof.

Report one nine-arm table per n in complete cold CPU seconds, wall, RSS, verified outputs, paired candidate/scalar and candidate/rho CPU ratios with 95% log-ratio t intervals, A/A ratio, phase times and all counters. An A/A median outside 0.90–1.10 or 95% interval excluding 1 invalidates a timing-gain claim, but its raw results remain archived. A window improvement requires the upper endpoint of its paired CPU interval below 1 against scalar at the same K. A timing crossover requires its paired interval below 1 against rho on both n values and a further disjoint Q confirmation; an *algorithmic* crossover additionally requires a calibrated common all-phase operation unit S. If all complete windows lose to rho, report a no-go only for these K/window cells on these Q. If any arm fails, times out or lacks independent replay, leave that cell censored rather than dropping it. Do not infer n83, GF(2^131), degree-263 descendant or native-PDP transfer from this panel.

The next exact-curve gate remains [the held native m>=3 protocol](../../../ecc2k130_leaf_native_m3_gate_20260926/PROTOCOL.md). Its implicit full-point producer and capacity admission are separate requirements; this S3 engineering test cannot satisfy them.
