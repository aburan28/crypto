# Frozen follow-up: batched-inversion and normal-basis rho versus compact orbit

Status: preregistered before the new evaluation corpus and hosted measurements. The previously merged [point-only panel](../compact_orbit_point_panel_20260929/RESULT.md) is the development control; none of its Q are used as the evaluation corpus here.

The n41 and n53 L=1,024 cold compact-orbit process beat the earlier signed-Frobenius batched rho in CPU time, but the comparator added one walk point at a time and enumerated the entire Frobenius orbit by field squaring. At n53/L=1,024 it charged 20,134,104 direct additions and 3,104 scalar multiplications. Since each scalar has at most 45 bits, even counting two affine operations per bit gives at most 279,360 further additions, under 1.4% of that sum. Precomputed scalar starts cannot remove the dominant walk cost. At n41 the analogous upper bound is 248,320 versus 3,628,240 direct additions, under 6.5%. These are operation-count bounds, not timing predictions.

The falsifiable operational hypothesis is that an automorphism-aware batched rho with 32 independent walks, one field inversion shared across active additions, and normal-basis rotation for signed-Frobenius canonicalization will erase the n41/n53 batch CPU lead on newly frozen public points. The original corrected rho, a 32-walk polynomial-basis x-first control, the 32-walk normal-basis candidate, and compact orbit will each run as a fresh cold process on exactly the same Q, five balanced blocks per n=37/41/53 and L=1/1,024. The same signed-Frobenius quotient, jump seed, 32 jumps, distinguished-point rule, public-point input, field polynomial, subgroup and generator apply to both rho versions. The new rho's different walk schedule and normal-basis representative can change walk counts; no bit-identical walk or equal-work claim is permitted. Both new modes use the same table-reduced `Gf2` field as compact orbit. The normal-basis construction, jump table, target starts, walk table, verifications and output remain inside each timed process. No scalar label is passed to any measured arm.

The disjoint evaluation corpora are `strong-rho-n{n}-L{L}-eval-20260929-v1` at seed 622901. A deterministic fixture generator publishes [d]G as Q into a separate point-only JSONL; scalar labels are kept only for the independent verifier. L=1 uses one distinct Q repeated across five cold blocks; L=1,024 uses 1,024 distinct Q repeated across five blocks. These same-target intervals measure runner noise rather than target-distribution uncertainty. Compact K is fixed from the disjoint earlier tune: n37 K=7/42, n41 K=85/255, n53 K=220/440 for L=1/1,024. No evaluation-target retuning is allowed. DP bits remain 4; rho seed and jump count remain 531310 and 32. The exact generator, point-file hashes, source hashes, toolchain and limits are in `FROZEN.json` and the run host records.

Each arm gets a 900-second, 5-GiB process limit; the hosted job gets 90 minutes. Every exit, timeout, stderr, full stdout, rank/base/target trace, CPU user+system, wall, RSS, host model and flags is retained, including failures. The independent verifier rechecks every fixture [d]G=Q, every rho recovered scalar, each IC rank transition, base log and target four-sum. A failed or incomplete arm invalidates its cell; it is archived, never omitted. A separate n13 regression tests the exceptional group-law cases, normal-basis forward/inverse transforms, Frobenius equivalence, orbit coefficient preservation and point-only input.

The IC counting floor is K independent base-log equations plus L target decompositions, reported as `(rank attempts + target attempts)/(K+L)` with probe counts separately; it is not an operation lower bound. The reference boundary is the strongest *verified same-Q* rho arm. Report a single table with all four arms, cold CPU/wall/RSS, successes, rho walks, IC probes, ratios to the strongest rho and the exact operation ledger available. A 95% paired log-ratio interval from five blocks must exclude 1 for a timing preference. Before interpreting an attack-speed crossover, a common fully charged operation unit `S=all operations/sqrt(r)` must cover both IC and rho, including normal-basis setup, field operations, table work, rank, LA and verification. Current producers do not yet provide that complete common unit, so S and an algorithmic speedup remain unset here even if wall or CPU crosses. n83 and GF(2^131) transfer remain unproved. If the stronger rho wins n41/n53 batches, the earlier timing lead is an engineering/comparator result; if IC still wins, the common-unit and larger-n gates remain mandatory before promotion.
