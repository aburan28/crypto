# Frozen K/base-size gate after the stronger rho result

Status: design frozen before generation of the new evaluation points and before any new evaluation run. The development-only feasibility check uses the already published Q from PR #943; those Q are excluded from this evaluation. The merged [strong-rho result](../compact_orbit_strong_rho_20260929/RESULT.md) is the operational control: at n41/n53 and L=1,024, the current compact S3 index build alone exceeds the whole normal-basis rho process.

**Hypothesis.** Reducing compact-orbit K lowers the eager S3 index's K²·n construction cost enough to improve cold full-rank logarithm recovery, but increases rank and target probes. There may be a held-out K with less complete CPU cost than the previously selected K=255/440. Whether any K beats the strongest matched rho is a separate, stricter gate. This experiment changes K, not the S3 index algorithm, and does not infer an untested index policy.

The fixed K grids are n41: 128, 192, 255, 320 and n53: 220, 330, 440, 550. The old selected K remains an explicit control. Every K builds its own factor base and complete index in a fresh process; no base or relation work is reused between arms. All four K policies must reach full rank and recover all 1,024 logs, or their failures remain in the cell. The matched reference is PR #943's 32-walk, batched-inversion, normal-basis signed-Frobenius rho with the same public Q, generator, subgroup, seed, jump count and distinguished-point rule. Each child includes setup, the index or walks, rank and target work as applicable, verification and output. The normal-rho process is repeated within every balanced block on the same host; no cross-host timing ratio is permitted.

Generate a **new** public-point corpus with `prepare.py` using v2's deterministic point generator at seed 622933: `compact-k-n41-L1024-eval-20260929-v1` and `compact-k-n53-L1024-eval-20260929-v1`. Each has 1,024 distinct Q. Keep fixture scalar labels in a separate file used only by the independent verifier. Freeze both file hashes, curve parameters, source hashes, K grid, five blocks and five-arm Latin rotation in `FROZEN.json` before evaluation. Each of the five blocks runs all four K arms and the normal rho once; rotate arm order by one position per block so each occupies each position exactly once. The same Q file repeats across blocks. These five paired ratios quantify runner variation on one corpus, not target-distribution variation.

Each arm has a 900-second and 5-GiB address-space cap; each n matrix job has a 90-minute cap. Retain every exit, timeout, stderr, full stdout, base/rank/target trace, user+system CPU, wall, RSS, host model and binary/source hash, including failures. The independent verifier recomputes `[d]G=Q` for every fixture, modular rank transitions and base logs, every compact four-sum and recovered scalar, and every rho recovered scalar from point-only input. A missing, failed or censored arm invalidates a complete-result claim, not merely that arm's denominator.

Report all four K rows and rho in **one table** per n, with complete cold CPU/wall/RSS, index build, rank and target phases, rank/target probes, misses, full-rank and scalar-verification counts, and paired CPU ratios with 95% log-ratio t intervals. The first decision is the complete-CPU K Pareto result, with memory included. A timing preference requires the paired interval to exclude 1. Selecting the minimum K from this evaluation is exploratory; any positive IC/rho timing crossover requires a fresh disjoint confirmation and a complete calibrated common operation unit `S=all operations/√r` before an algorithmic claim. If all admitted K lose to rho, this is a quantitative no-go for **this eager-index K grid on these Q**, not all index policies, descendants, n83 or GF(2^131). The next index-policy candidate must beat the measured index-build-plus-probe boundary at equal useful workload.
