# Cold public-point compact-orbit versus batched rho panel

Status: preregistered, before evaluation. This follows the merged independent rank-trace control in PR #938. It is a full-rank logarithm comparison, not a solver-stage test. The point-only rho input path is added here so neither measured process reads a planted scalar. Its old generated-fixture path stays available as a regression control.

The falsifiable hypothesis is that cold compact-orbit setup loses at L=1 but shared base logs can lower total process cost at L=1,024 on some of n=37/41/53. Historical scalar-input wall observations suggest the latter at n=41/53; those observations are tuning context, not evidence for this held-out point-only result. A contrary outcome, failed full rank, incomplete target recovery, or rho failure is retained. No operation-cost crossover is claimed from wall or user CPU alone.

All curves are E_0: y²+xy=x³+1 over GF(2^n), n=37,41,53, with the producer's exact polynomial basis, prime subgroup order, generator and signed Frobenius size recorded in the frozen fixture. These prime field degrees have no proper intermediate subfield over GF(2). ord_37(2)=36 and ord_53(2)=52 give irreducible nontrivial cyclotomic blocks, as ord_83(2)=82 and ord_131(2)=130 do; ord_41(2)=20 splits that block. None of n=37/41/53 settles ECC2K-130 scaling. The challenge itself is GF(2^131), and n=83 remains the required smaller-curve high-fidelity gate.

The frozen inputs are synthetic known-answer points generated separately by the deterministic rho fixture generator. The fixture JSONL and a separate point-only JSONL are committed with SHA-256 hashes in FROZEN.json. The two measured arms receive the exact same point-only file; neither command nor environment contains the scalar label path. The independent Python verifier alone reads the labels and checks [d]G=Q, every returned scalar, each compact target four-sum, x codes and pinned intermediates, every used factor-base label, every rank attempt and modular rank transition, and the final representative logs. A failed search remains in the rank trace. The replay does not prove that a reported miss had no decomposition.

The compact arm is a new process for every block: constructed orbit base, normal basis/self-test, index, rank search, linear algebra, target extraction and scalar checks are all inside the timed and memory-limited process. The optional rank trace and base dump are charged to its process. The signed-Frobenius Kuhn–Struik rho arm is also a new process, including jump setup, walks, table work, target checks and JSONL output. Public Q generation belongs to fixture preparation and is outside both DLP arms. Rho uses 32 jumps, distinguished-point bits d=4, seed 531310, and one table shared across a batch. IC uses rank seed 7. CPU user+system, monotonic wall, Linux peak RSS, load, exit, timeout, producer phases and rho counters are retained per process. A 180 s cap applies to each tuning candidate; a 900 s and 5 GiB address-space cap applies to each evaluation arm; GitHub job cap is 90 min. Failures and incomplete outputs remain in the archive.

For L=1, K is selected by the lowest median total process CPU among five verified completed runs per candidate on a *disjoint* one-point tuning corpus: n37 {7,14,28,42}, n41 {85,170,255,340}, n53 {220,440,660}. Candidates with a failed repetition cannot win. For L=1,024, fixed K={37:42,41:255,53:440} was chosen on the old disjoint 1,024-point tuning corpus described in the 2026-09-24 compact-orbit result. The new evaluation corpus is disjoint from both tuning corpora. Five paired cold blocks alternate IC/rho then rho/IC. The within-arm repeats show the A/A noise floor. K, output and all tuning misses are archived.

A counting floor for this exact linear-algebra route is K independent base-log equations plus L target decompositions. Rank attempts + target attempts divided by K+L is reported as an efficiency diagnostic; it is not an operation bound. The matched rho process is the reference for the same Q list. The required common unit is S=all charged operations/sqrt(r), with both S values and the attack-speed ratio left **null** here because the compact producer does not yet count its field operations in a unit calibrated against rho. The full-process wall and CPU ratios are secondary diagnostics only. A runtime improvement would require a paired 95% interval excluding 1 and a replication on another host; a transferable ECC2K-130 improvement additionally requires n=83 and explicit n=131 assumptions. The outcome PR must preserve source/input hashes, full-rank and target replay receipts, all arm failures, a single comparison table, and a decision that does not exceed this boundary.
