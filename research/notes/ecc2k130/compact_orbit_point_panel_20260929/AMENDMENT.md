# Preregistered comparator-backend amendment

Status: frozen before the corrected-backend run. The first hosted run used source head 0839f6905d76c857a5b94de925e75e9bbe1060b8, freeze SHA-256 b80b6a3fafc45ef4c5d2d9c873661b2662e84363fcb58724f523fe107ceaa8d2, and [Actions run 36554543689](https://github.com/aburan28/crypto/actions/runs/36554543689). It remains an immutable baseline. This amendment was prompted by inspecting source and the first n41/L=1,024 result: its rho walk count (~3.4 million) matched the historical work count, but its CPU time was about 3x larger. The rho example's x86 multiplication used a bit-serial carry-less loop and its inversion used square-and-multiply; the compact-orbit path uses runtime PCLMUL and an Itoh–Tsujii inversion chain. A wall ratio against those different arithmetic kernels cannot isolate the algorithmic advantage.

The corrected rho path adds runtime PCLMUL on x86 and uses the same Itoh–Tsujii addition-chain formula as the compact field. AArch64 keeps PMULL, with the inversion change; machines without the feature retain a portable product. The rho jump table, signed-Frobenius canonicalization, walk starts, distinguished-point predicate, collision equation, point-only input and published Q files are unchanged. The nine fixture and point-file SHA-256 pairs have been regenerated locally with the corrected source and match the original freeze byte for byte. The n13 point-only contract and 128 carry-less products plus 64 inversions at each of n13/37/41/53 pass against independent reference formulas locally.

Before looking at corrected timings, the decision rule is fixed: all six n/L IC/rho panels must still independently replay every rank and target relation; the corrected rho output must recover exactly the same frozen scalars. A same-runner rho backend A/B on n41/L=1,024 and n53/L=1 alternates the old source snapshot and corrected source five times on the identical point files. Every per-target Q, recovered scalar, walk count, table state and summary charge must match; otherwise the backend comparison is rejected. Only after identity holds may paired full-process wall and CPU ratios be called an engineering backend gain. CPU model, feature flags, core count, memory, compiler, binary hash and load are recorded for the new runs; the first run lacked CPU-model capture, so it is not by itself a matched-hardware performance A/B. The corrected arm's five IC/rho pairs are the reference for interpreting the compact-orbit route.

The fixed K choices, candidate grids, tuning/evaluation separation, 900 s/5 GiB evaluation cap, independent verifier and null operation-cost S are unchanged. The amended run adds an explicit one-thread setting. Rho still spends two scalar multiplications per target to create its walk starts; a precomputed-start rho control remains a separate next comparator. No ECC2K-130 attack-speed claim follows from either wall panel.
