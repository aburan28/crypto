# Cold point-only full-rank compact-orbit panel: measured boundary, not an attack-speed verdict

The frozen six-case experiment completed on Ubuntu 24.04 x86-64. Both arms received exactly the same public-point JSONL, with known-answer scalar files used only by the independent verifier. All 5/5 cold paired processes per case completed full rank or signed-Frobenius batched rho, all target logarithms matched the fixture labels, every compact rank attempt and target four-sum replayed, and all six downloaded archives independently replayed again on macOS. There were no rank search misses, target failures, process timeouts or OOMs. The n=37/41/53 fields have no proper intermediate subfields over GF(2). The n=41 nontrivial Frobenius module splits (ord_41(2)=20); n=37 and 53 have irreducible nontrivial blocks (orders 36 and 52).

The **corrected** rho reference uses runtime PCLMUL and Itoh–Tsujii inversion, matching the compact producer's field-kernel class. The first run's x86 software-product/square-and-multiply rho is retained as an accounting control, not the current reference. The intervals are log-ratio t intervals over five paired repeats on the **same corpus**. They measure runner noise, not target-to-target uncertainty; n37/L=1 wall is only ~11 ms per process and its wall interval [0.999, 1.009] straddles parity. CPU and wall are secondary diagnostics. The compact producer still lacks a complete counted operation vector in a unit calibrated against rho; thus all S values, full-operation speedups, ratios to the generic group floor and the selected `vs_rho` claim remain **unset**. This is a same-Q full-process wall/CPU result, not a measured algorithmic crossover or an ECC2K-130 key-recovery claim.

The comparator correction mattered. The first rho's n41/L=1,024 walk count was 3,399,415, essentially the historical 3,415,963, but CPU time was 25.72 s versus 8.29 s after the correction; the IC code and frozen Q list did not change. The same-runner backend A/B recompiled the first source snapshot and corrected source under one toolchain, then alternated them five times. At n41/L=1,024 corrected rho CPU was **0.3295** of baseline (95% interval 0.3283–0.3315); at n53/L=1 it was **0.2372** (0.2365–0.2381). Every Q, recovered scalar, walk count, collision/table state and reported algorithmic charge matched exactly. All nine fixture and point-file SHA-256 pairs stayed byte-identical across the inversion/product change. The first-run apparent compact batch ratios of 0.154/0.099/0.086 at n37/41/53 become 0.789/0.309/0.252 against the corrected reference. The cross-run ratio change itself is **not** a paired performance estimate because the first jobs did not record CPU models; the same-runner A/B is the controlled backend measurement.

The counting floor for this route is K independent base-log equations plus L target decompositions. Every selected compact run used exactly K rank attempts for K rank and solved every target, so its **attempt-count** ratio to that floor is 1.000. This does not mean one PDP probe per relation: at n53/L=1 the rank stage averaged ~85,007 probes per equation and consumed 5.814 of 7.436 in-process seconds; at n53/L=1,024 it averaged ~19,946 probes, with 6.313 s setup (6.220 s index), 3.207 s rank and 6.333 s targets of 15.854 s total. The n53 batch base has 46,640 useful points and ~1.28 GiB peak RSS, versus 23,320 points and ~328 MiB for the single target. The next IC lever is the K/base-size versus probe-cost/memory tradeoff and the cost of constructing the S3 index, not a claim of higher-than-floor relation yield.

The evidence-ranked next tests are:

1. **Strengthen rho before declaring a crossover.** The current v2 baseline still computes two start scalar multiplications per target (plus verification) despite sharing a jump table. Freeze a public-point precomputed-start variant, require identical Q/scalar answers and independently checked walks, and compare its full cost on n41/n53 L=1,024 and L=1 against the current rho and IC on the same host.
2. **Count and calibrate all operations.** Instrument compact field multiplication/squaring/inversion, table work, rank search and LA alongside rho additions, canonicalization and setup; calibrate a common equivalent group-operation or instruction unit on one pinned machine, retain wall as secondary, and recompute S and the applicable floor/reference ratios. A method crossover requires the complete cold S below the strongest matched rho, with no missing preparation or tracing costs.
3. **Sweep K and factor-base policy at equal useful size on held-out Q.** The [verified original/descendant-native/transported/pullback toy comparison](../../../ecc2k130_factor_base_replication_20260925/README.md) already found native cold multiplication 2.087–3.700× original and two exact n131 m2 descending lines with 0/32 hits each; it did not test the n≥3 PDP regime. Use the present per-phase/probe/memory ledger as the baseline, then test the oriented degree-263 descendants and pullback policies with equal useful points and frozen target lists. The [ring certificate](../../../ecc2k130_endo_ring_263_20260925/README.md) gives source discriminant −7 and descending degree-263 leaf conductor 263 and discriminant −484183. That structural difference is established, but no PDP advantage follows from it alone.

The n=83 E_0 full-cost gate remains required before transferring any improvement toward the GF(2^131) challenge. The current compact producer is limited to n≤63 by its one-word field representation; n=83 requires a verified wider backend, equal-source baseline/candidate workloads and matched strong rho. At n=131, useful factor-base population, probe distribution, rank cost, memory and automorphism-aware rho constants must be measured or explicitly bounded. Neither an n53 wall lead nor the conductor change supplies those assumptions.
