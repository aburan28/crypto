# Frozen design: swap/Frobenius quotient of compact S3 states

Status: protocol committed before any new evaluation Q is generated or any held-out performance run. The merged [K-grid result](../compact_k_boundary_20260929/RESULT.md) is the control: at L=1,024, all tested eager-index K values lose complete CPU time to matched normal-basis batched rho, and target probes rise when K shrinks. Previously published Q may be used for development-only correctness and feasibility checks; those points are excluded from the held-out evaluation.

**Hypothesis.** The ordered S3 state `(left,right,relative)` and `(right,left,(-relative mod n))` enumerate the same unordered pair after a global Frobenius shift. Retaining one representative of each swap orbit should preserve all canonical root keys and every four-sum witness, while removing approximately half the root-solver calls, stored regular states, and repeated first-pair query visits. Whether the complete cold process becomes cheaper than the *strongest matched rho* is a separate gate.

**Proof obligation.** A state `(l,r,t)` at shift `s` uses `(x_l^(2^s), x_r^(2^(s+t)))`. Its mate `(r,l,-t)` at shift `s+t` uses exactly the two coordinates in reverse order. `S3` is symmetric in these inputs, and elliptic-curve addition is commutative, so roots and four-sum witnesses are preserved up to input order. The involution fixes exactly `(l,l,0)` when n is odd; these states must remain. The candidate must test this identity for all ordered pairs and relative shifts over a small odd-degree field, including equal x values, zero, and solver fallback branches, and compare the baseline and quotient canonical-root key sets. A full held-out scalar replay is still required: the proof does not guarantee identical search order or cost.

**Code isolation.** Retain the merged `koblitz_orbit_dlp_fast` source and its historical frozen hashes unchanged. Build a separately named `koblitz_orbit_dlp_swap` experimental example from a pinned copy with only the state-representative guard and transparent policy counters. Source diff review must confirm that the factor-base construction, rank policy, target solver, group check and output contract are otherwise the same. Both binaries compile at the same source revision and on the same host.
