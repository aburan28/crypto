# Swap/Frobenius S3 quotient: fewer states, no matched-rho crossover

The frozen n41/n53 evaluation completed all nine Latin-balanced blocks on two new disjoint 1,024-point public-Q corpora. Each of the eight same-K baseline/quotient pairs built the same signed-orbit factor base, reached full rank and recovered every logarithm; the normal-basis 32-walk batched-inversion rho recovered the same Q. The hosted verifier independently checked 72 rank runs and 9,216 recovered outputs **per arm at each n**. All 162 cold child processes exited successfully; there were no censored timeouts or failed targets. A separate macOS machine replayed both complete raw artifacts and produced byte-identical PASS receipts to Linux (SHA-256 `56d7a57eb62b2a1b5071530a2e97b29388a397975bb7a10b6f54a4ccec21b690` at n41 and `42a191dfd292ecbd14d64f78fe5d74f385339687c1a14341d69ab8c2faec2034` at n53). Each block repeats the same Q corpus, so the intervals below describe within-runner variation, not independent target-distribution uncertainty.

The [protocol](PROTOCOL.md) was committed before new Q generation. Source, seed 622934, K grids, order, caps and acceptance rules were then locked in [SOURCE_FROZEN.json](SOURCE_FROZEN.json) at commit `757ad624`; the two point-only Q files and separate verifier-only scalar fixtures were locked in [FROZEN.json](FROZEN.json) at commit `716f46e6`, before hosted evaluation. Each file has 1,024 distinct points, independently checked as `[d]G=Q`, and zero overlap with 3,075 earlier public points at its n. The evaluated source is unchanged after that freeze. Both cells ran on Linux x86-64 AMD EPYC 9V45 runners; ratios are paired within each cell, and cross-n exponents are not fitted.

All eight quotient/baseline paired CPU intervals exclude parity on the improving side. All eight quotient/rho intervals exclude parity on the losing side. The observed quotient grid minima are n41 K=255 at 1.6124 s CPU (2.119× rho) and n53 K=550 at 10.7630 s (2.562× rho). Selection of these K from this evaluation grid is exploratory; neither minimum is a confirmed factor-base policy on a further independent Q corpus. The same-K quotient saves roughly 19–34% CPU at n41 and 8–25% at n53, and roughly halves the retained RSS at each K. This is an **engineering** improvement in complete cold-process cost; the generic counting boundary does not move.

The mechanism is exactly constrained. The involution `(left,right,t) ↔ (right,left,-t mod n)` fixes the `K` states `(l,l,0)` at odd n, so the quotient considers `(K²n+K)/2` candidates. The exhaustive GF(2⁵) test checks every ordered x pair and shift, including zero, equal inputs and solver fallback branches; the baseline and quotient canonical root-key sets and stored-witness validity agree. Across all 144 held-out compact rank runs, the same-K factor bases are byte-identical and the number of root-table entries is identical; at n41 K=255, regular states fall 2,666,025→1,333,140 while entries remain 2,664,777. At n53 K=550, states fall 16,032,500→8,016,525 while entries remain 16,030,253. Every compact arm reaches rank K in exactly K attempts in every block, meeting the K+L attempt-count floor for its K and 1,024 targets; the large cost is per-attempt work, not extra rank attempts. Every recovered scalar separately satisfies the group equation.

The cost reduction is concentrated in index construction. At n41 K=255 the quotient cuts median index build 1.141→0.557 s, while target work is 0.740→0.754 s and mean target probes 2,498→2,637. At n53 K=550 it cuts index build 8.275→4.243 s, while target work rises 3.539→3.882 s and probes 12,542→12,959. The complete rho process at n53 is 4.188 s wall: index build alone is approximately that cost, before 2.525 s of rank and 3.882 s of target extraction. A query-only improvement cannot cross this measured reference at that K, and an index-only improvement leaves large rank/query cost. [ANALYSIS.json](ANALYSIS.json) retains all K, phase, state, probe, memory and paired-ratio values; [analyze.py](analyze.py) derives it from the passing receipts.

**Decision.** This is a quantitative no-go for the preregistered swap quotient and K grids on these two point corpora against the strongest matched rho. It is not a no-go for another index/query policy, a degree-263 descendant, n83 or GF(2¹³¹). The common calibrated fully charged `S=operations/√r`, its generic-group-floor ratio and an algorithmic speedup remain **unset**. The next bounded experiment should first count S3 solver calls (including no-root returns), exceptional fallbacks, inversions, hash probes and lift attempts by phase, then preregister batch inversion windows for both index construction and query extraction. Query batching must preserve early-stop semantics and charge unused candidates in a window. The n53 K=550 result makes the joint index/query condition explicit; measuring one phase in isolation cannot satisfy the rho gate.
