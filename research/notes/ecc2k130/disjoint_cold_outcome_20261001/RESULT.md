# Fresh disjoint-Q W64 cold panel: correctness advances, timing censored

The one-shot [run 36794339148](https://github.com/aburan28/crypto/actions/runs/36794339148) used the inputs and source frozen in [PR #1095](https://github.com/aburan28/crypto/pull/1095). Five of six fixed cells passed the unchanged hosted verifier and a separate macOS replay. The n37/L1024 job executed all 15 children successfully but failed a frozen assertion about the order of two pinned intermediate points. A post-run addendum verified all of that cell's rank and point-log outputs by checking every pairing of the same four selected points; it found six records (three target cases, each in both compact arms) where the producer pinned the `(0,3)/(1,2)` pairing rather than the verifier's assumed `(0,1)/(2,3)` pairing. The original failure remains the cell's protocol status.

**The preregistered timing gate accepted 0/6 cells.** All five frozen-PASS cells had a valid compact A/A drift check and zero sampled contention. Each hosted isolation record also listed 81–82 user threads still *allowed* on the reserved CPUs, so the stricter frozen rule declared every one `uncontended=false`. This says those threads could run there; the monitor did not observe contention. It is not grounds to waive the rule after seeing ratios. No native-CPU crossover, fixed-policy no-go, method speedup, n83/n131 transfer, or ECC2K-130 challenge logarithm follows from this run.
