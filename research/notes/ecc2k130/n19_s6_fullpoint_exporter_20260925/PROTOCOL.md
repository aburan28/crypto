# S6 full-point Boolean exporter prerequisite for charged n19 phase comparison

Status: **stacked draft, representation only, n19 semantic census unrun, solver outcomes unrun**. This branch is based on the exact head `708e3c8` of draft [#804](https://github.com/aburan28/crypto/pull/804), itself stacked on [#802](https://github.com/aburan28/crypto/pull/802). The charged experiment is specified in [#809](https://github.com/aburan28/crypto/pull/809); the phase evidence is [#807](https://github.com/aburan28/crypto/pull/807). Its `FROZEN.json` deliberately sets `release_main_head=null`, and `run.py` refuses the n19 census until #802, #804 and #807 are merged, this branch is rebased onto their actual merged bytes, source hashes are re-frozen, and an independent peer reviews that exact head. Opening this draft is an implementation milestone, not release or a claim that SAT has beaten rho.

The question this prerequisite answers is whether one ordinary DIMACS circuit can represent a labelled six-factor decomposition with *exact full-point equality*. Every one of six distinct factor slots contains seven finite full points from the SHA-pinned #767/#769 archives. The finite 4-torsion point `(0,1)` is encoded `(o,x,y)=(0,0,1)`; the identity is `(1,0,0)` and never a factor choice. There is no cross-slot permutation reduction. `s6.py` creates 11 point roles `F0..F5,S2..S5,SUM`, five independent 19-bit slope words and 42 one-hot selector bits, exactly 566 primary bits. It translates the *same* #802 full-point relation into one shared Boolean DAG five times, with intermediate point wires shared. The single asserted output is the conjunction of all five edge relations, one-hot conditions and selector-to-full-point implications. `SUM` denotes the complete right-hand side `tau^s(Q)+T_torsion`, **not** the torsion point alone. `target_units()` pins its canonical full point in each query. #804's ordinary Tseitin writer then exports this shared DAG with one asserted output and 31-bit-safe positive IDs; the frozen caps are two million DAG nodes and 256 MiB per CNF. Any exceeded cap is a censored export, never a negative PDP.

`admission.py` independently parses the exact DIMACS, truth-tables each XOR/AND Tseitin gate, rejects extra or missing clauses, and requires exact target units before accepting either solver status. SAT admission requires exit 10, an exact complete model satisfying every clause and auxiliary gate, exactly one selector in each distinct slot, six canonical selected points, all five independently recomputed full group sums and determined slopes, and equality to the pinned full target. UNSAT admission requires exit 20, nonempty bounded text DRAT and a fresh run of a SHA-pinned external `drat-trim` binary on **those exact query and proof bytes**, preserving command and raw checker logs. Any unknown, timeout, missing model/proof or failed checker remains censored. This module is a verification interface; no n19 SAT/UNSAT run is archived in this draft.

The semantic gate, after release, enumerates all `7^6=117,649` labelled tuples for **each** beta in frozen order `3,338435,303097,464276,42605`. It uses the separate bit-serial/Fermat verifier from #767 rather than the Euclid-inverse witness constructor. For every tuple sum `S`, it computes `R=[4]S`, `Q=[4^{-1} mod 130873]R`, and `T_torsion=S-Q`; checks `[q]Q=O`, `T_torsion` is exactly one of `O,(0,1),(1,0),(1,1)`, `[4]T_torsion=O`, and `Q+T_torsion=S`; constructs the complete S6 witness; evaluates every DAG gate and parsed CNF clause; and checks the full `SUM` pin. This includes `S=O` and projected `O`. The recomputed projected histogram must equal every count in the SHA-pinned #767/#769 archives; the five known support sizes are respectively 62,389; 66,179; 66,203; 59,323; and 64,657. A mismatch is a failed gate, not a tuned result.

The five-beta semantic panel has a frozen **total** 8-hour / 16-GiB cap. `run.py` supervises each child with an external wall watchdog and address-space/tree-RSS cap, keeps raw stdout/stderr, partial CNF/progress, attempt receipts and a file manifest, and stops at the first failure. The child also rejects a requested wall cap above eight hours and installs its own address-space/alarm limits. The all-tuple parsed-CNF pass may be too expensive for this cap; if it censors, retain that failure and design a new, independently frozen optimization rather than relaxing this cap after seeing it. Toy `n=2` self-test is an implementation correctness check, not an n19 cost sample. In the finite-factor chain it verifies the four reachable local types: inverse, double, generic and copy from an O prefix. The inherited #802 local-gate evidence covers the impossible `copy_p` case where the right factor is O.

The implementation requires Python 3.10 or newer (`zip(strict=True)` is used by #802). The dedicated pull-request workflow runs only this hash/syntax preflight and the n=2 toy; it never launches `semantic.py` or a solver. The toy check currently has seven finite points and 107 primary bits. Its parsed DIMACS has 2,662 nodes, 9,018 clauses and 130,487 bytes; selected representatives for all four reachable branch types, O prefixes, and distinct tuples lift to satisfying complete models. This is a local regression, **not** a solver measurement, n19 semantic admission, operation count, or speedup. Matched automorphism-aware Pollard rho remains the reference; full-cost `S` and ratio to rho are unset.

This prerequisite is not the whole #809 charged gate. The n13 five-slot exceptional mask `[0,0,0,2,1]`, all 32 #785 branch labels with lifted models and external negative proofs, the eight n19 Q controls with all torsion branches, sealed 64-target same-Q run, cold base-log/rank acquisition, fallback rho, common operation unit and end-to-end accounting remain downstream. No solver timing begins merely because this representation or its semantic census passes. The next implementation PR must freeze the query runner, binary/source hashes, exact target order, proof checker, independent replay and those controls at an exact reviewed head before any charged outcome. A runtime or cryptanalytic crossover claim further requires the full #809 matched workload and its prescribed validation.
