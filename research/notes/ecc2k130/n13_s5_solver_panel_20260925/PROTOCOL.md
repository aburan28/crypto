# Held cold 32-label n13 S5 SAT/DRAT admission panel

Status: **pre-outcome draft; no n13 solver call or proof result has run in this branch.** This implementation sits on exact [#813](https://github.com/aburan28/crypto/pull/813) head `875bf0aa8869bfba63a3c15c0ce1110ad9d04ceb`, itself stacked on #811/#804/#802. It is the n13 proof-admission control required by [#809](https://github.com/aburan28/crypto/pull/809), not an index-calculus cost comparison. `FROZEN.json` starts with `release_main_head=null`. No run is released until #802, #804, #807, #811 and #813 merge; this branch is rebased onto their actual merged bytes, every hash and host/toolchain pin is re-frozen, its exact head receives independent peer review, and the guarded release gate passes. If the host differs, freeze a separate runner/binary record before outcomes; the current panel is for the pinned Apple arm64 Mac, not hosted Ubuntu. Hosted CI never invokes CaDiCaL, DRAT-trim, or the semantic census.

`QUERY_MANIFEST.json` is a pre-outcome byte freeze of all **32 exact ordinary DIMACS queries** in immutable order `Q0T0,Q0T1,...,Q7T3`. Each row pins `SUM=Q_i+T_j` as a full `(o,x,y)` point, its 27 full-target unit literals, variable/clause/byte count, SHA-256, and the exact full-tuple count from #774. The manifest is regenerated through #813's complete four-edge five-slot exporter and independent CNF parser by `queries.py --verify`; a changed byte fails before any solver call. The corpus `class` field is irrelevant to branch status. Exactly five rows have count>0 and expect SAT; 27 have count=0 and expect UNSAT. The exceptional `Q3T0`, index 12, full target `(7256,3272)` and O-prefix witness remain pinned by #813. Expected status is a preregistered comparator, not accepted solver evidence: a positive requires a complete independently lifted model, and a negative requires an externally checked proof on its exact query. A contradictory verified status is reported as an exact-count mismatch; an unknown, cap, incomplete model, missing/invalid proof or checker failure is censored.

The primary cold solver is the exact CaDiCaL 3.0.1 binary at `/opt/homebrew/bin/cadical`, SHA-256 `601c9fa8ba5d09fd81bb00c89b3e54832f138bccc3422bd8652e8cda4d74d1fa`. Each label gets a new process with `--no-binary query.cnf proof.drat`, including expected SAT labels; no branch receives a cached answer or clauses. The checker source is the vendored upstream `drat-trim` commit `2e3b2dc`, SHA-256 `d834b649f437e091597f5347f259b9f681087f89ca0844d0cee250a1a0c2ee`. The exact Apple clang version, Mac platform, `cc -O2` command and fixed output path are frozen. This toolchain embeds output-path-dependent bytes: two builds to different paths produced different hashes, whereas repeat builds to the fixed path reproduced the pinned checker binary SHA. `panel.py` compiles at that fixed path before the first query, fails closed if its bytes differ, copies those exact bytes into the outcome archive, and uses only the archived copy for all 27 proof checks. A nonblocking exclusive lock at the frozen path is held across checker compilation and the whole panel; a concurrent run fails before creating an outcome directory. Both source and binary hashes, compile command/logs/resources, and archived binary bytes are retained. A Linux runner would need its own reviewed pre-outcome freeze; source SHA alone is not substituted for a required binary pin.

For each label `export_one.py` runs under 60 s / 2 GiB and a 64-MiB CNF cap, checks the exact query hash, and preserves any capped partial file. CaDiCaL runs under 120 s / 4 GiB, with a 1-GiB proof/file cap. SAT model lifting runs under 60 s / 1 GiB and rechecks all CNF clauses/auxiliaries, five distinct selectors, four full-point sums, slopes, and the exact target by #813's independent Fermat replay. UNSAT admission invokes #813's exact-query auditor and an external text DRAT checker on the same query/proof bytes under **300 s / 4 GiB**, with a 64-MiB per-log cap; its enclosing admission process has 360 s / 4 GiB for Python parsing/logging. The entire panel has a separate 8-hour / 16-GiB external supervisor cap. None of these limits may be relaxed after a status is observed. A failed export stops the panel because the frozen query domain has drifted; other solver/admission failures are retained as censored attempts while the fixed label order continues until the whole-panel cap.

`run.py` verifies merged PR states and merge commits, frozen main ancestry/head and parent bytes, exact host/toolchain and binary/source hashes, query manifest and a working RSS sampler before creating an outcome directory. `panel.py` records per-label export, solver and admission commands, UTC intervals, exits, stop reasons, wall, sampled RSS, raw stdout/stderr, exact query and proof bytes/hashes, proof-checker logs and receipts even for failed external checks, lifted full-point witness for SAT, and a progress receipt after every label. It archives the exact compiled checker binary. The outer runner adds a recursive byte-count/SHA manifest and preserves partial data if capped. Child-plus-watchdog CPU is marked a platform diagnostic, since it includes sampler processes; it is not an exclusive common operation unit or a speed comparison. `PANEL_PASS` needs all 32 cases, precisely five lifted SAT and 27 externally proved UNSAT, every exact status agreeing with the independent tuple-count comparator, all caps respected, and no missing receipt. Anything less is `CENSORED_OR_FAILED`.

The next scientific decision is whether this complete n13 semantic/proof admission allows the held n19 six-slot experiment to proceed after its own full semantic gate. This n13 panel does **not** measure charged n19 PDP cost, base-log training, 64-target IC recovery, matched ±Frobenius rho, `S`, a crossover, or ECC2K-130 feasibility. Those remain subject to #809's cold same-Q accounting and separate exact-head freezes.
