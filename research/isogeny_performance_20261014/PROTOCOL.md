# Native isogeny performance campaign — 2026-10-14

Request: inventory each implemented isogeny-finding algorithm, measure its
baseline on several CPU types, and iteratively improve its speed. The previous
2,000-additional-map search remains a separate, unfinished requirement.

| Requirement | Evidence and acceptance |
|---|---|
| Inventory every implementation | `INVENTORY.md`, linked modules, input/output boundaries and existing benchmark groups |
| Freeze baseline before optimization | Clean source SHA, retained executable, compiler, host, command and exact input/output hashes |
| Several physical CPU types | Native hosted x86-64, Linux ARM64, Apple ARM64 and Intel macOS; detected models, no inference from runner labels; unavailable measurements stay open |
| Iterative optimization | Separate hoisting and batch-inversion rungs, exact map equality, all eight BMSS methods measured, rejection ledger |
| Comparable runs | Five A/A rounds followed by five interleaved A/B rounds on identical fixtures; raw samples retained |
| Qualified wall speedup | Reserved core, exclusive lock, pre/post other-process CPU accounting, pressure and interference checks; shared-host timings excluded |
| Correctness | Independent Kohel kernel/map comparison, native and counted implementations agree, four public point transports per case, all existing algorithm tests |
| Delivery | Dedicated `isogeny-perf` executable in ReleaseMe isogeny archives; ready PR; reports and benchmark browsing copies |

The first optimization series targets the eight BMSS methods for `(E,E') ->
normalized isogeny`, at 192, 224, 256 and 511 field bits and prime degrees
7, 31, 101 (257 available explicitly). Fixtures are deterministic public
supersingular curves generated by `ss_workload`; these are field-width cases,
not the published P192/P224 models. A supplied sigma is charged as existing
input for methods that require it. Generating fixtures, deriving the reference
kernel, verification, and allocating receipts are outside the constructor
interval and must remain explicit. Whole `isogeny search` and independent
replay require a subsequent dedicated campaign on named curves.

Counts are generic `Field` API operations, with inversion internals opaque.
They are not instruction counts, CPU cycles or a priced total cost. The
counted wrapper intentionally uses generic convolutions; timing uses the
original native field backend. Never convert a multiplication-count reduction
into a whole-search speedup. The native tool currently labels all timing
samples unreserved and unqualified. macOS has no Linux affinity/PSI facility;
this stage records counts without wall samples there. The isolation requirement
remains open until a native reserving wrapper is supplied and validated.

The broad legacy harness covers kernel construction, modular-polynomial and
division-polynomial finding, path search, class-group and higher-dimensional
methods. Its existing records lack exact-output fingerprints and qualified
isolation. It will be inventoried and retained as exploratory coverage; it
cannot substitute for the new measured constructor series.

Keep failures, interrupted records, source changes, binary hashes and run
costs. No optimized rung is accepted unless its exact outputs match the
frozen baseline and its independently checked reference. A larger degree
case can be censored by a resource limit without dropping it from the plan.
