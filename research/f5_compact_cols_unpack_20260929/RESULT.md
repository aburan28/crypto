# Compact-column F5 unpack: baseline and candidate pending

The first unmodified-source baseline was run in [CI run 36631128286](https://github.com/aburan28/crypto/actions/runs/36631128286) before any unpacker edit. It produced all seven exact F5 outputs on an Intel Xeon 6973P-C, Linux x86-64, Rust 1.98.1. The n24 degree-4 call returned 6,924 rows and 13,734,979 terms, with raw fingerprint `3f659516eff553b8` and canonical row-space fingerprint `ed5234ba018bc079`. Its 2,180,736-byte release binary has SHA-256 `604a81550ed7fc1caa232fffa2aee5850658a2092e6f3bd5dad8d26c43abd293` and is preserved as a deterministic [gzip artifact](runs/36631128286-attempt1/f4_f2_bench.gz) (compressed SHA-256 `5fa4b97779d4e168a16c0110905737186df0d7574b1f515c2acdb1f593b67946`). The [full receipt directory](runs/36631128286-attempt1) includes the manifest, output, CPU choice, isolation record and stderr.

The isolation wrapper reported zero contended samples during the short call, but left **81 user threads** eligible on its reserved CPUs because the hosted action could not move them. Its 78.989 ms call time is therefore an **unqualified baseline**, not a speed reference. The binary and correctness evidence remain valid.

The privileged retry in [CI run 36652061698](https://github.com/aburan28/crypto/actions/runs/36652061698) stopped **before timing**: root could not reopen the runner-owned default lock in sticky `/tmp`. Its [failure receipt](runs/36652061698-attempt1) and [workflow](WORKFLOW_BASELINE_ATTEMPT2.yml) are preserved; the rebuilt binary hash still matched the first attempt.

The third unchanged-source [CI run 36652868549](https://github.com/aburan28/crypto/actions/runs/36652868549) passed the isolation gate on the same Xeon 6973P-C hardware class. Its 10-second preflight observed 0.20 other CPU seconds, below the 1.00-second budget; the privileged wrapper moved 150 threads, left **zero user threads** on the reserved CPU pair, and recorded **zero contended samples**. All seven F5 outputs matched the first baseline, and the release binary again had SHA-256 `604a81550ed7fc1caa232fffa2aee5850658a2092e6f3bd5dad8d26c43abd293`. The primary n24 degree-4 call was 90.463 ms, with 38.159 ms elimination and 44.976 ms unpacking. This is a qualified **unmodified-source baseline** on that host, not a candidate speedup. Its [full receipt](runs/36652868549-attempt1) and [exact workflow](WORKFLOW_BASELINE_ATTEMPT3.yml) are preserved; the baseline workflow was removed from active CI after the run. The preserved binary from attempt 1 is byte-identical to this one by SHA-256.

No candidate code has changed yet. The paired candidate result and twofold complete-call goal remain pending, and future paired ratios must be taken within their own calibrated host rather than dividing by this baseline's absolute 90.463 ms.
