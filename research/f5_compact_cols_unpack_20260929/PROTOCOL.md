# Matrix-F5 compact-column output unpack: frozen experiment

## Question and dependency

On the n24 degree-4 full-output call, converting packed pivot rows into `Vec<F2BoolPoly>` costs about 55 ms, roughly half the branchless-strip candidate's measured 106 ms call. The current direct scalar loop performs one indexed load from a 64-bit monomial column list for each of 13,734,979 output terms. For the supported `n_vars ≤ 32` route, precompute a 32-bit column list once, then expand every row by unchecked loads guarded by the packed matrix's valid-column invariant. The output remains the same `Vec<F2BoolPoly>` of 64-bit monomial masks. The hypothesis is that the smaller lookup list and removed per-term bound check reduce full-call time. Retain the existing direct scalar path as `KIC_F5_UNPACK_COMPACT_COLS=0`; select the candidate only with `=1` until measured.

This is dependent on branchless-strip [PR #998](https://github.com/aburan28/crypto/pull/998), whose default-on gain is still pending the repository's CPU-isolated replay. The frozen source for this experiment is commit `773466870bffd780a629fc4afae4a95b636f3e82`: SHA-256 `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da` for `src/cryptanalysis/matrix_f5_f2.rs`, `6fd3f10ef8e681490784c624e703eeb8fa887c5817ec9bdf34844e3f943c7f5c` for `src/cryptanalysis/gf2_elim.rs`, and `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336` for `examples/f4_f2_bench.rs`. If #998 is not accepted, do not add this candidate's ratio to an accepted baseline chain; rebase and remeasure it on the final accepted source.

## Baseline, workload and stop rule

First build and preserve the unmodified frozen-source release binary, its hash, host/runtime/CPU-feature manifest and an isolated reference call before editing the unpacker. Use the seven F5 cases of `examples/f4_f2_bench.rs`, primary `f5_n24_m24_d4`, seed XORs `0`, `badc0de1`, `5eed2026`, `f5c02a28`. The paired decision uses one binary with separate explicit `KIC_F5_UNPACK_COMPACT_COLS=0/1` processes, one warmup per mode, five A/A and five alternating A/B pairs per seed, one Rayon thread, selective echelon, fused F5 row count, direct packed rows, AVX2 row XOR, table reuse, direct scalar unpack and the branchless strip default. Preserve every outcome, raw and canonical row fingerprint, rank, output term count, build/criterion counts, reduction word operations, source/binary hashes, hardware, affinity and all timings. New output must match every exact field on all seven cases and all seeds.

All release tests/builds on the Linux x86 runner use `tools/isolated_bench.py busy`. Run the paired harness through `tools/isolated_bench.py reserve` with a selected CPU and all its SMT siblings reserved, one free CPU left for other work, 0.25-second contention samples and the default preflight thresholds. Preserve CPU choice and every isolation receipt. Only uncontended runs with no user threads left on the reserved CPUs support wall-time claims; a refusal or contended sample is a recorded failure, not a gain. Use A/A ratios to report residual noise. The primary complete-call paired median must exceed 1.05× and its five-pair bootstrap 95% lower bound 1.02×, and no holdout or smaller case may regress beyond its A/A range. If it misses, remove the runtime candidate after preserving the exact patch, workflow and receipts. If it passes, perform a separately frozen default-on one-thread replay and a compliant multi-thread nonregression control before merge. The requested further 2× goal passes only if the frozen primary complete-call median and lower bound exceed 2.0× relative to the declared full-call reference with exact output and all regression guards. An unpack-only improvement is a solver-stage diagnostic, not an IC one-target online DLP or rho speedup.

## Baseline isolation correction before the candidate

The first baseline [CI run 36631128286](https://github.com/aburan28/crypto/actions/runs/36631128286) preserved the unmodified binary and exact output but was not a qualified wall-time baseline: the reservation record left 81 user threads eligible on its CPUs, because the hosted action lacked permission to move them. Preserve that artifact and do not use its wall time as a speed claim. Before changing the unpacker, rerun the same frozen source using noninteractive `sudo` only for the isolation wrapper so it can move other user threads, with the benchmark's option environment passed explicitly to the child. Keep `--max-other-cpu=0.10` and `--max-psi=5.0`, but increase the quiet sampling window to 10 seconds to distinguish a runner-worker startup burst from sustained load. Accept the baseline only if preflight succeeds, no user threads remain on the reserved CPUs, and no sampled interval is contended. Keep the binary and all failure receipts from both attempts. If the host still cannot meet those conditions, the wall-clock baseline remains unknown and the candidate must not be promoted from hosted-CI timing.

The privileged [CI run 36652061698](https://github.com/aburan28/crypto/actions/runs/36652061698) stopped before timing because root could not reopen the runner-owned default lock in the sticky `/tmp` directory. Preserve its receipt; its binary has the same SHA-256 as the first attempt. For the next unchanged-source retry, pass one lock under the runner's nonsticky `RUNNER_TEMP` workspace to both `busy` and the privileged `reserve` call. Retain the 10-second quiet check and all default contention thresholds. No candidate edit or timing is allowed until a baseline reservation succeeds under the stated gate.
