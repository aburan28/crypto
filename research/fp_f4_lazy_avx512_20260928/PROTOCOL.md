# AVX-512 accumulation for deferred prime-field F4

## Frozen hypothesis and reference

The existing 32-bit deferred kernel cut the frozen `quad_n8_p65521` complete F4 call to about 1.64× the original wide arithmetic. A measured AVX2 accumulation loop made the direct wide/candidate ratio 1.756× on an AVX2-only host, short of the user's 2× target. On an AVX-512F host, eight 64-bit lanes can carry eight bounded 32-bit products per loop iteration. Test whether that closes the complete-call gap while retaining the same 256-update normalization interval, row order, output and counted operations. `F4_FP_LAZY_AVX512=1` explicitly selects the new path; the scalar path stays the default and `F4_FP_LAZY_AVX2=1` keeps its separate opt-in behavior.

The unmodified reference is main commit `8402153b941b9b78e1b04a5e4906fc211099decf`, which includes merged [PR #903](https://github.com/aburan28/crypto/pull/903). Its `src/cryptanalysis/f4_fp.rs` SHA-256 is `b158b0823801d6af788bc989e4ca81482c27f5bb40f1f45cd83dfc5cce6b566d`; `examples/f4_fp_bench.rs` is `9a8b3db32520c21d6eefa3506c338a6cc39c45bdf6f134b59dd6563192bde883`. Build and retain that reference binary and the candidate with identical release flags. The candidate's only algorithm change is the opt-in eight-lane update and feature dispatch. The two binaries must differ by hash.

## Frozen paired workload and accounting

Use all 13 standard and `large` cases from `examples/f4_fp_bench.rs`, including the primary `quad_n8_p65521`. Freeze seed XOR zero, original holdouts `badc0de1` and `5eed2026`, and fresh holdout `a28cf401`. Pin one Linux x86-64 CPU reporting both AVX-512F and AVX2 and set `RAYON_NUM_THREADS=1`. A host without either feature records `unsupported_host` before any timing call. The AVX2 requirement covers the eight-value load intrinsic used inside the AVX-512 update. Warm all three arms once per seed, then take five A/A pairs in current mode `F4_FP_NARROW=2`, five alternating current/candidate pairs, and five alternating original-wide/candidate pairs. Wide uses the unmodified reference binary with `F4_FP_NARROW=0`; current uses it with `=2`; candidate uses its own binary with `=2` and `F4_FP_LAZY_AVX512=1`. Explicitly set `F4_FP_LAZY_AVX2=0` in all arms.

`f4_ms` covers the complete degree-bounded F4 call, including symbolic preprocessing, pair-row reduction, residual RREF and final interreduction; process launch and fixture construction are excluded. Retain every process's full output, status, seed, source and binary hashes, host features, affinity, load and timing. Every case and seed must match the reference basis and solve fingerprints, step count, matrix shape, basis size and verdict. The x86 direct accumulator test must match scalar updates across widths, offsets, factors and the 256-update normalization boundary.

## Decision and stop rule

For each case and seed, report five paired current/candidate and wide/candidate complete-call ratios, medians, exact five-pair bootstrap 95% intervals and A/A ranges. For engineering promotion, require primary current/candidate median ≥1.12 with lower interval >1, all primary holdouts above their A/A maxima, and no smaller complete-call median below its own A/A minimum. Only if that passes run a frozen four-thread control before changing the default. Claim a 2× complete-call gain against original wide arithmetic only if the **direct same-run** frozen wide/candidate median and lower interval both exceed 2.00 and holdouts show the same direction. A missed gate leaves AVX-512 opt-in or removes it, with the raw result preserved; do not rerun timing to seek a passing sample. This is a solver-stage measurement, not one-target IC online time or DLP speedup.

## Pre-measurement dispatch guard amendment

[Run 36469467083 attempt 1](https://github.com/aburan28/crypto/actions/runs/36469467083/attempts/1) passed tests and built both binaries, then recorded an AMD EPYC 7763 `unsupported_host` with zero benchmark calls. Its receipt is preserved. Attempt 2 was canceled during the exactness-test step, before building the reference or making any benchmark call, so the runtime guard could require AVX2 as well as AVX-512F. The eight-value load uses an AVX2-width intrinsic. This safety guard and the matching host check were added before measurement; the source reference, cases, seeds, pair count, timing boundary and 2× gate are unchanged.
