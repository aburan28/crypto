# Matrix-F5 one-pass direct unpack: frozen local screen

## Question and source

Can direct output unpack avoid its full-row popcount prepass without slowing the exact `Vec<F2BoolPoly>` result? The candidate reserves a bounded estimate per echelon row, checks space once per 64-bit input word, and grows when necessary. It writes terms in the same column order and keeps all rows, rank, fingerprints and counted work identical. `KIC_F5_ONE_PASS_UNPACK=0` runs the existing exact-preallocation direct unpack; `=1` selects the one-pass path only for the n24 degree-4 shaped call (`cols >= 4096`) when direct unpack is active. The row capacity estimate is `(cols.len() - row_index) / 3 + 64`, clamped at 64, with growth checked at each word; this is an allocation heuristic, never an output limit. The candidate must return the same output for sparse, dense, odd and partial-word rows. Its maximum allocated capacity and growth count will be reported as diagnostics.

The immutable reference is main commit `1f4f87b1b5aa2af3f9dcc1eb371b4fd4c35750f4`. Source SHA-256: `matrix_f5_f2.rs` `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da`; `gf2_elim.rs` `6fd3f10ef8e681490784c624e703eeb8fa887c5817ec9bdf34844e3f943c7f5c`; `f4_f2_bench.rs` `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336`; isolation wrapper `ff59e53fd5566078ad493c8be0d06168699c4fd194bc881d99df19fa20e007ef`. The separate POPCNT experiment in PR #1033 may overlap this hypothesis; neither its result nor its code enters this reference.

## Frozen screen and decision

Use one release binary and `tools/isolated_bench.py busy` on the local Apple ARM64 host. Set one Rayon thread, selective echelon, fused row build, direct pack, direct unpack, branchless strip when available, Gray-code table reuse, four tables, and disable deferred-above, word batching and AVX-512 unpack. Run all seven F5 cases from `examples/f4_f2_bench.rs` for seeds `0` and `badc0de1`. For each seed, run one warmup per arm, five reference/reference A/A pairs and five alternating reference/candidate A/B pairs. Preserve every process, failure, timeout, source and binary hash, host, exact raw and canonical fingerprints, structural and counted operations, output terms, wall and phase times, selected route and capacity diagnostics. Do not time only unpacking; the primary ratio is the complete `f5_n24_m24_d4` call.

This local screen is exploratory, not an x86-64 or isolated-host speedup claim. Advance to a separately frozen x86-64 isolated replay only if both seeds have exact output on every case, the primary paired full-call median is at least 1.04 on each seed, each seed's exact five-pair bootstrap 95% lower bound exceeds 1.02, and no smaller-case paired median is below its own A/A minimum. Any failure, missing output, OOM or timeout is retained and stops promotion. The user's 2x target remains a separate full-call gate: paired median and lower confidence bound must both exceed 2.0 under isolated x86-64 conditions. If the local screen fails, archive the tested patch and raw receipt, remove the opt-in runtime path, and keep only research evidence. These are F5 solver-stage costs, not IC one-target DLP or rho times.
