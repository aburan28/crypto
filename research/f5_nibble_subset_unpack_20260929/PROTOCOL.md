# Matrix-F5 nibble-subset output unpack: frozen experiment

## Hypothesis and reference

The exact one-thread n24 degree-4 matrix-F5 call emits 6,924 rows and 13,734,979 monomial terms. Direct scalar unpacking now occupies roughly 37–55 ms of the complete call on measured x86-64 hosts. A byte-subset copy table of 14.9 MB was exact but substantially slower, plausibly because its lookup footprint exceeded useful cache. This experiment instead precomputes each ordered four-column subset. At 12,951 columns, 16 patterns per chunk require about 1.05 MB of offsets and masks, including allocated capacity. The candidate copies each selected term sequence into the exact `Vec<F2BoolPoly>` row; table build and allocation are inside the complete-call timer. This is a new hypothesis, not a reinterpretation of the rejected byte-table result.

The frozen unmodified source is commit `154faab572a133425a031b0ae76a520a939a85a9` on branchless-strip PR #998. SHA-256: `src/cryptanalysis/matrix_f5_f2.rs` `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da`, `src/cryptanalysis/gf2_elim.rs` `6fd3f10ef8e681490784c624e703eeb8fa887c5817ec9bdf34844e3f943c7f5c`, `examples/f4_f2_bench.rs` `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336`, isolation wrapper `ff59e53fd5566078ad493c8be0d06168699c4fd194bc881d99df19fa20e007ef`. The previously qualified unchanged-source EPYC 7763 baseline is [run 36657129349](https://github.com/aburan28/crypto/actions/runs/36657129349), binary SHA-256 `604a81550ed7fc1caa232fffa2aee5850658a2092e6f3bd5dad8d26c43abd293`; its complete receipt and binary are in PR #1013. Its 106.119 ms absolute time is a reproducibility reference only. Candidate ratios use one same-binary, same-host paired run, never a cross-host division.

## Candidate, workload and gates

The opt-in `KIC_F5_UNPACK_NIBBLE_TABLE=1` selects the candidate only for direct scalar unpack with at least 4,096 columns; `=0` is the unchanged reference. Cap actual table allocation at 2 MiB and fall back on allocation failure or larger columns. Preserve ascending column order within each output row, raw and canonical output fingerprints, rank, output terms, row/column counts, criterion/build counts and reduction word operations. Test partial final chunks and the memory cap. Keep selective echelon output, fused row count, direct packed rows, AVX2 row XOR, branchless strip, Gray-code table reuse and direct scalar unpack fixed across arms. Disable deferred-above, word batching, AVX-512 unpack and experimental table building.

Use all seven F5 cases of `examples/f4_f2_bench.rs`, the frozen seed XOR `0` and holdouts `badc0de1`, `5eed2026`, `f5c02a28`. Run one and two Rayon threads separately. Per seed and thread count, use one warmup per arm, five A/A reference pairs and five alternating A/B pairs: 22 processes, seven cases per process. Preserve every process including failure, timeout and OOM, and all source/binary hashes, host/affinity, case outputs, phase timings and counted work. Build and test through `tools/isolated_bench.py busy` under the same CI lock.

For timed calls, use privileged `tools/isolated_bench.py reserve` under that lock, pin all SMT siblings, leave one CPU for other work, and pass the runner's Rustup environment to the harness. Before each block require a successful 10-second preflight, outside CPU use at most 0.10 per second, CPU PSI at most 5.0, zero eligible user threads left on reserved CPUs, and zero contended samples at a **two-second** sampling interval. This interval and the separate blocks are fixed now, before candidate timing. For each seed, try at most three reservations in order and select the **first** attempt meeting all isolation and 22-call exactness conditions regardless of its timing. Archive all refusals and partial attempts. If any seed lacks a qualified block, the result is unknown and no speedup may be claimed. Do not combine absolute times from distinct hosts.

The incremental candidate advances only if the frozen one-thread complete-call reference/candidate paired median is at least 1.05, its exact 3,125-resample bootstrap 95% lower bound exceeds 1.02, no seed or smaller case has a complete-call median regression below its own A/A minimum, the two-thread control has no such regression, and actual table allocation stays within 2 MiB. The requested further 2× complete-call goal passes only if the same frozen-primary median and bootstrap lower bound both exceed 2.0 with all exactness and smaller-case guards. If this experiment fails, preserve the exact measured patch, workflow and raw receipts, remove the runtime option, and report the negative result. If it advances, freeze and run a separate default-on confirmation before merge. All ratios here are matrix-F5 solver-stage diagnostics, not IC one-target online DLP or rho speedups.
