# AVX2 lookup-table XOR for shared GF(2) elimination

## Hypothesis and reference

The shared Macaulay GF(2) kernel has an explicit AVX-512 table-row XOR but no AVX2 dispatch. The prior frozen F5 runner was AMD EPYC 7763 with AVX2 and no AVX-512, so its table application used the scalar fallback. Compile the same fused XOR loop with an AVX2 target feature and dispatch once per elimination. Keep the existing AVX-512 path and scalar fallback. The row operations, pivot order, RREF/echelon outputs and counted XORs must be identical. This is distinct from the negative column-panel experiments: it changes the instruction width of each existing row update, not the matrix traversal or table layout.

The unmodified reference is commit `aa2c05c9ddbf15133878aa64e2cace8ee5cef1d8`, whose `gf2_elim.rs`, `matrix_f5_f2.rs` and F5 benchmark source SHA-256 digests are `f8319f456271c31e82e1789643be60d9d16a5bde67e7a346cb4901217a4b51cf`, `592761e4da6a385fa0145b8a548d86ca7b2930d0322398f1dcae07cc96dbeccb` and `812fdc75bd89c7ac7944a2631158dc02bf1861fed25aa72fd629774daeb6f37a`. Build and retain its release example binary beside the candidate binary with identical Rust flags. The benchmark host must report AVX2; otherwise retain an unsupported-host row and do not interpret timing as an AVX2 test. Set `KIC_GF2_FORCE_AVX2=1` in the candidate, including the exact-output tests, to select the AVX2 implementation even when the host also offers AVX-512F. The reference has `KIC_GF2_SIMD=0`, which selects scalar regardless of that force flag.

## Frozen paired measurement

Use `examples/f4_f2_bench.rs`, one repetition of the seven matrix-F5 cases per process, primary `f5_n24_m24_d4`. Freeze seed XOR zero and holdouts `badc0de1`, `5eed2026`, and fresh `a28c0de5`. In both arms request RREF output, set `KIC_GF2_DEFER_ABOVE=0`, `KIC_GF2_WORD_BATCH=0`, `KIC_F5_FUSED_BUILD=0`, and keep the default table count. Set `KIC_GF2_SIMD=0` and `KIC_GF2_FORCE_AVX2=0` in the reference binary, and set both to `1` in the candidate. Pin one Linux CPU with `RAYON_NUM_THREADS=1`, warm both arms once per workload, then take five A/A baseline pairs and five alternating-order A/B pairs. Preserve all process statuses, complete output, source and binary digests, CPU/features, load, memory, and paired phase timings in a raw receipt. `reduce_ms` is elimination; `wall_ms` is the complete F5 call excluding fixture construction and process launch. Use exact five-pair bootstrap 95% intervals and each case's A/A range. If the one-thread gates pass, repeat on four pinned CPUs before any default change.

Require identical raw and canonical row fingerprints, rank, pruning, criterion and reduction word-operation counts on every case. The shared-kernel tests must match textbook RREF and echelon row space on randomized, structured and rank-deficient matrices. The frozen primary elimination median reference/candidate ratio must reach 1.20 with its 95% lower bound above one; the complete-call ratio and lower bound must exceed one; all holdout primary gains must lie outside A/A noise; and no smaller complete-call median may fall below its own A/A lower bound. A failing candidate remains opt-in or is removed from the final runtime diff, with its receipt preserved. Do not repeat timing until a pass appears.

The user's 2× goal is a **complete F5-call** gain against the current RREF default. This SIMD candidate is one bounded lever, and ratios from separate experiments cannot be multiplied into a measured combined claim. No one-target IC or DLP speedup is claimed from this stage benchmark.
