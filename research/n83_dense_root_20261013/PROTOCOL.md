# N83 dense packed-root table: frozen execution plan

## Contribution being tested

The opt-in `KIC_PACKED_ROOT_TABLE_DENSE=1` reduces requested table slots from
four per regular state to two, before power-of-two rounding. It preserves the
root-key and first-witness semantics. The pinned Lean declarations in
`DenseCapacity.lean` establish the numerical capacity breakpoints under the
source-loop bound `states <= 83*K^2`.

## Exact instance and workload

- Koblitz `a=1`, field degree 83, polynomial low terms `[0,2,4,7]`,
  subgroup order `8569786107849059`, generator as checked by the fixture
  generator and producer. Prefix signed-Frobenius base construction with
  `construct:83:1:K`; actual point counts and hashes are measured, not inferred.
- Public points are generated by `examples/n83_dense_root_fixture.rs` with
  domain `n83-dense-root-held-out-20261013-v1`, BLAKE3 over domain plus a
  little-endian `u32` index, scalar `1 + low_u64_le(digest) % (r-1)`, then
  generic curve multiplication. The producer receives only `targets.jsonl`
  or its first row, `primary_target.jsonl`; `answers.jsonl` is a separate
  verification sidecar.
- SHA-256: points `e9ed7ddb0aeafdbfc7354d67279a8712572eea9d2aee3896f99633bdc2e937cc`;
  answers `6a7022f739df0b2a9e7d7bbbf542820244497147f98d595dff0dbafba0bb9181`.
  Primary point `21c8dfc7d488909e5c4a42c839fcc01bdefa9821c11ba001626a1d15697240e8`.
  The primary workload is the first public point. The remaining points are
  reserved for a secondary paired holdout panel after the primary single-target
  run and same-point rho are recorded.

## Frozen arms and order

| Order | Arm | K | Packed table | Dense request |
|---:|---|---:|---|---|
| 1 | k1271_regular | 1271 | yes | no |
| 2 | k1271_dense | 1271 | yes | yes |
| 3 | k1500_dense | 1500 | yes | yes |
| 4 | k1500_regular | 1500 | yes | no |

Each arm builds its own base and rank system from seed 29 with 12 rank threads,
uses one target thread, and solves the same point. Every producer run has a
900-second wall cap; status 124 is a timeout. A failed or censored arm remains
in the record. We collect `time -l` max RSS, raw output, producer JSONL,
actual base count/hash, table capacity/bytes, setup/rank/LA costs, and
exclusive online phases. The primary comparison is per-target online time
only when scalar replay passes. A completed same-point rho is required before
an IC/rho speedup can be evaluated. Absolute startup and setup stay separate.

The paired rho control uses the previously selected
`fold-L64-DP6-E0` strong-rho policy from
`research/n83_evaluation_20261012/optimization/README.md`, seed
`2026101301`, one OS thread, and a 60-second process cap. Its point-only
worker is `examples/n83_rho_optimization_eval.rs`; configuration is pinned
in `rho_config.json`. The 60-second cap preserves a censored result if it
does not finish; it cannot be interpreted as a solved baseline.

After the primary comparison, the 64-point panel compares target probes and
phase times on the same public points. It is secondary, with reused prepared
logs inside each arm; no panel mean replaces the one-target result. Selection
among the four arms is by lowest mean target probes over complete verified
panel rows under the common resource envelope. Exploratory Mac wall times
cannot establish a controlled CPU speedup. Any table-layout improvement is a
stage result unless the full one-target paired criterion is met.
