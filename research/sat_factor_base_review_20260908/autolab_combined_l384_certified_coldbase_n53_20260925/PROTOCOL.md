## Reproduce the certified base, including index order

The archived base used by merged [#760](https://github.com/aburan28/crypto/pull/760) originated in `examples/koblitz_rank_fixture.rs::point_defined_base` (the #714/#720 producer lineage), not in the current IC producer's ascending-x routine. At n>32 the rank fixture seeds a 64-bit wrapping LCG with `0xD1B54A32D192ED03 ^ n ^ (wanted << 17)`, advances by `state = state * 6364136223846793005 + 1`, masks to the n-bit field, cofactor-projects each finite lift, keeps the first new signed-Frobenius orbit, sorts accepted orbits by canonical representative, then appends each orbit's sorted members and their labels. The IC producer's new opt-in `KIC_FACTOR_BASE_SELECTION=legacy_rank_fixture_lcg_v1` reproduces that schedule and orbit-grouped order. Its default `ascending_x_v1` still follows the previous path. The source and test pin the exact rule; the new mode cannot accompany `KIC_FACTOR_BASE_JSONL`.

The certified header is a read-only admission oracle: gzip SHA-256 `23397af2ef668aed0775bcb409e1ae19555357ded635452818c9a3812f679d08`, 220 columns, 23,320 points, 106 members per signed orbit, 400 scanned x values, ordered-representative-keys BLAKE3 `d859319015ea405fd18aee41b51396ce4edcab64ef66265d8edcdeb5e040eb71`. A Rust test constructs the n53 base from scratch and compares every point coordinate, point label and representative in its exact stored order, plus the representative hash and scan count; a small-field test checks the selection-mode relation independently. The timed training child receives **no** `KIC_FACTOR_BASE_JSONL`, emits its complete newly constructed header, and the separately timed materializer requires the same exact arrays, point-to-label map, representative sequence, scan count and structural fields. The rank fixture serializes `cofactor` as text while the IC producer emits an integer; the materializer checks numeric equality first, then formats that fresh value as text in its own header. No archived point or label is copied into the fresh output. A mismatch stops the arm before rho or 384-point IC.

The exact array order matters: #760 loaded the archived base in that order, and index/witness tie choices may depend on point indices. A semantic set match with different order is **not** admitted as this same-index-policy repeat. The resulting materialized header is the only base input for the later IC point child. The fixture gzip is never used as a producer input and its prior construction time is never charged as new work.
