# Compact-orbit transfer to ECC2K-130: a bounded feasibility gate

**Verdict for the current materialized-root, exhaustive-query design:** no-go for an n=131 port as the next performance step. This is an architecture-specific, conditional projection, **not** an n=131 measurement or a claim about index calculus in general. The next investment should be in a demonstrably subquadratic-memory pair support *and* a query path that avoids scanning all pair states on a miss, followed by a same-stream, cold matched-rho comparison on smaller rungs. The model and exact integer calculations are in [`n131_transfer_model.py`](n131_transfer_model.py).

## Pinned inputs and accounting boundary

The repository's [ECC2K-130 profile](../../../src/bin/ic/params.rs) has field degree `n=131`, curve `a=0,b=1`, subgroup order `q=680564733841876926932320129493409985129` (about `2^129`), and cofactor `4`. It records a permuted type-II normal basis **without imported challenge coordinates**. The present [compact producer](../../../examples/koblitz_s5_sat_instance.rs) stores field coordinates and many scalar labels in `u64`; it implements rungs only through `n=53`. A correct n=131 arithmetic and coordinate-translation implementation is a separate prerequisite. The `q` and field information are source facts, while every n=131 count below is a projection.

The n=53 baseline is the certified base promoted by [PR #720](https://github.com/aburan28/crypto/pull/720): `R=220` signed-Frobenius orbit columns, `F=23,320=2·53·220` signed subgroup points, `2,565,200=53·220²` regular relative-pair states, and `5,081,560` distinct indexed roots (99.048% of the two-root candidates). Base point-set SHA-256: `d859319015ea405fd18aee41b51396ce4edcab64ef66265d8edcdeb5e040eb71`; original producer source SHA-256: `93c3159a0da27d4703727b21041cdf529b3f2206c3a6d3a7878913f951cd08fd`. Merged [PR #735](https://github.com/aburan28/crypto/pull/735) (`d92439080c2d5c3a858f71abfc8e749e273125bb`) supplies its frozen 512-target full-rank receipt: 512/512 relations, first rank 220 at relation 461, 51 subsequent scalar labels predicted, plus eight point-only logs independently recovered. Rank receipt SHA-256: `d5c87025740036476e0d8d492c93a23ede8ed144ce665125d3cebc4c0d0ec285`. The 158.127 s training wall and 646,742,016-byte peak RSS are measured n=53 cold process costs; they are **not** multiplied into an n=131 time estimate. The archived producer double-counted a SAT time that was not incurred, so this note uses its state and index counts, not that erroneous charged subtotal.

The repository's earlier [batched-rho n=53 study](../../../research/sat_factor_base_review_20260908/autolab_batched_rho_n53_20260922/RESULT.md) used a different IC producer and showed it losing to same-target-stream, signed-Frobenius batched rho over its tested batch sizes. Its absolute timings cannot be transferred to this compact producer. We use rho only as a **nominal operation-count reference** here, subject to a matched implementation measurement.

## Counting boundary and current-code work model

For a four-sum relation over a factor base of `F` subgroup points, at most `F⁴` ordered tuples exist. Even if *every* tuple lands on a different group element, a uniformly random probe has success probability

```
p <= min(1, F^4 / q).
```

This is a necessary coverage bound, not a random-sum prediction: tuple collisions, invalid lifts, exceptional cases and rank deficiency can only make the method worse. At n=53, `F⁴/q≈14,053`, so 512/512 observed hits are already in a saturated regime and do not estimate an n=131 occupancy or coverage constant. The 51 post-rank checks validate solved logs, not unsaturated random-target yield. The current base uses complete signed-Frobenius orbits, so a corresponding n=131 base of `R` full columns has `F=2nR=262R` points. The [regular-state scanner](../../../examples/koblitz_s5_sat_instance.rs) visits `nR²` `(left,right,relative shift)` slots; the n=53 scan admitted every slot and emitted two S3 roots each. The current index has about `2nR²` root candidates. On an unsuccessful target, its [query loop](../../../examples/koblitz_s5_sat_instance.rs) tries each of those roots at all `n` absolute shifts, or `2n²R²=F²/2` S3 calls if all states remain regular. The latter two formulas are **implementation projections**; root collisions, regular-state rate, and future algorithms can change them.

The packed-memory column below assumes each distinct n=131 root stores a 17-byte field element and a 7-byte packed `(left,right,relative shift)` witness, with no hash-table overhead. It is a deliberately optimistic 24-byte *record* projection, not a measured RSS lower bound. The n=53 process actually used 646.7 MB for only 5.08 million entries and associated state/base structures. Values are decimal PB/EB (`10^15`/`10^18` bytes).

| n=131 scenario | `R` columns | `F` points | `p` upper bound | regular scan slots | two-root candidates | optimistic packed roots |
|---|---:|---:|---:|---:|---:|---:|
| Keep 220 columns | 220 | 57,640 | `1.62e-20` (`2^-65.74`) | 6.34 million | 12.68 million | 304 MB |
| Cap packed roots at 1 TiB | 13,223 | 3,464,426 | `2.12e-13` (`2^-42.10`) | 22.91 billion | 45.81 billion | 1.099 TB |
| Smallest base whose *upper bound* reaches 1% | 6,164,759 | 1,615,166,858 | 0.010000003 | 4.98 quadrillion | 9.96 quadrillion | 239 PB |
| Smallest base whose *upper bound* reaches 50% | 16,393,005 | 4,294,967,310 | 0.500000007 | 35.20 quadrillion | 70.41 quadrillion | 1.690 EB |

At the 50% counting threshold, the 16.39-million-column rank target is itself a transfer assumption. A dense modular matrix would contain about `R²=2.69e14` cells, or about 4.57 PB at 17 packed bytes per 130-bit coefficient. Four-sparse relation rows can be stored far more compactly, but no n=131 sparse-solve cost or rank-growth distribution has been measured. The n=53 run needed 461 admitted relations to first reach rank 220; this table optimistically budgets only `R` useful hits, not 2.095R.

The 50% threshold is `F>=4,294,967,297` before orbit rounding; `2^32` is one point too small for the exact subgroup order. It gives a **necessary** base size only: no measurement says its actual success rate would be 50%. Similarly, holding the original `F=23,320` points would give `p<=4.35e-22` (`2^-70.96`); merely extending its 220 orbits to length 262 gives the first row. The field representation alone grows from one 64-bit word to at least 131 bits, so n=53 field timings cannot be held constant.

For independent uniform probes, at least `R/p` expected probes are needed to obtain `R` useful relations even if every hit adds rank. Under the current exhaustive loop and all-regular-state assumption, the **failed** probes alone imply about `2^98.24` S3 calls for the 1 TiB row and `2^86.97` for the 50% row. This does not count construction, successful probes, linear algebra, group validation, scalar multiplication, storage overhead, or 1,024 online target descents. It also is **not** a field-operation-equivalent cost: the measured cost per S3 call at n=131 does not exist.

For scale, a nominal idealized signed-Frobenius rho reference with automorphism size `γ=262` is `sqrt(pi*q/(2γ)) = 2.02e18 ≈ 2^60.81` group additions for one log. The [Kuhn–Struik multi-log](https://ac.informatik.uni-freiburg.de/publications/publications/sac01.pdf) shared-work approximation used by this repository's n=53 comparator gives `sqrt(2Lq/γ) ≈ 7.29e19 ≈ 2^65.98` additions at `L=1024`. These are **model references, not matched n=131 measurements or formal lower bounds**. To beat the latter with the 1 TiB row's failed scans alone, each n=131 S3 test would need to cost below roughly `2^-32.26` of a group addition, before all omitted costs. A group-addition-equivalent conversion must be measured on the same implementation; raw count ratios alone are not speedups.

## Falsifiable next experiment and decision

Freeze public synthetic target streams and base hashes at `n=19,23,37,41,53`, with at least three base sizes per rung chosen to expose nonsaturated hit rates. For each candidate record the complete `R`, `F`, subgroup order, regular slots, unique root count, `root_entries/(2nR²)`, peak RSS, failures, S3 calls per failed probe, useful rank, cold process cost and field/group-operation calibration. Run the same targets through signed-Frobenius batched rho at `L=1` and `L=1024`; include its setup, collisions, verification and memory. Hold out a second target stream and independently replay every admitted relation and recovered scalar. Treat a zero-failure run as a censored coverage estimate, not as `p=1`. The committed protocol must name seeds, input/source hashes, timeout and resource caps before launch.

The present architecture is a **no-go** for an n=131 port while its measured occupancy remains near `2nR²` and failed-query work near `2n²R²`: its optimistic 1 TiB variant cannot cover more than `2^-42.10` of random probes, and the necessary 1%-coverage variant already projects 239 PB of packed roots. Reopen it only if a reviewed replacement demonstrates both (a) an index fitting a declared practical memory budget and (b) an independently verified, full-rank, point-only cold cost below matched rho at multiple growing rungs. A larger SAT/F4/Gray-code solver can be evaluated under the same boundary, but solver-stage speed alone does not discharge either requirement. No ECC2K-130 success or speedup is claimed here.
