# Stage 19: frozen official-calculator completion panel

Stage 19 has no calculator POST or Magma result. It freezes the ten remaining named-generator inputs among the fifteen Stage 13 n=31/n=41 tasks that fit the official Magma Calculator's published 50,000-byte limit. Stages 15–17 already retain five terminals, so ten clean receipts would complete the public-service-accessible n=31/n=41 F4 coverage at fifteen of twenty frozen matrix tasks.

The protocol fixes seed-major order, one sequential worker, exactly one attempt per task, zero retries, a two-second inter-request delay, a 75-second hard parent watchdog around the service's 60-second limit, a 1 MiB response cap, and a halt after the first non-clean receipt. Network submission requires an explicit `--execute` flag. A halted run is terminal. On resume, any historical or recovered non-clean receipt prevents every later request; only a fully verified clean prefix may continue, after enforcing the retained two-second spacing boundary.

Before any request, the deterministic renderer revalidates the custody-complete twenty-task Stage 13 archive, regenerates the Stage 15, 16, and 17 expected summaries byte-for-byte, independently parses the ANF and verbose Magma sources into ordered Boolean monomial masks, and requires all twenty equation lists to agree. It then renders one named Boolean-ring generator per source variable while preserving `grevlex`, `SetGPU(false)`, `SetSeed(1)`, direct Faugere F4, `Dense := false`, and `Nthreads := 1`. Each input prints its exact task ID and source-instance SHA-256 before the seven F4 markers, preventing response substitution. The prepared plan binds every prior response, source, source-binding receipt, rendered input, protocol, and verifier dependency by size and SHA-256.

The runner records an atomic attempt-start receipt before each POST, the exact form-body size and hash, UTC chronology, execution commit/tree/binding, HTTP status, selected nonsecret headers, raw response bytes, and terminal classification. It then creates a single-use launch authorization bound to the committed plan, exact task/ordinal/input/body, attempt path, execution manifest/binding, child, and process meter. A random 256-bit nonce is inherited by the metered child while only its SHA-256 is retained in the attempt and launch authorization. The child refuses a socket unless that nonce and the exact default-artifact ledger agree, then atomically consumes the authorization first. A separately metered child performs the only POST under `process_meter.py`; the parent kills its process group at 75 seconds, the child uses a 70-second socket ceiling, redirects are refused, and reads stop at 1 MiB. The child atomically retains a raw or bounded partial response followed by its transport envelope. A crash at directory creation, after attempt start, after the transport process, after response persistence, or after envelope persistence is recovered without another request as a permanently nonclaiming receipt and terminal halt. Timeout, orphan, nonzero-child, and killed-during-atomic-write receipts hash every retained attempt file, including complete responses, envelopes, meter outputs, launch authorization, and atomic temporary remnants.
