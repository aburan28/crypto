# Stage 21: distributional relation-yield bridge

Stage 21 measures the natural two-summand relation probability for the frozen
degree-23 algebraic divisor factor base. It closes the distributional gap left
by the balanced Phase-B PDP panel: a 50/50 decomposable/nondecomposable panel
measures conditional solver behavior but cannot estimate how often a natural
collector target yields a relation.

The production profile is fixed before execution:

- Koblitz `K_0 / F_(2^23)`;
- divisor indices `[0,2]`, dimension 12, and 4,281 rational factor-base points;
- 256 natural targets generated by domain-separated hash-to-curve followed by
  cofactor projection, without constructing target scalars;
- 64 deterministic planted two-point sums;
- 64 independently generated subgroup targets certified absent from the exact
  pair table;
- all `4,281 * 4,282 / 2 = 9,165,621` canonical pairs, including repeated
factor-base points.

The planted control samples canonical pairs by deterministic priority. A target
with several decompositions therefore receives several opportunities to enter
the panel; this arm is multiplicity-weighted and is only a 64/64 correctness
control. It does not estimate a uniform distribution over decomposable targets
or natural relation prevalence.

The Wilson interval treats the domain-separated BLAKE3 natural stream as a
pseudorandom Bernoulli sample from the stated hash-to-subgroup distribution.
Accepted targets are distinct, so the draw is technically without replacement.
No finite-population correction is applied: 256 targets are about 0.000122 of
the 2,095,852 nonidentity subgroup points, making that correction negligible at
the reported precision. This assumption remains part of the interpretation,
not a proof of an independent random oracle.

The algebraic factor base is selected by the previously frozen public rule. Its
construction does not enumerate the target subgroup and does not construct
factor-base discrete-log labels. The natural arm is fully selected before the
pair table exists, so its membership outcomes cannot influence target choice.

## Evidence boundary

The Rust producer records exact arm outcomes, point witnesses, ordered public
target covariates, operation counts, internal wall timers, transcript hashes,
and retained-payload lower bounds. It deliberately leaves process CPU, peak
RSS, host identity, executable identity, and measured single-core elapsed time
unset. The Python custody runner supplies process-scoped measurements and
requires a separate enclosing outer receipt.

`single_core_seconds` in the inherited process-meter schema is a legacy alias
of total CPU time. It is not measured single-core elapsed time. The verified
summary therefore reports `single_core_elapsed_seconds: null`. The fresh Cargo
build uses one job, but simultaneous aggregate process-tree RSS is unavailable;
the admitted memory figure is the maximum process RSS seen by the enclosing
meter.

This stage does not collect a relation matrix, perform modular linear algebra,
recover a scalar, or execute Pollard rho. It does not measure SAT performance:
the complete pair table is an exact finite reference oracle. A successful
production execution is one public synthetic relation-yield candidate at
`n = 23`, pending independent payload replay. The current verifier recomputes
all JSON, row, arm, witness, and result-binding hashes derivable from the
retained payload, but it does not independently rematerialize every factor-base
point or replay all 9,165,621 curve additions. It therefore emits
`scientific_measurement_admitted: false` with status
`pending_independent_payload_replay`. It is not a scaling law, crossover,
novelty result, cryptographic-size attack, or SOTA claim.

## Planning

Planning reads and validates the frozen protocol and prints the exact inner and
outer commands without creating an evidence directory:

```bash
python3 scripts/run_koblitz_relation_yield_bridge.py plan \
  --output /absolute/new/run-root \
  --outer-stdout /absolute/new/outer.stdout \
  --outer-stderr /absolute/new/outer.stderr \
  --outer-metrics /absolute/new/outer.metrics.json
```

The run root, verification root, and all three outer paths must be outside the
implementation checkout. The outer paths must have an existing parent, must
not already exist, and must remain outside the write-once run root.

## Operational smoke

The smoke profile uses a mixed-coverage degree-7 algebraic base and exact
8/4/4 arms. It exercises the full custody path, including a fresh offline build,
but is ineligible for scientific admission. Use the exact outer command printed
by `plan --smoke --allow-dirty`; after it exits cleanly, verify it with:

```bash
python3 scripts/run_koblitz_relation_yield_bridge.py verify \
  --run-root /absolute/smoke/run-root \
  --outer-metrics /absolute/smoke/outer.metrics.json \
  --output /absolute/new/smoke-verification-root
```

The verifier reconstructs the task receipts, raw JSON outputs, executable and
input identities, aggregate resources, run inventory, and outer enclosure. It
does not trust the run summary as an accounting source. Archived identities are
currently checkout-path-bound; portable verification after relocation remains
unsatisfied and requires a successor with archive-relative identities or an
equivalent source snapshot/tree replay.

## Production execution

Production requires a clean committed checkout and the committed default
protocol. It rebuilds both the public discovery program and the yield producer
with `--locked --offline`, one Cargo job, disabled incremental compilation, and
a fresh retained target directory. It then charges two target-independent
discovery processes followed by the relation-yield process.

Run the exact outer command emitted by the production `plan` invocation. Do not
add `--smoke` or `--allow-dirty`. A complete execution first writes
`run-seal.json` with status `relation_yield_outputs_frozen`; the separate
`verify` command then requires the enclosing receipt before writing a terminal
verification seal.

Any failed, timed-out, partial, or unsealed output root is retained as evidence
and is never resumed or overwritten. A successor attempt must use a new output
root.

## Acceptance checks

A production result becomes eligible for scientific admission only after all
of these checks pass, including the still-pending independent factor-base and
complete pair-oracle replay:

- both public curve-variant discoveries reproduce the frozen cross-curve
  selection;
- the factor-base predicate, divisor, dimensions, point count, orbit counts,
  ordered point hash, and no-log boundaries match the protocol;
- the natural arm contains exactly 256 distinct targets and was selected
  without access to the pair oracle;
- the planted arm contains 64 distinct targets, every witness re-adds exactly,
  and every target independently passes subgroup membership;
- the proven-UNSAT arm contains 64 distinct targets, all absent from the
  complete pair table;
- all 384 targets are distinct across arms and retain the preregistered
  covariates;
- exactly 9,165,621 pairs were enumerated and transcript-bound;
- the Wilson interval, trials-per-relation, hashes, operation counts, timers,
  and retained-size fields are internally consistent;
- every child process terminates cleanly under its frozen watchdog;
- the outer driver receipt encloses child CPU, sequential wall time, and peak
  process RSS;
- the implementation, protocol, dependency lock, tools, executables, raw
  outputs, and complete artifact inventory remain hash-bound.

[`stage-21-relation-yield-protocol.json`](stage-21-relation-yield-protocol.json).
