# n53 target-derived regular-key rotation: held matched rank panel

This draft registers a **rank and relation-selection experiment**, not an ECDLP recovery or an IC-versus-rho benchmark. The sealed #760 certified-base training stream reached rank 220 at relation 461. The first #815 native-base attempt was censored at its base-equality gate; an uncharged post-outcome replay of its already sealed 512 training relations found rank 219, with column 102 absent. Those two historical streams motivated the policy but are not evaluation data here. Their bases differ because the certified fixture used an LCG x schedule and the native constructor enumerates x. This panel makes no same-base inference between those histories and never retries #815's first attempt.

The sole algorithmic change is `KIC_ORBIT_REGULAR_SCAN_POLICY=target_cyclic_v1`. The producer still builds the identical sorted regular-key table and canonical root index, checks the same S3 relations and full group lift, and scans every state at most once. For each finite public target `(x,y)` over `GF(2^n)`, the cyclic start is `SplitMix64(SplitMix64(x xor X) xor SplitMix64(y xor Y) xor SplitMix64(n xor N) xor D) mod regular_states`, with fixed X=`0x6b69632d78353321`, Y=`0x6b69632d79353321`, N=`0x6b69632d6e353321`, D=`0x7461726765747631` and SplitMix64's standard two avalanche multipliers given in source. It traverses the suffix then prefix of the lex-sorted key vector. The default `lex` policy starts at zero and retains the previous first-relation behavior; the new query telemetry records start and visited-key counts. The rule uses public point coordinates only. It is a scheduling experiment, not a change to the factor base or relation predicate.

## Fixed inputs and factorial controls

The 512 known-scalar target list is committed as `target_scalars.txt`, with independently computed coordinates in `target_points.jsonl`. The schedule is SHA-256 of `ECC2K53-TARGET-CYCLIC-RANK-20260925-v1/<counter>` reduced to `1..q-1`, unique and filtered against both the previous 512 training scalars and the L384 validator scalars/points. The generator checks zero scalar overlap with each earlier stream and zero point overlap with the public Q file. The exact files, generating source, previous manifest/Q inputs and hashes are pinned in `FROZEN.json` before any n53 outcome. This is a public synthetic known-scalar probe; the producer receives only the scalar file, and the independent audit reconstructs Q with separate Python group arithmetic.

Run precisely four fresh child processes, all on the byte-identical new target file and the same pinned Rust binary, in this fixed order:

| Arm | Factor base | Regular-key scan |
| --- | --- | --- |
| `native_lex` | Fresh native ascending-x construction | Lexicographic |
| `certified_cyclic` | Read-only #760 LCG certified header | Public-target cyclic |
| `certified_lex` | Same certified header | Lexicographic |
| `native_cyclic` | Fresh native ascending-x construction | Public-target cyclic |

All arms use n=53/a=0, eta=1/10, 220 signed-Frobenius columns, `orbit_factorized`, lazy relative support, `pair_then_pair`, one-hot representatives, batch-only mode, `KIC_ORBIT_INCLUDE_BASE_HEADER=1`, and `RAYON_NUM_THREADS=1`. The certified fixture is decompressed once to a hashed local input before the measured children; that preparation time is separately reported. Both native children omit `KIC_FACTOR_BASE_JSONL` and charge their own construction, setup, scan, index, query, and serialization in **full subprocess wall/user/system CPU and peak RSS**. The certified children load the same file and charge their own loading and the remaining pipeline. Within each base, the two policies must emit identical point, label and representative arrays; the two base kinds are expected to differ. The four-arm order is fixed to avoid choosing a favorable sequence after outcome, but a single pass is not a confidence interval or a cold-cache guarantee.

## Endpoints, decisions, and stop rule

Primary endpoint: independent modular rank after **all 512 scheduled targets**, counting every failed target and relation. Report `rank(target_cyclic_v1) - rank(lex)` separately for native and certified bases. Secondary endpoints: first target index attaining rank 220, independently verified representative logs if attained, zero-occurrence columns, first-pair column diversity, all 512 public scan starts, failed-target list, total S3 calls and regular keys visited, query component time, and full process wall/CPU/RSS. Do not stop when rank fills, append targets, replace failures, or tune the cyclic constants after the panel. Every produced relation must replay under the independent polynomial-field/group law, its pair intermediates and full target sum, before its row contributes to rank. The rank implementation must verify its full solution back against all representatives. A process failure, timeout, memory cap, missing raw output, audit failure or base inequality is censored/invalid and retained, not a reason to rerun the same attempt.

Advance the native cyclic policy to a **new, separately frozen fully charged log-recovery comparison** only if it reaches rank 220 by target 512, has no more failed queries than native lex, and every relation/base label passes independent replay. If native lex is also full rank, require cyclic's first full-rank index to improve by at least 32 targets and its full process wall not to exceed 1.25 times native lex before choosing it for performance follow-up. If native lex is not full rank but cyclic is, treat that as a structural lead even if wall exceeds 1.25; price the additional work before any performance claim. If neither reaches rank 220, retain the negative rank result and design a new policy rather than extending this registered stream. A certified-base gain is corroborating evidence only; it cannot substitute for the native endpoint. One process per arm yields descriptive wall costs without a statistical runtime claim.

The producer process cap is 240 seconds per arm; independent audit cap is 600 seconds; all sequential stages together cap at 1,800 seconds. Every child process group is capped below 2 GiB. The runner captures exact command/environment, inputs, source/binary/lock hashes, exit/timeout, process-group RSS, user/system CPU, wall and stdout/stderr bytes. It stops on the first process failure, and the audit replays all completed arms if all four producers succeeded. A Python setup or process-wrapper exception after the output directory exists writes a classified exception receipt and preserves any partial child files. If an abrupt OS/workflow termination leaves the last `RUNNING` snapshot, the archive verifier reports incomplete raw provenance only; neither path admits a rank or cost result. The full producer process cost is primary; Rust `charged_total_ms` omits startup/encoding/serialization and remains component telemetry. No rho process, point-log recovery, common operation unit `S`, speedup ratio, ECC2K-130 transfer, or attack-speed crossover is claimed here.

## Held release gate

`check_protocol.py` checks every pinned source/input hash, regenerates the 512 schedule and disjointness proof, validates the certified fixture, and confirms this branch descends from the final #815 result commit. It does not run an n53 producer. `FROZEN.json` remains `held_no_outcome` with `release_main_head=null`. The one-shot `run-n53-rotation-once` Actions label cannot pass this held gate. The runner refuses to execute until a separate reviewed release commit pins the current main head, an exact reviewed PR checkout is supplied through `KIC_ROTATION_EXPECTED_HEAD`, and the Linux x86_64 / Rust 1.93.1 / Python 3.12 toolchain gate passes. Any source, protocol, schedule, parent, or dependency change requires a new freeze and review before a first one-shot measurement. The final archive and scoreboard update belong to the subsequent evidence commit, whether the outcome is positive, negative, censored or invalid. The committed archive verifier rehashes every raw file, checks the frozen source/target/base identity and each completed child manifest/resource/stdout/stderr receipt, and, for a completed rank-stage claim, reruns the independent group/rank audit from those archived bytes. Censored archives receive raw-provenance classification only.
