# Direct complete-call comparison of combined F5 options

## Frozen hypothesis and reference

Three already separate opt-in changes affect different parts of the matrix-F5 call: selective echelon output avoids most back-substitution on the large degree-4 case; fused row construction avoids recounting rows; and the AVX2 table-XOR loop can accelerate elimination on x86 hosts. Their published gains are not multiplicative evidence. Measure the three options together against the current default in one frozen, paired complete-call experiment to test the user's 2× goal directly.

The unmodified source is main commit `f672329103dc2bffaecf95316b6354dbfde185c3`. The SHA-256 hashes are `fbc966fa00f3ef5bab9e49756ef6079db4dfd548f40cb48283843ba8cff3e167` for `src/cryptanalysis/matrix_f5_f2.rs`, `7598ae38a45d07a076995ad2eda10ba684730ea9ea33797c7631ffbd6e6cf388` for `src/cryptanalysis/gf2_elim.rs`, and `812fdc75bd89c7ac7944a2631158dc02bf1861fed25aa72fd629774daeb6f37a` for `examples/f4_f2_bench.rs`. Use one release binary with explicit flags in separate processes. Baseline has `KIC_F5_ECHELON=0`, `KIC_F5_FUSED_BUILD=0`, `KIC_GF2_FORCE_AVX2=0`; candidate has `=2`, `=1`, `=1` respectively. `KIC_GF2_SIMD=1` in both arms. The candidate's raw rows may differ because echelon output is a distinct, explicitly selected representation; the canonical row space must match exactly.

## Frozen workload and accounting

Use all seven matrix-F5 cases emitted by `examples/f4_f2_bench.rs` with `1 24 f5`. The primary is `f5_n24_m24_d4`. Seed XOR zero is frozen, `badc0de1` and `5eed2026` are prior holdouts, and `f5c02a28` is a fresh holdout. Pin one CPU on a Linux x86-64 host reporting AVX2, with `RAYON_NUM_THREADS=1`. An AVX-512F host is eligible; its baseline uses the existing AVX-512 default and its candidate explicitly forces AVX2. Thus the ratio applies only to the measured CPU and default dispatch, not by extrapolation to an AVX2-only CPU. On each seed, warm baseline and candidate once, take five baseline/baseline A/A pairs, then five alternating baseline/candidate pairs. No selection or rerun after seeing timings. Preserve each process's full output, exit/timeout status, exact seed, host, source and binary digest, CPU flags, affinity, load, wall time and internal phase timings.

`wall_ms` is the whole degree-bounded matrix-F5 call inside the example, including the criterion, row build, elimination and row unpacking. Process launch and fixture construction are outside this interval. Also preserve exclusive build, reduction and unpack costs, raw and canonical row fingerprints, rank, pruned rows, criterion and reduction word operations. Canonical row-space fingerprint, rank, pruning and criterion work must match baseline on all calls. Raw fingerprints must be stable within each arm; raw equality across arms is not required for echelon output.

## Decision and stop rule

For each seed/case, report the median of five paired baseline/candidate `wall_ms` ratios and the exact five-pair bootstrap 95% interval, plus its A/A range. The 2× complete-call target is met for this **one-thread opt-in solver mode** only if the frozen primary median and lower interval bound both exceed 2.00, the three holdout primary medians are above their A/A maxima, and no smaller complete-call median is below its own A/A minimum. If that passes, run a separately frozen four-thread control before considering a default or wider applicability. If it misses, stop this combination experiment and archive the negative or partial result without a timing-driven repeat. Existing default behavior does not change in this experiment. No one-target IC online time, paired rho result or DLP speedup can be inferred from a solver-stage timing.

## Pre-measurement host amendment

[CI run 36465188507, attempt 1](https://github.com/aburan28/crypto/actions/runs/36465188507/attempts/1) and [attempt 2](https://github.com/aburan28/crypto/actions/runs/36465188507/attempts/2) both reached the benchmark step on an AMD EPYC 9V45 with AVX-512F and returned `unsupported_host` before a single timing call. Both exactness-test and build steps passed, and both complete zero-call receipts are retained. The original AVX2-without-AVX-512F host restriction is therefore relaxed before measurement as stated above; the three option settings, inputs, seed set, pair count, 2× gate and stop rule are unchanged. This amendment accepts the next AVX2 host without choosing among timing samples. An AVX-512 default-versus-forced-AVX2 comparison is a direct valid comparison for that host, with its narrower scope made explicit.
