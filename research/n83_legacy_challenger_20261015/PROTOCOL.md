# N83 root22 and root21 challenger screen

This balanced screen retests two factor bases from the earlier N83 search
against the current K3300 root11 Bloom and K3596 root4 pipelines. It uses
the same executable snapshot and complete target-dependent online interval
for all four configurations. The comparison varies factor-base size, root
index layout, and Bloom profile together.

| `root21k3220` | 534,520 | 3,220 | five-byte root21, 21-byte state | off |
| `root11k3300wide3` | 547,800 | 3,300 | five-byte root11, 11-byte state | 1 GiB, three hashes |
| `root4k3596` | 596,936 | 3,596 | four-byte root4, 11-byte state | off |

The fixed order is **A B C D D C B A**, with a new process and empty
base, index, and logs for each arm on one `ubuntu-24.04` cloud allocation.
Each receives the same 1,000 new public N83 subgroup points, generated by
SHA-256 domain `n83-legacy-challenger-fresh-1000-20261015-v1`. The generator
excludes all earlier factor-base, Bloom, ABBA, high-K, and six-arm panels.
Known scalars are confined to a sidecar outside producer inputs and timing.
The target file SHA-256 is
`1603eea50d7ddebea7fe23d6c3ba7f480736f2682bcba819f5592daa8081c884`;
the sidecar SHA-256 is
`7f7c1a54562f95efbb95754190053e303a1338eca6cfd48d4339556acbca61f7`.

Each process has a 1,200-second wall cap and a 14 GiB observed peak RSS
guard; the workflow has a 210-minute cap. Preserve all attempts, source and
binary hashes, base digest, index layout, host and cgroup snapshots, phase
times, setup, RSS, stderr, and failures. An arm enters the comparison only
when all 1,000 answers, base points, and four-point relations independently
replay; its exact index checks pass; peak RSS stays within 14 GiB; and its
cgroup records zero new throttled periods and OOM kills. Missing or failed
arms make selection `BOUNDED_UNKNOWN`.

Average the two online intervals for each point and pipeline. Form each
ordered pairwise difference. Compute 99% intervals from 40 contiguous blocks
of 25 targets, with 10,000 bootstrap resamples and fixed seeds
`2026101580+i*4+j` for table positions `i,j`. Select the lowest-mean pipeline
only if its upper paired 99% endpoint is below zero against every other
pipeline. Preserve first-minus-second contrasts with seeds `2026101590+i`.
This is a secondary many-point screen; a surviving challenger proceeds to
fresh same-point Tier 1 single-target IC/rho pairs under the frozen resource
and calibration envelope in `docs/IC_BENCHMARK_TIERS.md`.
