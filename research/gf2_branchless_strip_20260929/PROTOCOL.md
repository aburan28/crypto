# Matrix-F5 branchless strip clearing: frozen one-thread experiment

## Hypothesis and reference

The pinned EPYC 7763 pivot profile in `research/gf2_pivot_phase_profile_20260929/RESULT.md` measured about 18.9 ms per n24 degree-4 elimination in the conditional strip-clear loop, the largest subphase. Each pivot currently tests one bit and conditionally XORs its strip value into every remaining strip entry. Replace this with an exact branchless XOR mask, using AVX2 four-lane updates where available and a scalar fallback, to avoid per-row conditional branches. Do not change pivot selection, matrix rows, counted word operations, output form, or other default options. Make the candidate opt-in with `KIC_GF2_BRANCHLESS_STRIP=1`; `0` is the reference.

The frozen main reference is `cec942b1c782103fba73ff4464ce2fcec4e1d6c1`. SHA-256: `src/cryptanalysis/gf2_elim.rs` = `20d2c0933daea0673f2b642226c056f8bdef8ad933614d994737e96923a1d951`; `src/cryptanalysis/matrix_f5_f2.rs` = `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da`; `examples/f4_f2_bench.rs` = `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336`. The full receipt hashes the experimental source and binary. The accepted fast path before this change is approximately 122 ms for the frozen one-thread n24 degree-4 complete F5 call on this runner.

## Workload and decision, frozen before timing

Use all seven F5 cases in `examples/f4_f2_bench.rs`, primary `f5_n24_m24_d4`, with seed XORs `0`, `badc0de1`, `5eed2026`, `f5c02a28`. Run separate reference/candidate processes from one release binary on Linux x86-64 with AVX2/BMI2, pinned to one allowed CPU and one Rayon thread. Both modes use selective echelon output, fused F5 row counting, direct packed rows, direct scalar unpack, forced AVX2 row XOR, Gray-code table reuse and no deferred-above, word-batch, AVX-512 unpack or experimental table builder. Run one warmup per mode, five reference/reference A/A pairs and five alternating reference/candidate pairs for each seed. Preserve every success, failure, timeout and OOM, source/binary hashes, host load/affinity, raw and canonical row fingerprints, rank, terms, build/criterion counts, and reduction word operations.

All seven cases must match every exact output and counted-work field between modes. Report paired reference/candidate ratios and bootstrap 95% interval for complete-call `wall_ms` and `reduce_ms`, plus A/A range, on each workload. Advance the candidate only if the frozen primary complete-call paired median is at least 1.05, the bootstrap lower bound exceeds 1.02, and no holdout or smaller case has a median complete-call regression outside its A/A range. A candidate that fails these gates is rejected and its exact patch and full receipt are archived; the opt-in runtime path is then removed. A candidate that passes is enabled by default with `KIC_GF2_BRANCHLESS_STRIP=0` retained as rollback, followed by a fresh default-on confirmation at one thread and four threads before merge.

The requested further 2× complete-call goal passes only if the frozen primary reference/candidate median and bootstrap lower bound both exceed 2.0 with the exact-output and smaller-case guards. Elimination-only gains do not count. This is a matrix-F5 solver-stage measurement, not an IC one-target online DLP or rho comparison.

## Monitor accounting correction before the fifth replay

[CI run 36653786999](https://github.com/aburan28/crypto/actions/runs/36653786999) completed all 88 exact paired calls in both one- and two-thread jobs, but failed the frozen zero-contention gate: two and three sampled intervals were marked contended, respectively. Preserve both full receipts and do not promote either wall-time ratio. One one-thread sample charged 0.25 CPU seconds to `f4_f2_bench`, a child of the measured harness. The monitor captured CPU ticks, then separately walked `/proc` for descendants; the short-lived child exited between those operations and was falsely classified as outside load. Correct the monitor by reading each process's CPU ticks and parent PID from the same `/proc/<pid>/stat` entry and constructing its descendant set from that snapshot. This changes only attribution, not the benchmark workload, solver, binary, threshold, 0.25-second sampling period, or strict zero-contention gate. A synthetic regression test must reproduce the child-exits-between-scans case. Genuine outside-process contention remains disqualifying; archive every failed retry. The next replay must pass the same 88-call exactness, preflight, empty eligible user-thread, and zero-contended-sample gates before any speed claim.

The two-second window uses the same 0.10-CPU rate threshold while still detecting sustained outside work; its zero-flag result is a different qualification rule and cannot retroactively validate any 0.25-second receipt. Split each thread count into four seed blocks. A block contains that seed's 22 processes: two warmups, five A/A pairs, five alternating A/B pairs. Each block has its own `isolated_bench.py reserve` call under the same build/benchmark lock. For each seed, make at most three attempts in order and **select the first attempt that passes**: reserve exit 0, empty `left_on_reserved.user_threads`, zero `contended_samples` under the new two-second sampling, all 22 calls successful and exact on all seven cases. Retry only on those qualification failures, never on a slow or unfavorable ratio; preserve every failed attempt, including preflight refusals and partial processes. A seed with no qualified attempt after three tries makes the thread-count result unknown, not a gain. Use `busy` for the release tests/build, and do not run other work on the same runner during a reserved block.

The two-thread blocks must satisfy the original no-regression guard. No absolute times or ratios are combined across separate hosts or thread-count jobs. This segmentation reduces the chance that unrelated CI bursts invalidate all four seeds at once; the two-second sampling period and first-clean rule are fixed before their outcomes and never selected using timing.
