# Prepared one-target source controls, version one

This registration tests the accepted target-only SAT and F5 adapters on the
already disclosed toy point `[52411,72106]`, curve
`EC1N17Ckb1hbbe2b5b6b1e6`. It authorizes exactly one new execution per family,
with both invocations and external seals retained before either execution.
All historical native registrations and the three confirmation sets remain
consumed and closed. It creates no fresh target or campaign dispatch.

The hypothesis is that each complete source-bound implementation can import
its independently certified preparation, perform only target-dependent work,
recover the scalar, and pass the preexecution-frozen mathematical/source audit.
An incomplete or failed outcome falsifies completion for that invocation; it
must not be replaced by a retry, extension, changed seed or favourable sample.
The two controls are independent admission questions, not a speed comparison.

## Execution and stop rules

Before registration, reconcile current upstream PRs, local retained prepared
directories and live/recent dispatches. No newer prepared execution was found
in this workstream at registration. The accepted implementations passed their
applicable exact-head checks; code bindings are verified again from bytes.

Use `prepared_f5_runtime_v2.py register` and
`prepared_sat_runtime_v1.py register` with the two panels, native assets and
external certificate seals. Commit the compact registration identities,
whole-invocation SHA-256 digests and preparation/native/source bindings before
executing either arm. Registration, import and source inspection start no solver.
Do not change the inputs or regenerate a consumed registration.

Launch each `execute` CLI sequentially from its own new registration and new
output directory, with its externally recorded whole-invocation digest. Run
this correctness workload through `tools/isolated_bench.py busy` so it shares
the repository's heavy-work/benchmark exclusion lock. This mode does not pin
or calibrate macOS timing. Start no local build, test suite or audit during a
native control. The fixed watchdog owns and cleans up inherited native groups.
Its atomic claim consumes the registration before setup or launch; even a
setup failure, timeout or missing final source gate closes the attempt.

The F5 invocation permits one build-identity preflight and one native target
pipeline. SAT permits one CMS version preflight and the registered per-query
export/CMS calls. Preflights are outside online work; preserve their receipts.
On a failure, retain all partial files and the registration claim, report
unknown verified online cost, and continue only the other independently frozen
arm. Never restart the failed family in this registration.

After both native controls stop, use `prepared_runtime_transport_v1.py audit`
with each external invocation seal and a new independent output. This invokes
the helper and family auditor frozen **before** execution under `-I -S -B`,
with full source/interpreter/module gates and no native solver. Preserve audit
failures separately; no audit result authorizes a native retry.

## Admission and accounting

Complete admission requires preparation replay before online start, no new
ordinary queries or native relation-LA solve, all target attempts retained,
actual family dispatch, verified group witnesses, recovery from their
coefficients, independent general-group scalar replay, and complete isolated
Python/native before/after source gates. Candidate/workload/run IDs must match
the external preexecution registration throughout execution and audit.

Keep the target-dependent interval and its five exclusive phases. All failed
target-dependent attempts and verification work are charged. Input loading,
launch, reusable geometry/log validation, fixed symbolic setup and later
independent audit remain outside the online interval. The phase sum must close
to the recorded interval; missing costs are unknown, never zero.

The host is uncalibrated and lacks Valgrind/Linux CPU reservation. Raw observer
clocks remain development diagnostics and are not comparative performance
evidence. Do not rank the two arms, compute a speed ratio, report S/floor ratios,
or call these disclosed controls fresh one-target measurements. There is no
rho/incumbent arm. `headline_online_admissible`, `fresh_paired_qualification`
and `promotion_eligible` remain false; `online_speedup` remains null.

Freeze and retain the new candidate/workload/run manifests, both original
execution trees, claims, partial/failure output, isolated independent audit
receipts, compact status/attempt/phase reports, and a durable archived copy with
digests and an extraction command. Publishing evidence must not alter the
original execution. A passing implementation or audit transport does not
substitute for complete mathematical admission.

## Remaining full-goal requirements

Complete controls establish the prepared implementations' disclosed-point
admission only. The full objective still requires natural-query evidence with
uncertainty and failed attempts correctly attributed to preparation, complete
historical/current exposure reconciliation, accepted strong one-target
references, source-bound builds for the comparison host, observer/calibration
controls, frozen resources and arm order, and a new paired fresh-target protocol.
Every primary workload in that later protocol contains exactly one new public
point. The existing confirmation sets cannot be reused.
