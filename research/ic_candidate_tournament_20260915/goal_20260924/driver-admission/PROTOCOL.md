# Driver admission integration controls

This is an accounting and correctness change, not an improvement round. The
hypothesis is that the existing `autolab.py` and `tournament.py` drivers can
produce independently reconstructible canonical records from the admitted
schema-3 optimized workers. No reference is qualified by these controls and
no performance winner may be promoted.

Use the prepared `scaled` source from `producer/prepare.py`, its exact source
manifest and the tagged release build. The native control uses two registry
entries with `pair_table`, `tiny_gauss`, three summands, one-trial collection
batches, and limits of 65,536 and 32,768 trials. The latter changes a stopping
limit; it is not asserted to improve the algorithm. Ordinary public points are
generated in separate processes. The bounded control seed is 2026092530,
with one target in each of n13a0 and n17a1 and one process repetition in the
portable screen. Rho widths 1, 8 and 32 and an A/A copy are retained.

Also run an n13a0 control with a one-trial IC arm, reusing the sealed native
executable. Expect collection exhaustion and a retained canonical failure with
null verified timing/costs. Its repeated incumbent workload must have a distinct
run ID. The final Linux control executes this six-job failure screen as well.

The Linux driver control additionally freezes the existing pilot tournament
with n13a0 development and n17a1 holdout cells, three repetitions, and the same
two IC configurations. Exercise A/A and smoke only, then independently audit
with its frozen evaluator. It is a wiring test, not the goal's five-cell,
60-target confirmation. Record prepared-but-unexecuted stages explicitly.

Success requires every scheduled control's independent point/scalar-field
certificate, strict nonempty IC descent, exact source and actual kernel
binding, immutable candidate/workload/run records, and native online closure.
Profiled jobs additionally require all scientific phases and their independently
collected whole-process checksum. Reconstruct every record from the frozen
inputs and raw artifacts. Deliberate corruption tests must reject changed
targets, identities, timing, sources and ledgers. Failed jobs retain a canonical
key with null complete costs and null verified online timing.

The primary timing interval is one public point, after reusable preparation
through scalar replay; fixture construction is excluded. Complete cold native
time and Linux Valgrind 3.22 amd64 instruction counts are supplementary and
remain separate units. macOS controls use the host target with the explicit
empty `CARGO_ENCODED_RUSTFLAGS` build override recorded in the candidate; they make no
calibrated Linux performance claim. Native CPU affinity and memory caps stay
unknown on that host. On Linux use one pinned CPU, 8 GiB and a 180-second job
limit. Keep source, executable, evaluator, raw reports/profiles, receipts,
rejected attempts, and summaries. Stop on a wiring/certificate failure and
retain the failed output; a corrected replay uses a new output directory.

The first macOS control stopped at linking: an empty Cargo configuration array
merges with the archived Linux linker flags instead of replacing them. Retain
`native-v1/build.log`. The corrected control uses a declared empty
`CARGO_ENCODED_RUSTFLAGS` environment override and a fresh `native-v2` directory.
This is a portability fix; no measured jobs completed in v1.

The second native preparation (`native-v2`) compiled successfully but stopped
before timing: the canonical writer correctly rejected a floating-point process
duration. The driver now stores process measurements as ordinary immutable raw
JSON while retaining strict canonical identity records. `native-v3` completed
12/12 native controls and its frozen audit. Later driver-only checks reuse the
same sealed executable in fresh directories; they remain fixed-input controls.
