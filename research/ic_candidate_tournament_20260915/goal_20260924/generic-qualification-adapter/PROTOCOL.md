# Mixed-adapter integration control

This tests the existing tournament's generic-worker connection. It is not the
five-cell reference qualification, an observer-overhead study, or an improvement
round. It cannot promote a candidate or change the accepted archived incumbent.

Use the existing prepared `scaled` producer as the control incumbent and a new
controlled `generic_build.py` build. Freeze all source/build/binary identities.
On n13a0, use seed 2026092662, one supplied public point per job, three process
repetitions, and only A/A, smoke and development. The existing fixture generator
produces one A/A point, one smoke point and three development points; no selection,
confirmation or replay targets are generated. Retain every exposed fixture for
exclusion from later research confirmation. The unmeasured CLI holdout n17a1 is
not generated or inspected by qualification mode.

Register four IC configurations: prepared pair_table/tiny_gauss/m3 and generic
pair_table/m3 with dense LA, sparse LA, and dense LA limited to one collection
attempt. Other arms use max_trials=65536; all use batch_trials=1. The inherited
subgroup_orbits recipe is seed43, requested points6n, with actual support and
folded columns independently audited. Support policy is a declared variable.
The one-attempt generic arm cannot reach the multi-column full-rank gate and must
remain incomplete. Rho widths1 and4 run from each of the two distinct source
snapshots, including actual clipped width. These are wiring controls, not a rho
sensitivity screen or a globally best reference selection.

Use Linux amd64, Rust1.94.1 and Valgrind3.22.0, one pinned CPU/one Rayon worker,
8GiB and 180seconds per process. The maximum is120 measured trial slots. Exactly
102 are scheduled: six A/A slots plus24 smoke and72 development slots. Ninety
must have verified native/profile pairs; twelve budget-arm profile attempts must
remain incomplete, without executing a native solve or acquiring a complete cost.
The CI job has a90minute deadline including source preparation/build and other
controls. Preserve interruption, timeout, OOM, failure, build logs and raw profiles;
no failed measured process may be retried or overwritten.

Inventory freezes candidate/reference identities without querying or solving the
supplied target. The worker reports the selected packed arithmetic kernel and
labels inventory as configuration-only. Actual runs independently bind build,
dispatch, factor-base support, query law, stored matrix, rank, all failed attempts,
descent and final scalar replay. Native and profile executions get distinct IDs.
Both use one frozen workload identity, shared with the prepared producer.

Primary timing is one-target native online time after reusable preparation through
scalar replay. Full process wall time and user-space Callgrind Ir are supplementary.
All exclusive phase intervals must close, with unknown costs remaining null on
failure. No timing under Callgrind becomes a native measurement. All instrumentation
costs stay charged; this control does not establish uninstrumented performance.

Success means all90 intended complete pairs pass, all12 intentional failures are
retained and disqualified, and the transported frozen evaluator independently
reconstructs every record and qualification summary. Verify the same campaign
without launching any worker again. Report only these control outcomes. Any
numeric rankings generated by the existing development summary remain control
diagnostics and cannot enter the research scoreboard as qualified speedups.
