# Fresh paired one-target IC tournament: implementation design

This is a design for the **next** registration, not a frozen protocol or a
measurement. It does not reopen any consumed registration. The SAT arm is
eligible only if the original, already running 512-query preparation finishes
and its frozen data-only audit establishes rank 29/29, complete independently
replayed logs and complete source/runtime custody. A partial or failed panel
remains a result; it cannot be refilled by F5 rows or old SAT outputs.

## What the tournament must answer

For a previously unseen public point on the same exact n17 subgroup, measure
whether a complete index-calculus candidate recovers and independently
verifies its scalar, then compare its **one-target online** wall interval with
the same-point strong rho solve. Preserve every failed attempt. Candidate
identity must describe the entire pipeline, including its actual 62 usable
base points, 29 folded columns, point-decomposition solver, collection,
matrix solver and target policy. Give every fully bound method an `IC1` ID and
every paired point a workload ID under `AGENTS.md`; use proposal IDs until
the code, preparation and factor-base digests are settled.

The first comparison is an admissibility and correctness test. A performance
claim additionally needs an isolated-host receipt satisfying the
`cryptanalysis` repository's `docs/ISOLATED_BENCHMARKS.md`. Mac timings may
diagnose stage costs but cannot establish a controlled CPU speedup.

## Source, preparation and point custody

1. Independently audit the original SAT preparation. Bind its source seal,
   producer bytes, mathematical-input digest, all 512 outcomes, rank and
   verified logs. Bind an independently complete F5 preparation in the same
   way. Neither arm may import the other arm's relation rows or logs.
2. Freeze the target-capable worker, native roles, independent checker,
   build receipts and candidate manifests **without a target point or known
   scalar**. Publish and replay the complete unconsumed archives as data,
   then commit and push their external seals. A published source hash must
   precede every point exposure.
3. Only after publication, make a card for each fresh public point containing
   the exact point, curve ID, point-generation receipt, frozen workload law
   and source publication hashes. Derive each point from a newly recorded
   seed by a declared hash-to-x, curve lift and subgroup-cofactor procedure;
   verify that it is nonidentity and in the declared subgroup. No known
   scalar is needed or given to a solver. Record each card hash before any
   arm launches. For each one-target solve, the same card is the sole input
   to SAT, F5, the incumbent and strong rho.
4. Give each candidate/run a separate create-only consumption claim. Each
   worker must load only its sealed preparation and the public point, retain
   a durable start/completion record before and after every native attempt,
   and drain all exporter, SAT and auditor process groups. A failure is a
   terminal row for that run; never retry under the same run ID.
5. The independent checker replays each point query, full-point witness,
   projection, matrix logs, scalar recovery and final multiplication using
   arithmetic separate from the producer. It checks native binary/source
   pins, role arguments, ANF/CNF/model bytes, receipt chronology, failed
   attempts, all exclusive clocks and original execution inventory without
   invoking any solver. It records target exposure and distinguishes an
   audited online interval from an isolated-host performance claim.

The existing registered F5 point predates this exposure sequence and is a
useful correctness control, not a fresh paired holdout. The earlier rho
solve on that point is likewise exploratory.

## Tournament decisions

| Stage | Recorded evidence | Gate |
| --- | --- | --- |
| Factor base and preparation | Geometric points, distinct usable subgroup points, orbit columns, construction cost/memory, all ordinary-query outcomes, verified relations, novel-rank trajectory, complete logs | Exact base digest and rank/log replay; failed and zero-yield queries remain in the denominator |
| Target PDP and descent | Every seeded query, exporter and F4/F5/SAT status, native output, full-point lift, recursive attempts, exclusive online phases | Verified scalar on the supplied point; incomplete and timed-out attempts are charged |
| Final relation LA | Exact sparse matrix, modulus, rank, solver family, setup and solve costs | Independent row and recovered-log replay; internal F4/F5 Macaulay reduction is charged to PDP |
| Paired comparison | Same point, order-balanced arm runs, worker count, resource limits, source hashes, host receipt, rho certificate | Compare verified one-target online wall times; missing costs or failed solves give no speedup |

Screen multiple candidate families on a development point set, retain a
diverse set of promising complete pipelines, and lock the final family and
settings before a disjoint paired holdout. Stage-only wins do not eliminate
an end-to-end candidate: retain alternatives on a Pareto frontier of online
time, preparation cost, failure rate and memory. Freeze the selection rule,
number of candidates, point count and familywise inference method before
the holdout. Report paired per-point ratios and uncertainty, including any
slower points and failures. Do not substitute batch throughput, a planted
decomposition, a favorable subset, or a post-hoc local winner for this test.
