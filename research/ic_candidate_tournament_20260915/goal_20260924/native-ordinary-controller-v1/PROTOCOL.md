# Native ordinary preparation controller v1

Status: source implementation, bounded controls and a passing validation-only
offline freeze with [full data custody](BUILD_VALIDATION_RESULT.md). No scientific
registration, panel, runtime admission or fresh comparison is executed by this change.
Depends on worker PR #1344 and preparer PR #1342. The full complete-solver goal
remains active; the old SAT/F5 controls and three confirmation sets stay closed.

The hypothesis is unchanged: actual MatrixF5 and accepted external CryptoMiniSat
must generate their own fixed natural ordinary-query panel and reusable factor
logs on the disclosed educational n17 instance. Preparation is target-free.
The proposed future panel remains 512 queries with seed 2026100311, three
summands, standard dimension six, 63 geometric points, 62 usable projected
points and 29 folded columns. Those numbers are independently checked, not
assumed from nominal dimension. Known historical decompositions are controls,
never yield estimates. No scientific invocation is authorized by a unit test.

Freeze copies the complete source, local Cargo.lock and compile-time documents,
vendors dependencies offline, rejects ancestor Cargo configuration, and builds
both worker and independent controller/auditor from that new immutable tree.
Compiler/Cargo hashes and versions, exact build arguments/environment, source
manifest, binaries and compiled worker identity are retained. The native CMS
arm additionally retains the accepted archive/manifest and its verified
extracted files. Freeze invokes only build tools and the worker's identity
command. Validation-only registrations cannot execute.

The build-only custody extension adds `ordinary-control-publish-build` and
`ordinary-control-replay-build`. The first retains the exact sidecars, receipts
and a complete plain USTAR gzip archive from an unconsumed validation capsule.
The second requires the external validation seal, verifies every byte and all
original source/build/asset bindings as data, and launches no archived binary.
The real build and the two retained failed attempts are documented separately;
archive custody is never source-bound scientific execution admission.

Execution requires the external registration seal and its own frozen controller
binary. It creates the execution directory and durably consumes the registration
before the sole launch. The exact worker argv, environment, outer deadline,
stdout/stderr, PID ledger and process-group drain are recorded. All escaped
native children are drained even after an outer timeout or transport error.
After drain, the controller inventories all execution files; the frozen auditor
requires that exact inventory before interpreting the producer or original
receipts. Save inspection and audit outputs outside the execution directory.
Terminal source/drain/transport failures remain records; there is no resume,
retry, refill or imported-log fallback.

The durable prefix is not a complete panel. Each completion must follow its
matching start; an outer interruption can leave one final start without a
completion. Prefix inspection checks chronology, frozen scalar law and file
shape without admitting source-runtime custody. A complete panel still needs
the frozen independent audit of worker and role receipts, original SAT source
models, all mathematical outcomes, rank/log replay and exclusive phase costs.
Failure to prove any gate leaves admission and costs explicitly unknown.
The full audit checks the actual build-receipt pair encoding, compiled build
pins and flags, complete phase-key schema and aggregate closure. It compares
the producer's sparse rows and column order with the independent group-derived
rows, so a correct recovered scalar cannot conceal a defective row builder.
Aggregate producer evidence retains hashes and lengths; original ANF/CNF/model
files remain per-query artifacts and must pass the audit directly.

Only the registered environment (`LC_ALL=C`, `RAYON_NUM_THREADS=1`) is passed.
The source's environment-controlled preprocessing/reduction/parameter caches
are disabled when their keys are absent; no ambient environment is inherited.
The reusable collector within this one process is intentional. Current native
assets are macOS ARM64 only. Portable source/transport controls do not establish
other native solver runtimes or physical CPU performance.

Scientific registration/publication must precede dispatch. The actual new
natural-panel outcome, failures, novel-rank trajectory, cost per useful row,
memory/resource evidence and independent preparation acceptance remain pending.
Fresh target exposure/IC1/workload registration and same-point one-target online
ecbench comparison with the incumbent and strong rho follow preparation. All
target-dependent attempts and independent scalar verification belong inside the
online interval. CPU speedup promotion additionally requires the user-specified
auditable host isolation/noise receipt. No build, transport or mathematical
control closes those complete-solver/comparison gates.
