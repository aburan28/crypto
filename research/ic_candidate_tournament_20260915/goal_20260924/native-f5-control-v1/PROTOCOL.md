## Freeze and invocation

```mermaid
flowchart LR
  P[Sealed historical preparation] --> F[Freeze committed Rust source and offline dependencies]

  W --> A[Native bounded F5 attempts and producer scalar replay]
  A --> R[Raw output, watchdog receipt and process drain]
  R --> I[Frozen independent transport and mathematical audit]
```

Freeze requires a clean committed source set and retains all `src`, the actual
`examples/ic_tournament_worker.rs`, Cargo manifest and exact lockfile, compiled
JSON/SQL resources and offline vendored dependencies. It builds only from that
snapshot with an empty Cargo home, explicit compiler and a fresh build target.
It rejects unregistered ancestor Cargo configuration: an empty Cargo home alone
does not prevent Cargo from reading ancestor flags or wrappers. Compiler/Cargo
versions, commands, environment, file hashes and original build logs are retained.
The source inventory and build descriptor are bound into the worker at compile
time. A build-identity-only call checks that binding without receiving a job.
Compiler, Cargo and frozen source hashes must stay unchanged through the build.
`--validation-only` produces a build-validation capsule that the dispatcher
rejects. This mode permits an end-to-end freeze/build check without creating
another potentially executable scientific invocation.

The capsule includes the source/dependency/binary inventory, exact config,
whole preparation, mathematical-only job, physical host context, worker and
checker hashes, declared environment and registration seal. Actual registration
publication and durable archive/custody replay are separate gates before any
scientific invocation. A local capsule path alone is insufficient publication.
Only the macOS ARM64 disclosed control is executable under this protocol;
other hosts run mathematical and transport tests, not archived binary fallbacks.

The worker receives only the public point, 63-point geometry, 29 column logs,
state seal and exact solver limits. It receives no historical queries, witness,
target answer, certificate proof or previous target timing. Input target seeds
are `[]`; supplied-point output provenance is `[null]`. These distinct shapes
must stay distinct. Runtime environment is exactly `LC_ALL=C`,
`RAYON_NUM_THREADS=1`, `IC_ARTIFACT_CACHE=off`, `IC_F2_BACKEND=cpu`, with ambient
variables cleared. The factor-base and log validation and symbolic preparation
finish before target-dependent timing begins.

Dispatch must use the frozen controller binary and explicit externally published
registration seal. A synchronized create-only claim consumes the capsule before
the child starts, including setup failure, transport error or interruption.
There is no resume route. Never restore an archive to bypass a consumed claim.
The worker receives exact registered stdin bytes, no command-line job overrides
and a bounded process group. Nonblocking job delivery keeps the deadline active
when a child never reads. The raw output/error, input hash/delivery count,
environment, executable pre/post hashes, PID ledger and drain receipt are retained.
The terminal record preserves transport and source-gate failures.

## Independent audit and timing

Only the preexecution-frozen checker can perform original admission. It checks
the immutable source tree, inputs, claim, sole PID ledger, exact argv/environment,
stdin hash and complete delivery, stdout/stderr hashes, executable identities,
timeout/output-limit/drain flags, exit status and compiled producer build identity.
It then uses the independent target verifier for the seeded query law, complete
geometric negatives, witness group addition, cofactor projection, recovery and
scalar replay. A test fixture cannot be admitted as a scientific report.
The auditor starts no native child and writes its output once.

The five exclusive producer phases are target query, PDP (including all failed
and timed-out attempts that return a report), relation check, target descent and
recovery check. A successful target requires all five integer slots and exact
closure; incomplete unperformed phases remain null. A worker killed before a
valid report leaves online scalar and complete cost unknown. Exit 0 means a
completed report and exit 2 an incomplete report. Source-bound execution
admission and target completion are separate fields.

External independent audit time is retained separately from the original
producer interval. This disclosed control has no matched rho/incumbent, calibrated
resource envelope, A/A uncertainty or operation calibration. Its producer timer
is a diagnostic and cannot establish the primary independently verified online
speed claim. Fresh qualification, headline eligibility, promotion and full-goal
completion remain false; speedup remains unknown.
