# Native target worker and durable attempt files, version 1

This extends PR #1362 for the exact disclosed educational n17 fixture. The
full goal still requires native source-admitted preparation for both families,
complete target execution/audit and a fresh paired incumbent/rho comparison.
This source stage runs no F5/SAT search or scientific registration and does not
reopen any of the three closed confirmation sets.

Hypothesis: the F5 recording entry can be connected to a new frozen worker and
exclusive fsynced attempt files, and a data-only reader can preserve a pending
query after abrupt writer termination. Reuse the existing native file creation,
bounded reads, immutable inventory and watchdog/drain implementation. A target
capsule has its own scope, source/build identity, preparation input/audit pins
and consumed execution claim; an old ordinary or target-control capsule cannot
authorize it. A development binary, validation-only registration or missing
compiled identity must fail before solver invocation.

Controls use synthetic record payloads only. Success requires exclusive start
and completion files with file and parent-directory fsync, frozen seeded
coefficients and target binding, chronological completion linked to its start,
no overwrite/resume after a failed write, bounded prefix inspection, rejection
of altered/missing/wrong-family records, and a retained pending start after a
watchdog kills a control process that writes no cryptographic computation.
Preserve failed tests and original process receipts. Stop on source assertion
or compilation failures and fix them before rerunning. Run all builds/tests,
parsing and watchdog controls through the shared busy wrapper.

The first actual worker integration selects the bounded F5 recorded API. Its
setup and input loading precede online timing; target-dependent record writes
remain charged in the target API's five-phase interval. Worker callbacks cannot
grant runtime admission. The file journal also supports the SAT record shape,
but no cold per-query CLI adapter is admitted as a primary online SAT solver.
The accepted exporter CLI takes query coordinates at launch; complete SAT
integration therefore still needs an accepted preinitialized native transport
whose target-independent launch/loading is outside the headline interval.

A preparation receipt is a pinned prerequisite, not self-proving evidence. The
future independent complete-run auditor must verify its original frozen source,
native execution, natural query yield, all failed attempts, final rank/logs and
custody against the external preparation seal. The new target controller/freezer
must publish its own registration before any sole scientific dispatch and audit
the original native worker, source/build identities, exposure and watchdog
receipts. Structural prefix inspection launches no solver and never promotes a
partial run or proves a source UNSAT claim.

Canonical identities, accepted new preparation/target seals, source-bound
complete-run audit, fresh paired targets and strong same-point rho, operation
and memory accounting, and host isolation/noise receipts remain pending. No
speedup, native yield or complete solver admission is claimed by these controls.
The failed historical CI job is retained separately: it builds a mixed current
crate/old module and lacks embedded files. Do not rewrite its frozen manifest,
rerun its closed panel or interpret that failed build as a scientific outcome.
