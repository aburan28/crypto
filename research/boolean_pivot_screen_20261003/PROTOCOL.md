# Frozen proposal: sibling Boolean pivot-trace feasibility screen

## Question and boundary

A prior indexed support envelope reconstructed changing-coefficient matrices, but its [qualified discovery](https://github.com/aburan28/crypto/pull/1190) cleared 0/32 of the declared 2x construction groups, and the five-arm comparator omitted the stronger packed-direct constructor. Before implementing another cache, test the mathematical precondition for a row-space update after a Boolean branch. For a quadratic system F and variable x_j, let F_0 and F_1 be its exact restrictions at x_j=0 and x_j=1. In the Boolean quotient, F_1 + F_0 is the Boolean derivative in x_j, affine in the remaining variables. That low polynomial degree does not by itself imply a low-rank change in their degree-3 Macaulay matrices. Measure the change rank and pivot-trace stability exactly.

A future timed candidate must compare against the pointwise fastest correct matched construction-plus-elimination control, including packed direct for n<=12 and both ranked-dense and ranked-sparse constructions at larger n. It must charge all delta work, trace verification, fallback, elimination, output validation and destruction in the same binary and resource envelope. This screen does not time or claim such a candidate. Full solving, relation yield, memory at cryptanalytic scale and rho cost remain null.

## Exact matrix contract

Generate public quadratic Boolean systems with n in {8,12,16,20,24}, m=n, degree bound D=3. Reset a 64-bit SplitMix64 state to the seed for each size. Each `next` wraps all arithmetic modulo 2^64: add `0x9e3779b97f4a7c15`; let `z=(state xor (state>>30))*0xbf58476d1ce4e5b9`, then `z=(z xor (z>>27))*0x94d049bb133111eb`, then return `z xor (z>>31)`. This is the transition used by `boolean_packed_construction_20260922/worker.rs`. For each of n generators, repeatedly draw `a=next()%n` and `b=next()%n`; discard equal indices and add `(1<<a)|(1<<b)` to an ordered set until it has exactly 2n distinct quadratic terms. Draws continue across generators without reseeding. No planted solution, curve input, scalar or target is used.

For each system restrict four fixed variable indices 0, floor(n/3), floor(2n/3), n-1 to both values. Remove the restricted bit and shift higher variable bits down by one, so both branches use the same n-1 variable names. Represent products with squarefree multiplication as bitwise OR and coefficient cancellation as XOR. A pair is replay-eligible only if every generator has the same degree in both branches; otherwise count a guarded fallback. For an eligible pair, the generator-then-numeric-multiplier row skeleton is identical. Keep zero rows as labelled slots for trace comparison, although the canonical matrix oracle omits them. Columns are all monomials of degree at most D in **descending numeric order**, matching the F5 pivot convention; the oracle compacts to actual occupied support when comparing returned matrices. Rank and row-space fingerprints must agree between the labelled and canonical forms for each branch.

Let M_0 and M_1 be padded ambient matrices on that shared skeleton and Delta=M_0+M_1. Use independent bitset Gaussian elimination to compute rank(M_0), rank(M_1), rank(Delta), and deterministic leftmost-pivot traces. At each column in descending numeric order, take the least eligible row index at or after the current pivot position with a one, swap it to the pivot position, and XOR it into every later row with a one in that column. Record every selected column and source row index, including skipped columns. A replay is structurally viable only if each scheduled pivot remains nonzero, no earlier skipped column becomes a pivot, and a complete fresh reduction of M_1 selects the **same columns and source row indices**. Report weaker column-only survival separately; equal rank or equal pivot columns alone is not a replay certificate. Compare each matrix and rank with a set-parity product oracle on every fixture. Fail closed on any shape, cap or equality discrepancy.

## Frozen sample and stop rule

Discovery seeds: 20261003, 3141593, 2718281, 1618033. Holdout seeds: 20261010, 4242421, 5772157, 1414213. Each seed yields one n-variable system per size and four paired branches; 80 pairs in each split. Cap every case at 4,096 rows and 8,192 columns. Before seeing holdouts, archive complete discovery raw rows/ranks/traces and a source/protocol digest. If any oracle check fails, reject. If fewer than 80% of nontrivial degree-stable discovery pairs at n>=12 have rank(Delta) <= rank(M_0)/8 and an identical full pivot trace, reject replay as an unattractive 2x candidate without running holdouts. This is a conservative feasibility screen, not a lower bound or proof of eventual speedup. If it passes, freeze the worker and run the untouched holdouts; the same condition must hold there before a separate implementation/timing protocol is opened. Report fallback frequency, change-rank distribution, trace survival, matrix dimensions, exact work counts and memory. All timings stay null in this structural study.

Preserve failed attempts, source/binary hashes, host/resource records, immutable raw data and a native Rust verifier. Use Rust for producer, tests and replay; shell only for thin orchestration. Any later implementation of incremental elimination gets new seeds and must compare complete construction+elimination against same-binary packed direct/ranked sparse, then complete solver and rho only when those costs are actually measured. No curve or key input is admitted.
