# Bounded current-weight F5 pivots: frozen structural and paired screen

## Distinct hypothesis and reference

The [unbounded current-weight experiment](../gf2_minweight_pivots_20260929/RESULT.md) reduced frozen n24 degree-4 output from 13,734,979 to 7,216,068 terms but slowed the complete call: it rescanned all remaining rows at each pivot and recomputed every changed row's weight after table updates. The [initial-density sort](../f5_initial_density_order_20260929/RESULT.md) avoided update recounting but cut terms by only 3.5–3.9% and missed its gain gate. This experiment tests a narrower algorithm: after finding the next pivot column by the existing rule, consider only the first `K` eligible rows for that column (`K=8` or `16`), count their **current** suffix popcounts on demand, and take the lightest, breaking ties by row order. It never maintains weights for the other rows. Charge selection and counting to elimination and the complete call. The output can differ as an echelon basis, but rank and canonical row space must agree exactly. This is an opt-in research route while the returned-row contract remains undecided.

The frozen reference is merged main `4877c7577d7a164e7de0dededa3c1b7486f4ff35`: `matrix_f5_f2.rs` SHA-256 `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da`, `gf2_elim.rs` `6fd3f10ef8e681490784c624e703eeb8fa887c5817ec9bdf34844e3f943c7f5c`, benchmark `f4_f2_bench.rs` `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336`, isolation wrapper `ff59e53fd5566078ad493c8be0d06168699c4fd194bc881d99df19fa20e007ef`. The most recent qualified x86 exact-output reference was 106.680 ms on an AMD EPYC 7763 in [run 36679082741](../f5_x86_guarded_unpack_20260930/RESULT.md); that standalone time is context only and is **not** a candidate denominator. New timing must use same-binary pairs.

## Candidate and frozen work

`KIC_GF2_PIVOT_CHOICES=0` keeps the reference. `=8` or `=16` applies bounded current-weight choice only to echelon elimination with at least 4,096 packed rows and 4,096 columns; all other matrices and RREF use the reference rule. The choice scans only enough strip entries to find the first `K` rows containing the selected pivot bit, then popcounts the current suffix of those candidates; it does not sort the input or recount rows during table application. Record an actual route indicator for the primary case. One release binary and fresh processes per arm prevent environment caching across arms. Keep selective echelon, fused row counting, direct packed build and scalar unpack, branchless AVX2 strip where present, AVX2 row XOR, four Gray-code tables, and table reuse. Disable deferred-above, word batching, AVX-512 unpack, and experimental table construction. Use one Rayon thread for the local screen.

The seven F5 cases from `examples/f4_f2_bench.rs` and seed XORs `0`, `badc0de1` are the local structural and paired workloads; `f5_n24_m24_d4` is primary. Correctness requires unchanged rank, canonical row-space fingerprint, F5 criterion count, built/pruned row counts and columns for every case. Raw row fingerprints, output term counts and reduction word XORs may differ only where the new route is selected. Unit tests compare small random/sparse/dense/partial-word echelon rank and canonical RREF with the reference for both `K` values. All processes, failures, timeouts and OOMs remain in the receipt.

First build and test with `tools/isolated_bench.py busy` and run **one untimed-for-decision process per arm, per seed and K**. Preserve its full JSON output, source/binary hashes, host and route. Selection is deterministic: use `K=8` if both seeds return at most 75% of their baseline primary output terms; otherwise use `K=16` if both do; otherwise reject without a timing claim. Do not choose based on observed wall time. If a correctness or route check fails, reject. This structural gate asks whether bounded choice captures at least half of the unbounded term reduction; it is not a speedup claim.

If the structural gate passes, run a local Apple ARM64 paired screen on the selected `K`: per seed, one warmup per arm, five reference/reference A/A pairs, then five alternating reference/candidate pairs. Preserve process stdout/stderr, all seven cases, host/load, source and binary SHA-256, route, exclusive phases, complete-call time, counts and fingerprints. Run measured processes through `tools/isolated_bench.py reserve` if this host can reserve a core. With qualified isolation, advance to x86 only if both primary seeds have paired complete-call medians at least 1.05 and no smaller case falls below 0.95. If the host cannot provide qualified isolation, mark ratios exploratory: reject only if both primary medians are below 0.90 or correctness fails; otherwise advance to x86 for a qualified decision without claiming a local gain. The at-most-75% term gate applies in either case. A local rejection removes the opt-in runtime path after archiving its exact patch, harness and raw receipts.

A passing local candidate must then use Linux x86-64 AVX2/BMI2 with a pinned reserved CPU, one- and two-thread jobs, seeds `0`, `badc0de1`, `5eed2026`, `f5c02a28`, five A/A and five alternating A/B pairs per seed, first-clean selection, zero eligible user threads and zero contended samples. The incremental x86 gate is a one-thread frozen complete-call median at least 1.10 with exact 3,125-resample bootstrap lower bound above 1.05, no smaller-case or seed median below its own A/A minimum, and no two-thread regression. The user's further 2× target requires frozen full-call median **and** lower bound above 2.0 with all guards. Output-basis promotion additionally needs confirmation that row-space-equivalent output is an acceptable caller contract. These are Boolean matrix-F5 solver-stage diagnostics, never IC one-target online DLP or rho speedups.
