# Protocol: does any non-generic ECDLP method see the endomorphism conductor?

Frozen 2026-10-10, before any ecbench session on these specs. **Stage
diagnostic.** No speedup is claimed; the null hypothesis is the one the
Lean-provable theorem states for generic methods (README §4).

## Question

Two curves over the same `GF(q)` with the same prime order `N`, the same
trace `t`, the same Frobenius discriminant `t² − 4q = −19·ℓ²`, differing in
exactly one invariant: the crater curve has endomorphism ring `O_K`
(conductor `f_E = 1`), the floor curves have conductor `f_E = ℓ`, with `ℓ`
a prime of 9 to 17 bits. Does the paired cost ratio

    S(method) = cost(floor) / cost(crater)

differ from 1 for any method ecbench runs?

## Pre-registered predictions

- Generic methods (`rho.*`, `bsgs.*`, `kangaroo.*`): `S = 1` within the
  bootstrap interval, at every `ℓ`. This is a theorem (README §4), so a
  deviation is a harness fault, not a discovery.
- `ic.pipeline` with `prime-abscissa` factor base and `mitm` oracle: the
  factor base is a set of x-coordinates and the decomposition is a
  search over the group; neither reads the endomorphism ring. Prediction
  `S = 1`. A confirmed `S ≠ 1` at the exponent or constant level would be
  the first evidence that an implemented method sees the conductor, and
  would be followed by a fresh pair at a different `ℓ` before any claim.

## Decision rule

A method "sees the gap" only if, on two independent specs at different
`ℓ` (ℓ = 263 and ℓ = 8209), the paired bootstrap interval of
`log₂ S` excludes 0 with the same sign, and the A/A control arm's interval
includes 0. One spec alone is a lead, not a result.

## Specs

`specs/gap-ell263-q19.json` (19-bit q, every method), `specs/gap-ell8209-q29.json`
(29-bit q, generic methods), `specs/gap-ell131101-q37.json` (37-bit q,
generic methods, one floor curve so far). Each spec lists the crater first,
then the floor curves, as `prime_explicit` constructions generated by
`make_spec.py` from `results/*.txt`; the generator is deterministic
(smallest x with a square right-hand side, smaller y).

## What is not measured here

Walking the ℓ-isogeny between the levels. For `ℓ ≥ 263` the degree-ℓ
modular polynomial is out of reach, which is why the pairs are built by
CM, not by walking. A method that *needs* the isogeny to exploit the
conductor is outside this protocol's scope.
