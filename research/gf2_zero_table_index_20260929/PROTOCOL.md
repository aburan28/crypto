# GF(2) table zero-entry selection: frozen matrix-F5 experiment

## Hypothesis and source

The shared GF(2) Method-of-Four-Russians row-clear loop computes up to four table offsets per row and then divides each offset by the runtime suffix length to decide whether it addresses a table's zero entry. The offset builder already knows each table's zero-entry base. Compare the offset directly with that base and advance the base by `table_size * suffix`; keep every table, pivot, row, counted XOR and output bit identical. This may remove runtime divisions from a hot loop after branchless strip clearing. The candidate is opt-in as `KIC_GF2_ZERO_GROUP_INDEX=1`; `=0` retains the exact existing check. The code path serves all shared Macaulay solvers, but this experiment's timed primary is matrix F5.

The frozen source is commit `154faab572a133425a031b0ae76a520a939a85a9`, merged as PR #998. ## Frozen paired method and decision

Run all seven F5 cases in `examples/f4_f2_bench.rs`; primary `f5_n24_m24_d4`, seeds `0`, `badc0de1`, `5eed2026`, `f5c02a28`. Compare one and two Rayon threads separately. Hold selective echelon output, fused row count, direct packed rows, branchless AVX2 strip, AVX2 row XOR, table reuse and direct scalar unpack fixed. Disable deferred-above, word batching, AVX-512 unpack and experimental table building. Per seed and thread count, run one warmup per arm, five A/A reference pairs, and five alternating A/B pairs: 22 processes and seven cases each. Preserve every call, failure, timeout and OOM; record source/binary hashes, host, affinity, raw/canonical fingerprints, rank, output terms, rows/columns, criterion/build counts, reduction word operations and exclusive phase/full-call times. The shared `gf2_elim` and F5 release tests must pass under both flag values, including partial table groups and zero entries.

Build and test under `tools/isolated_bench.py busy` with one lock. Run each seed's timed block through privileged `tools/isolated_bench.py reserve` with all SMT siblings reserved, one CPU left free, a ten-second preflight, outside CPU rate at most 0.10, CPU PSI at most 5.0, zero user threads eligible on reserved CPUs and zero contended samples at a **two-second** period. Pass the runner's Rustup home to the privileged harness. For each seed, make at most three attempts in order; take the **first** block with successful reservation and all 22 exact calls, independent of timing, and preserve all refusals or partial blocks. A missing qualified seed makes the timing result unknown. Do not compare absolute times across hosts.

Advance only if the frozen one-thread primary paired complete-call reference/candidate median is at least 1.05, its exact 3,125-resample bootstrap 95% lower bound exceeds 1.02, no seed or smaller case has a complete-call median below its A/A minimum, and the two-thread control has no such regression. A passing candidate needs a separately frozen default-on confirmation before merge. A failing candidate has its exact patch, workflow and raw receipts archived and its runtime option removed. The user's further 2× target requires a frozen-primary one-thread full-call median and lower bound both above 2.0 with all guards. This is a solver-stage comparison, not an IC one-target online DLP or rho speedup.
