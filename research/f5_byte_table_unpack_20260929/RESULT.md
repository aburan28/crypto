# Matrix-F5 byte-subset unpack: qualified baseline, candidate pending

The [protocol](PROTOCOL.md) was frozen before candidate code or timing. The unchanged-source [CI baseline run 36657129349](https://github.com/aburan28/crypto/actions/runs/36657129349) completed on AMD EPYC 7763, Linux x86-64, Rust 1.98.1, with AVX2/BMI2 and one Rayon thread. The ten-second preflight saw 0.19 outside CPU seconds (below the 1.0-second budget); the privileged reservation moved 152 threads, left zero user threads eligible on the pinned CPU, and recorded zero contended samples. All seven F5 cases returned exact output. The n24 degree-4 full call took 106.119 ms, including 43.309 ms elimination and 54.528 ms output unpacking, with 6,924 rows and 13,734,979 terms.

The unmodified binary has SHA-256 `604a81550ed7fc1caa232fffa2aee5850658a2092e6f3bd5dad8d26c43abd293`; its deterministic compressed archive and hash are in [BINARY_ARCHIVE.json](runs/36657129349-attempt1/BINARY_ARCHIVE.json). The [full baseline receipt](runs/36657129349-attempt1/baseline-manifest.json) retains source hashes, host, exact output and isolation, and the [exact baseline workflow](WORKFLOW_BASELINE.yml) is archived. The binary hash matches the earlier PR #1001 baseline on a different host, but the 106.119 ms time will not be divided into a later candidate time. Candidate ratios will come from one same-runner, same-binary paired harness. No candidate speedup is claimed yet.
