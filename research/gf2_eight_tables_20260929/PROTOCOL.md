# Matrix-F5 eight-table elimination: frozen experiment

## Hypothesis and reference

The exact n24 degree-4 matrix-F5 call has 6,924 packed rows, 12,951 columns, and 203 words per row. The current GF(2) elimination groups at most four eight-pivot Gray-code tables, so it clears rows below a block after at most 32 pivots. This experiment tests **eight tables of eight pivots each**, up to 64 pivots per block, to reduce complete scans of the matrix. This is a table-count change, distinct from the earlier six-column table-width experiment and from the slower GF(2) column panels. The hypothesis is that fewer scans outweigh the larger lookup footprint on the frozen n24 degree-4 call. The reference is the current four-table kernel in the same release binary, selected by `KIC_GF2_TABLES=4`; the candidate is opt-in with `KIC_GF2_TABLES=8`. The default remains four tables during measurement. Select eight tables only when the packed matrix has at least 4,000 rows and 4,096 columns; all smaller matrices use four. The maximum logical table footprint for the frozen n24 case is `8 × 256 × 203 × 8 = 3,325,952` bytes. Keep it below 4 MiB at runtime or fall back to four tables. Report actual table allocation and peak process memory. The implementation must retain the portable scalar path and runtime SIMD dispatch.

The source reference is current main commit `1d2a2e537e7ff7af7dc923ce82231cef0c3f3982`: `gf2_elim.rs` SHA-256 `6fd3f10ef8e681490784c624e703eeb8fa887c5817ec9bdf34844e3f943c7f5c`, `matrix_f5_f2.rs` `bf35680f431ab7ac13a7615d334ec9b060217b84bdde36f03ce00319491d42da`, benchmark `f4_f2_bench.rs` `d40f9f0c76e5c56c9f4a52596b9edef41f321aa3d70cfb023c4ba21fdde70336`, isolation wrapper `ff59e53fd5566078ad493c8be0d06168699c4fd194bc881d99df19fa20e007ef`. The unchanged-source EPYC baseline and binary are archived in PR #1013; absolute times from that run are context only, never the denominator. This candidate changes block grouping, so reduction word-operation counts may change. They must be retained for both arms and included in the stage cost analysis; output fingerprints, rank, terms, columns, builder and criterion counts must match exactly.

## Workload, isolation, and decision

Use all seven F5 cases in `examples/f4_f2_bench.rs`, primary `f5_n24_m24_d4`, seeds `0`, `badc0de1`, `5eed2026`, `f5c02a28`, and one and two Rayon threads separately. Hold selective echelon output, fused row count, direct packed rows and unpack, branchless AVX2 strip, AVX2 row XOR, and Gray-code table reuse fixed. Disable deferred-above, word batching, AVX-512 unpack and experimental table construction. Verify the requested/actual table route and logical/allocated bytes for every case. Per seed and thread count run one warmup per arm, five A/A reference pairs and five alternating A/B pairs: 22 processes with all seven cases. Preserve every call, failure, timeout, OOM, source/binary hash, CPU/affinity, raw/canonical row fingerprints, rank, terms, columns, row/criterion/build counts, reduction word operations, route, allocation, exclusive phases, and complete-call time. Release unit tests must compare four and eight tables on partial columns, sparse/dense rows, row-space and exact outputs, and verify small-matrix fallback.

Build/test through `tools/isolated_bench.py busy` under one lock. Each timed seed block uses privileged `tools/isolated_bench.py reserve`, all SMT siblings reserved, one CPU left free, runner Rustup environment passed through, ten-second preflight, other-CPU rate at most 0.10, PSI at most 5.0, zero eligible user threads and zero contended samples at a two-second period. Attempt each seed at most three times in order, select the **first** block with reservation success and 22 exact calls independent of timing, and archive every refusal and partial call. If any seed lacks a qualified attempt, speedup is unknown. Do not combine absolute times across hosts.

The candidate advances only if the frozen one-thread primary complete-call paired reference/candidate median is at least 1.05, its exact 3,125-resample bootstrap 95% lower bound exceeds 1.02, no seed or smaller case has a complete-call median below its own A/A minimum, the two-thread control has no such regression, and the logical table footprint stays within 4 MiB. A passing candidate needs a separately frozen default-on confirmation. A failing candidate has its tested patch, workflow and raw receipts archived and its opt-in runtime path removed. The user's further 2× goal requires the full-call median and lower bound both above 2.0 with all guards. Since elimination was only about 43 ms of a roughly 107 ms unchanged-source complete call, even eliminating its entire measured cost would bound this isolated lever to about `107/(107-43) ≈ 1.67×`; a 2× complete-call result also needs work on output and other phases. These are solver-stage measurements, not IC one-target online DLP or rho speedups.
