# Next discriminating gate: algebraic χ decomposition over `F_(p²)`

Status: polynomial-oracle protocol proposal, unexecuted. The [current cost report](REPORT.md) measured an exact χ orbit **index** and a public scaling-isomorphism control, with unchanged relation yield and extra index CPU work. It did not build the nonfactorable χ polynomial oracle requested in the [original frozen protocol](PROTOCOL.md).

## Hypothesis and boundary

The hypothesis is that a descended decomposition system in `χ=(y+1)/(y−1)` with the public action `χ(P+T)=1/(1−χ(P))` can reduce the complete cost of a single unknown-scalar DLP on `E(F_(p²))[r]`, after all polynomial work, source/quotient checks, relation collection, linear algebra, target recovery and verification. A speed result requires the cold `S` total below the same-target matched rho on increasing `r`, with the original generic two-class floor and a charged six-class rho reference. Any benefit limited to a polynomial step is a stage diagnostic.

An L0 paired implementation run can reject broken oracle equations or reveal a bounded signal. A performance claim requires the four sizes, L2 or better isolated interleaving, independent-host exact replay, and a matched rho distribution with A/A noise. If χ improves decomposition yield but loses in cold total, preserve both observations. If it wins only on a target-selected base, run an unseen same-point target and charge selection. If its supports and costs match the quotient control, treat the difference as coordinate bookkeeping until a paired counterexample separates them. If no oracle is implemented or native costs remain unpriced, leave the original hypothesis open.

The present `E:y²=x³+1 → E':y²=x³−27` pair has a checked public scaling map on **all four** frozen extension fields. More generally, every nonzero `F_p` coefficient is a square in `F_(p²)` for odd `p`, so `−3` always has a square root there when `p≠3`. Rescreening this fixed pair at another odd quadratic-extension prime cannot yield a non-isomorphic destination. To seek a degree-three effect specific to a non-isomorphic destination, construct a different exact source/isogeny/destination over `F_(p²)` and check the absence of an `F_(p²)` isomorphism for that pair. Freeze its ICV1/EC1 identities, kernel and subgroup map checks before running relation comparisons. Keep that map-attribution search separate from the χ polynomial-oracle test on these four fields; bounded failure to find a new pair is not a nonexistence theorem.

## Separate multiplicative extension-field route

For a pairing reduction, the relevant embedding degrees from `q=p²` are `9,5,105,405`; the multiplicative outputs would lie in `F_(p^9)`, `F_(p^10)`, `F_(p^105)`, `F_(p^810)`. A common field containing the frozen `F_(p²)` input and these root-of-unity fields has degree `18,10,210,810` over `F_p`; the second pairing input may force a larger evaluation field. Before any finite-field DLP comparison, construct and check a nondegenerate pairing on the exact subgroup and target, including that second input and its discrete-log relation. Price the actual evaluation-field construction, Miller/final-exponentiation work, the chosen multiplicative DLP algorithm, transfer back to the ECDLP scalar, and final `[k]G=Q` verification against the same rho reference. Embedding degree alone is a screen, not a priced transfer.
