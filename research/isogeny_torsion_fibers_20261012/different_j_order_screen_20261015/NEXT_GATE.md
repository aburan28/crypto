negation rho; paired full/BSGS and full/rho ratio medians were 11.139
and 9.509. Full-image and destination-direct support were 98 and 90

independent-host performance replay and growing-order assessment
remain open. The following preregistered decision rule is retained
as historical protocol, not as an unperformed execution checklist.

The [bounded native screen](RESULTS.md) selected the first qualifying
different-j pair at `p=211`, `r=229`: source
`y²=x³−21x+37`, destination `y²=x³−81x−243`, rational degree-three
kernel `{O,(3,1),(3,-1)}`, `j=77` and `160`, and direct
`F_(211²)` point counts `44,655` on both models. This made the
64-distinct-target batch feasible. The
separately frozen [full map/fiber audit](FIBER_REPORT.md) now completed
every enumeration, three-point fiber, exact order-229 generator and
52,441 ordered subgroup-pair checks with independent native replay.
The protocol below retains its pre-audit wording as the original
decision rule; its map/fiber prerequisite is now discharged.

Freeze a new native Rust protocol and source/binary hashes **before**
that batch. First construct a source point of exact order 229 by
cofactor multiplication, verify its image has exact order 229, and
enumerate every rational source point to check destination membership,
the three-point kernel, map fibers, and the exact image size. Use
independent arithmetic replay; sampled screen witnesses alone do not
discharge this full map gate. These map/fiber checks are complete in
`FIBER_V1`; the batch must pin its generator and public target custody
independently. Select eight factor-base columns by a
committed public rule from a fixed candidate pool, retaining both
projected-image and full rational-image choices.

Create 64 distinct nonidentity source targets in a seeded order derived
from their public point coordinates; commit only the public point file
to solver input and keep known scalar correspondences in a separate
checker file. Run source projected, projected isogeny image,
destination direct, full rational image, reusable direct source BSGS,
direct source negation rho, and rho A/A on the same targets and frozen
streams. Compare prefixes `N=1,4,16,64` over three arm-rotated rounds,
with equal relation caps and memory. Require full relation rank and
recovered scalars for every target; independently replay every scalar,
map pair and relation witness. Preserve failures and caps as raw
receipts, not zero-yield rows.

Charge field construction, point enumeration, image mapping, base
selection and lookup tables, every failed relation or rho attempt,
linear solve, recovery, final verification, process startup and output,
RSS and the exact number of distinct targets reusing setup. Report
cold and per-target totals at each prefix against same-target BSGS and
rho. Convert all priced primitives into the repository's counted
`S=total operations/sqrt(229)` unit with measured conversion factors;
keep child CPU, wall and RSS as separate receipts. Three shared-host
rounds may screen a candidate, while isolated interleaving and an
independent host are required before a performance claim.

Before tuning or interpreting a candidate arm, record the generic
negation-orbit collision floor `S_floor=sqrt(pi/(2·2))=sqrt(pi/4)` for
this non-exceptional-`j` prime-order subgroup and run the frozen
same-target direct rho and reusable source BSGS controls. Record their
measured complete-cost `S` and memory with intervals as the reference
for the candidate table. The order-61 reference values are a separate
workload and cannot be substituted for these controls.

If the full-image support changes, measure equal-stream paired
relation yield and complete solve cost, not support alone. If the
whole-process construction dominates, report that bounded result and
retain the remaining larger-order/exponent question. The direct
χ-coordinate resultant remains a separate obligation with its own
same-target controls and counted cost.
